# Call of Slop

A tiny multiplayer arena shooter built directly on the [BRUTAL framework](https://github.com/ahwootech/BRUTAL).
Pick a loadout from 50 weapons and a map from 8 blocky prototype maps, then frag each other or a pack of bots.

| BRUTAL library | Used for |
| --- | --- |
| `Ahwoo.BRUTAL.Glfw` | Window, OpenGL context, keyboard and mouse |
| `Ahwoo.BRUTAL.OpenGl` | Rendering (OpenGL 4.1 core, everything is a box) |
| `Ahwoo.BRUTAL.RakNet` | UDP networking (listen-server + clients) |
| `Ahwoo.BRUTAL.ImGui` + `.Backends` | Lobby, menus, loadout screen, HUD text, scoreboard |
| `Ahwoo.BRUTAL.OpenAl` | 3D positional weapon audio, streamed procedural music |

## Requirements

- .NET 10 SDK
- Windows x64 or Linux x64, a GPU with OpenGL 4.1, and speakers or headphones
- Internet access the first time you build (NuGet restores the BRUTAL packages)

## Play

Double-click **`Start.bat`**. It builds the game if anything changed (the first build downloads the BRUTAL packages), then shows the BRUTAL logo for a few seconds (the BRUTAL licence asks for it before gameplay; click or press a key to skip it) and opens the **lobby**:

| Lobby option | What it does |
| --- | --- |
| **Single player** | You against up to 31 bots (as many as the map takes, see [Lobby size](#lobby-size); Easy, Normal, Hard or Insane), or **No bots (test mode)** with the slider at 0. Fully offline, nothing touches the network. The game pauses while the Esc menu is open. |
| **Multiplayer: Host** | Starts a match others can join. It opens the port on your router automatically with **UPnP** (can be turned off), and you can fill empty slots with bots. Real players replace bots as they join. The address friends should use appears at the top-left of your screen. |
| **Multiplayer: Join** | Type the host's address and join. Esc cancels while connecting. |
| **Settings** | Four tabs. **Player:** name, sensitivity, invert Y, FOV, network stats. **Controls:** rebind every action to any key or mouse button. **Video:** windowed / borderless fullscreen / fullscreen, resolution, UI scale, HUD width, name tags, head bob, frenzy visuals, gore, VSync. **Audio:** master, music, effects, own gun and footstep volume, music style, kill frenzy music, frenzy gun sound. Changes apply immediately and are saved to `settings.txt` (in the [save folder](#where-your-saves-live)); the same screen is in the Esc menu during a match. |

In a match, **Esc** opens the menu (Resume, Change loadout, **Kill yourself**, Settings, Leave match, Quit). Leaving takes you back to the lobby, and as host it ends the match and closes the router port.

- **Kill yourself (respawn)** closes the menu and kills you through the normal server path, then the usual death flow follows (death cam, then the loadout screen; in Gun Game you respawn on your own). It counts as a **suicide**: a death for you, no kill for anyone, your kill streak resets, and it never scores for a team or changes your Gun Game weapon. It's greyed out while you're dead or the match isn't live (warmup, countdown, results), and the server accepts it at most once a second. Online, clients ask the server, which decides.
- **No bots (test mode):** set the bot slider to 0 in Single player (or *Fill with bots* to 0 when hosting) to try weapons, attachments, perks and mode objectives on your own. Deploy (or Ready) starts the match straight away. While you're the only one in the match **the match clock stops and nobody can win**: team scores (hill points, flag captures) still count but stop one short of the limit, so the match never ends on its own. In team modes you're simply on a team by yourself. As soon as another person joins a hosted game, the normal rules apply again. The bot count is saved in `settings.txt` as before.

To test on one PC: run `Start.bat` twice. Host in one window and join `127.0.0.1` in the other.

- The first time you host, Windows Firewall asks whether to allow Call of Slop. Click **Allow**.
- If the host's address says "LAN only - UPnP unavailable", turn on UPnP in your router's settings or forward UDP 60000. Same-network play works either way.
- "Behind a second NAT" means a second router or your ISP's carrier-grade NAT. Use a LAN or a virtual LAN tool like Tailscale or ZeroTier.
- The game has no console window; its log is written to `callofslop.log` next to the exe.
- Text boxes take plain text only: pasting an image or a file does nothing (the log says `[ui] paste ignored: the clipboard has no text`), and pasted text is cut to printable ASCII. Names, server names and other text from other players are cleaned the same way, and a broken or hostile network packet is dropped with a `[net] dropped a bad ... packet` log line instead of closing the game.

Command-line shortcuts (skip the lobby): `CallOfSlop.exe host [port]`, `CallOfSlop.exe join <ip> [port]`, plus `--no-upnp`, `--lag=ms`, `--loss=%` for testing.

### Matches

- These are the **Free-for-all** rules (the default). The host can pick another game mode; see *Game modes*.
- **First to 11 kills wins, but you must be 2 kills clear** of the next player (like tennis). At 11-10 the match carries on until someone leads by two.
- **Score limit: Auto (default) or Fixed** (Single player and Host screens, under the game mode). Auto scales the limit with the number of players (people + bots) so a 24-player match takes about as long as an 8-player one: 11 kills is the limit at 8 players, more above that, fewer below (never under 7). It's set from everyone present when the match starts and only ever goes **up** if people join mid-match (never down when they leave). Fixed keeps the classic limits (11 kills, 40 team kills, 150 points, 3 captures). The match bar always shows the current limit. Formulas and measurements: [docs/SCORE-SCALING.md](docs/SCORE-SCALING.md). Saved in `settings.txt` as `score_limit`.
- **Warmup and ready-up** before every match (the first one and each one after the map vote): see *Ready-up* below.
- **5-second countdown** once everyone is ready: everyone is frozen (you can still look around), the loadout menu opens, and whatever you have selected deploys automatically at GO.
- **10 minutes max** (the host can pick 5, 10, 15, 20 or 30 in the lobby room; saved as `match_minutes`). When the clock runs out, the kill leader wins; a tie at the top is a draw.
- The clock and the score (you vs. the best other player) sit at the top of the screen. It turns orange with "Win by 2!" when the match goes to deuce.
- At the end you get VICTORY / DEFEAT / DRAW and the final scoreboard. Nobody can be hurt on that screen, and a new match starts on the same map after 12 seconds.
- Same rules in single player and multiplayer; the host's game decides when a match ends.

### Ready-up

- Every match opens with a **warmup**. The loadout screen opens; you can pick a loadout, respawn and walk around, but nobody can be hurt or shoot. A panel on the left lists everyone with a tick for who's ready.
- Press **F3** (rebindable: *Ready up*) or click **READY UP** in the loadout screen footer or the panel. The 5-second countdown starts as soon as **every person** is ready. Bots are always ready.
- **Single player:** Ready, Deploy or Respawn starts the countdown straight away.
- **Hosting:** the panel has a **FORCE START** button. The Host screen also has *Auto-start the match once someone is ready* (off by default): when it's on, the match starts that many seconds after the first person readies up, even if others haven't.
- When the countdown starts, everyone is put back at a spawn point. People who join during the warmup start not ready. People who join mid-match, or who leave, never hold anyone up.
- The warmup panel also shows the **map and mode**, and in team modes the players are listed under a **BLUE / RED** heading each.

### Pre-match lobby

When you **host or join** a game you land in the **lobby room** first, a menu in front of the map (drawn slowly orbiting behind it), before anyone is in the match:
- **Players:** name, rank (prestige/level) and hat, team (`*` = picked), ping, ready tick, a crown for the host. Bots are listed as filler.
- **Teams** (team modes): Join Blue / Join Red / Auto with the usual rules (*Picking teams*), but **no switch cooldown** in the lobby. The host has **SHUFFLE** (everyone on Auto, random even split) and **BALANCE** (picks kept, the rest split evenly).
- **Next match:** the map with its size, player limit and description, the mode and its goal, the pack (which the vote draws from) and the settings. The **host** changes them live and everyone sees it at once: mode, pack and map (maps too small for the people here, or not for this mode, are greyed out: the same rule as the map vote), **Random map**, score limit, **time limit**, auto-start, **Return to lobby between matches**, frenzy buffs, bots and their difficulty, team rules and team balance. The host's choices are saved to `settings.txt` when the match starts.
- **LOADOUT** opens the loadout screen (you spawn with the selected loadout; it can still change during the countdown). Your hat is shown beside it.
- **Chat:** type and press Enter. Lines are printable ASCII, at most 120 characters (pasting an image or anything odd is safe), at most 4 lines at once then one every 1.5 s each (checked by the server too); the last 50 lines are kept.
- **READY UP** (or F3). The host's **START** works once every other person is ready (it readies the host too); **FORCE START** works any time. With *Auto-start* on, the countdown starts by itself once everyone is ready, or that many seconds after the first person readies. A **5-second countdown** follows; if someone un-readies it's cancelled (not a forced one; the host can **CANCEL** any). People leaving never stall it.
- At zero the match starts: everyone spawns, and the normal 5-second match countdown runs with the loadout screen open (the lobby replaces the first warmup). The map was already loaded and drawn in the lobby, so the start is quick.
- **People who join during a match** skip the lobby and join the match, as before.
- **Return to lobby between matches** (host setting, Host screen and lobby room, default **off**, saved as `lobby_return`): on, everyone comes back to the lobby after the results screen and the map vote (with the voted map); off, the next match's warmup starts straight away.
- **Single player** has no lobby room: its menu page already has every setting, and the in-map warmup starts the match.
- The **server browser** shows what a game is doing: **In lobby** (green: join now and ready up), Warmup, Starting, In match or Results.
- Online it's server-authoritative: the lobby state (map, settings, every player's ping, ~30 bytes + 3 per player) is sent on every change and once a second; chat goes through the server (protocol 32).

### Game modes

Pick the mode on the Single player or Host screen. It stays the same from match to match (the map vote only changes the map), and the server browser, the match bar and the results screen show it. Every mode but Zombies has the same 10-minute limit.

| Mode | Rules |
| --- | --- |
| **Free-for-all** | First to 11 kills (at 8 players; see *Score limit* above), win by 2. |
| **Team Deathmatch** | Two teams (Blue and Red), pick your side or let the game balance them (see *Picking teams* below), bots included. First team to **40 kills** at 8 players; with the Auto score limit it grows with the player count (70 at 16, 120 at 32). No friendly fire, grenades and streaks included (your own grenade can still hurt you). You spawn on your team's side of the map. |
| **King of the Hill** | Two teams. A glowing ring marks the hill. Hold it with **only your team** inside for **1 point a second**; while both teams are in it (contested) nobody scores. The hill moves to the next zone every **60 s**. First to **150 points**. |
| **Capture the Flag** | Two teams, a flag at each base. Touch the enemy flag to take it; bring it to **your own flag** to capture, which only works while your flag is at home. A carrier who dies drops it; a teammate touching a dropped flag sends it home, otherwise it returns by itself after **20 s**. Carriers keep their guns, and a light beam over them (and over a dropped flag) shows through walls. First to **3 captures**. |
| **Gun Game** | Everyone starts with the same gun, the first one in the unlock order, whatever they've unlocked. Each kill moves you to the next gun; a **melee kill also sets the victim back one gun**. The first kill with the last gun wins (a melee kill on the last gun doesn't count). Loadouts, grenades, perks and kill streaks are off. The ladder is 20 guns, evenly spaced through the 50-odd weapons in unlock order. |
| **Zombies** | Co-op for 1-4 against endless rounds of zombies (World at War style), only on maps with a Zombies layout (today the dev map **Zombies Test**). No time limit: the run ends when everyone is down. See "Zombies" below. |

Team modes colour everyone blue or red (players, scoreboard, kill card). King of the Hill is played by teams. The HUD shows the hill's holder, its distance and direction and when it moves; the state of both flags; or your Gun Game weapon, the next one and the leader. The scoreboard groups players by team (or by gun level). If a player leaves and the teams end up two apart, a bot switches sides.

On dev-pack maps (Zombies Test) the mode list also offers **Last Man Standing** (one life each, the last one standing wins), the Dev-only template that shows how a mode is written. For developers: every mode is a module under `Source/Game/Modes/<Mode>/` (rules flags, lifecycle, bots, HUD and replicated state in one class), registered in `GameModeRegistry`; [Source/Game/Modes/README.md](Source/Game/Modes/README.md) explains how to add one.

**Picking teams (play with your friends).** In every team mode you can choose **Join Blue**, **Join Red** or **Auto**:
- **Where:** the **TEAMS** window beside the loadout screen (it opens by itself in the warmup; the **TEAMS** button in the loadout footer opens or hides it, also on the respawn screen and when you join a match in progress) and **Esc > TEAMS**. Both show each team's roster, so you can see where your friends are; **Join** next to a person on the other side puts you on their team. A `*` after a name (also on the scoreboard) means they picked their team.
- **Size rule:** a side may be at most **2 players bigger** than the other (host setting *Max team size difference*, 0-4). Only people who picked a side count: bots and people on Auto fill the smaller side, so a group of friends can stack a little but not 6v2. A full side's button is greyed out with the reason. **Bots never block you:** join a side that has a bot and that bot moves to the other side.
- **Switching:** before the match (warmup, countdown, results) or while dead, at most once every **10 s**, never while carrying the flag. It's a respawn, not a suicide: no death, no score or kill streak change. While alive in a live match the buttons say to switch while dead.
- **Autobalance** only moves bots and people on **Auto** (people only while dead or between matches). Someone who picked a team is never moved; a new match keeps everyone's pick. People who join get the smaller side on Auto.
- **Team balance** (host setting: Host and Single player screens, the lobby room and Esc > TEAMS; saved as `team_balance=auto|off|humans_vs_bots` and `humans_team=0|1`; older files get Auto):
  - **Auto** (default): everything above.
  - **Off:** no autobalance and no size limit on picks, so a group of friends can all stack one side; bots stay wherever they were put (a new match still splits people on Auto and bots evenly, then nobody is moved).
  - **Humans vs Bots:** every person on one side (pick **People on Blue** or **People on Red**, default Blue), every bot on the other; the bot slider sets how many bots you face. People who join mid-match go to the people's side, new bots to the bots' side; picking the bots' side is refused, and autobalance, SHUFFLE and BALANCE are off. Score limits, team spawns and map player limits work as in any team match.
- **Host settings** (Host and Single player screens, shown for team modes; the host can also change them in Esc > TEAMS): **Team selection: Manual / Auto only** (default Manual; Auto only is the old automatic split) and **Max team size difference** (default 2). Saved in `settings.txt` as `team_select=manual|auto` and `team_max_diff=2`; older files get the defaults. Online, a client asks the server, which checks the rules and answers (protocol 20).

Maps can place team spawns, hills and flags by hand; otherwise the game works them out from the map (see Maps/README.md).

### Attachments (gunsmith)

Every weapon has up to six attachment slots: **Optic, Muzzle, Barrel, Underbarrel, Magazine, Stock**. Open a gun's attachments from the loadout screen: the **Edit attachments** button on the Primary or Secondary card, or **Attachments** (top right) on the weapon select. The attachments page shows the gun large, with how many attachments are unlocked and what's equipped; click a slot card to pick from it. Hover an attachment to see its pros, cons and the resulting stats.

- **Optics:** Pinhole Reflex (1.4x), Red Dot (1.5x), Holographic (1.6x), Brick 2x Prism, 2.5x ACOG, Tandem 3x Hybrid, 4x Scope, Variant 6x LPVO, 8x Sniper Scope and Longshot 12x (snipers only). Each has its own model, reticle and zoom, and the bigger the optic, the slower you aim.
- **Seeing through optics:** every optic is a physical sight on top of the gun. When you hold right click the gun comes up and the sight moves to your eye, housing and all, and you look through its lens: inside it you see only the world and a crisp reticle (no rail, receiver or tube insides), with a faint glass tint. The higher the magnification, the more of the screen the lens fills: reflex sights (Pinhole, Red Dot, Holographic) stay a small window on the gun, the 2x-3x prisms fill a good part of the screen, the 4x and 6x most of it, and the 8x and 12x all of it but a thin eyepiece rim in the corners. It's one continuous motion from the hip to full aim, with no switch to a flat overlay. Guns with a built-in scope work the same way. Each optic's look (reticle, how much of the screen its lens fills, rim, tint) is in its file's `sight` block ([Attachments/README.md](Attachments/README.md#sight-block)). Fitting an optic removes iron sights and LMG carry handles that would be in its way.
- **Muzzle:** Suppressor (much quieter shots, faint tracers, -15% range), Compensator (cuts the climb), Muzzle Brake (cuts sideways recoil and shake), Choke (shotguns).
- **Barrel:** Long, Short, Heavy. **Underbarrel:** Vertical Grip (cuts the climb), Angled Grip (faster aim, softer first shot), Laser.
- **Magazine:** Extended, Fast, Drum. **Stock:** Light, Heavy (less recoil, faster recovery), No Stock.
- The gunsmith's stat bars show each change in green or red with the percentage. However much you stack, a gun keeps at least 40% of its recoil and half its hip spread.
- Which attachments fit depends on the weapon class, and every class has some of its own: pistols get the Slide Dot, slide comp, extended and snub barrels and a brace or holster stock; shotguns chokes, a slug barrel, a drum and a shell holder; snipers the 12x, a match barrel, a straight-pull action and stripper clips; LMGs a quick-change barrel and a long belt box; and the specials (nailgun, arc carbine, musket, toy blaster) their own sights, muzzles, barrels, gyro and braces, down to a blunderbuss bell and a **bayonet** for the musket (the bayonet makes a melee stab reach 3.2 m instead of 2.4 m). Every attachment is a trade (each makes at least one stat worse), and the full class-by-attachment table is in [Attachments/README.md](Attachments/README.md#which-classes-take-what). Ammunition (AP, incendiary) only changes stats.
- **Unlocks are per weapon** with weapon XP (see Progression): 3-7 matches with a gun to unlock everything on it. Weapon XP is saved in `progress.txt`, and Reset level clears it.
- The server applies the same attachments to the same stats, so they're fully networked. Other players hear your suppressor and see your optic and grip.

### Loadouts

Open **LOADOUTS** from the main menu, or press **B** in a match. The screen lists your loadout slots on the left. Pick one to make it the loadout you spawn with; it's marked with an orange star. The selected loadout is shown on the right as cards: **Primary Weapon**, **Secondary Weapon**, **Perks**, **Lethal**, **Tactical**, **Hat** and **Kill Streaks**. Click a card to change that part, and **Rename** to name the loadout. Each loadout keeps its own attachments, and a gun you move into another loadout starts with the build you last used on it. Everything saves to `loadout.txt`. An older single-loadout file becomes slot 1.

- **More slots unlock as you level up.** Level 1 gets one slot, and the tenth arrives at max level, evenly spaced: levels 1, 6, 11, 17, 22, 27, 32, 38, 43 and 48. Only unlocked slots are listed, with a small "Next slot at level N" line under them. A locked slot keeps whatever you saved in it (after a reset or prestige, say) and comes back as it was once you reach its level again; if your selected slot is locked, you spawn with your highest unlocked one.
- **Back goes back one page.** The screen is a stack of pages: the footer's **BACK** button (and **Esc**) returns from the attachments to the weapon select (or to the overview, if you came from a card's Edit attachments), from the weapon select, lethal, tactical, perks and kill streak pages to the overview, and from the progression page to whatever was open before. On the overview, BACK returns to the main menu (in a match it's **CLOSE** and closes the menu). A line at the top shows where you are, e.g. *Custom Loadout 1 / Primary weapon / Kestrel PDW attachments*.
- **Your progression is the bar at the bottom right:** LEVEL, XP into the level and the next unlock. Click it (*ALL UNLOCKS*) for the progression page: level, XP, stats and every unlock by level.
- **Edit attachments:** the Primary and Secondary cards have an **Edit attachments** button beside the gun's name, which opens that gun's attachments directly. Clicking anywhere else on the card opens the weapon select.
- **Picking a gun:** clicking the Primary or Secondary card opens the weapon select. Class tabs run across the top (each shows how many guns it has and how many are still locked). Below, a column of tiles shows each gun with this loadout's attachments on it, its level (attachments unlocked) and weapon XP bar, and an EQUIPPED, SELECTED or LOCKED tag (with the level it unlocks at). **Click a tile to select it**: the gun is shown big on the right (hovering a tile previews it too), with its stats compared to the gun you have equipped (green = better, red = worse), its magazine, reload time and shots to kill. The selected tile has a blue outline; hover is orange, and the equipped gun has an orange bar and the EQUIPPED tag. **EQUIP** (bottom right) puts the shown gun in the loadout; it reads EQUIPPED for your current gun and is greyed out for a locked one. **Double-clicking a tile does exactly the same as EQUIP** (the tile flashes, then shows EQUIPPED); on a locked gun it just shakes.
- **Attachments on the weapon select** (top right) opens the attachments of the gun shown. For a gun you haven't equipped yet, the page opens as a preview, and picking your first attachment equips the gun into this loadout with that attachment. It's greyed out for locked guns.
- **Kill streaks:** the Kill Streaks card opens the streak page. Your three slots are along the top, and every streak is below with its kill cost, what it does, and the level it unlocks at if it's still locked. Click a streak to carry it; when all three slots are full, it replaces the highlighted slot (click a slot to choose which). Click a streak you carry to drop it. See [Kill streaks](#kill-streaks).
- **Cosmetics (hats):** the **Hat** card (beside Lethal and Tactical) opens the COSMETICS page: a card for *No hat* and each prestige hat (Beanie, Baseball Cap, Fedora, Top Hat, Ridiculous Top Hat), each with a little drawing of the hat on a head. Hats unlock with prestige; locked ones are greyed with the prestige they need (*LOCKED - Prestige 3*). Click an unlocked hat to wear it. The hat is **one choice for your whole profile**, worn with every loadout (it's who you are, not a tactic), saved in `loadout.txt` as `hat=fedora` (older files: no hat). It's cosmetic only. The server checks it: only people can wear hats (bots never do), and only a hat their prestige unlocks; everyone else in the match sees the hat you're wearing.
- **Double-click always means "pick it"** across the loadout screen (lethal and tactical lists, perks, kill streaks, attachment lists), and the second click of a double-click never also clicks whatever the page change put under the mouse. Clicking something locked gives a dry click.

### Perks

Each loadout carries one perk from each of three categories. Every perk only works in one situation, but it's strong when that situation comes up. Perks light up on the HUD (under your health) while they're active, and a banner announces the big moments.

| Category | Perk | When | What it does |
| --- | --- | --- | --- |
| Movement | **Low Profile** (start) | Crouched or prone | Move 80% faster; Recon Pulses can't reveal you while you're low |
| Movement | **Head Start** (level 3) | Just spawned | 35% faster for the first 4 s of every life |
| Movement | **Parkour** (19) | Walls, windows, roofs | Reach ledges 0.6 m higher, climb twice as fast, jump about 55% higher |
| Movement | **Stalker** (11) | Aiming down sights | Keep 95% of your speed while aiming instead of 70% |
| Movement | **Dead Silence** (23) | Sneaking up | Others hear your steps, jumps and landings 75% quieter and from half as far; bots notice you behind them within 3 m instead of 7 m |
| Movement | **Lightweight** (33) | Carrying a heavy gun | Your gun never slows you below full speed (LMGs, snipers); no effect with light guns |
| Movement | **Afterburner** (36) | Just got a kill | 35% faster for 4 s after a kill; no refresh during the boost, 6 s cooldown after it |
| Movement | **Ghost** (45) | On the move | Recon Pulses and Recon Sweeps can't reveal you while you're moving (faster than 1 m/s), and Motion Sensors never ping you |
| Survival | **Flak Jacket** (start) | Grenades | 75% less explosive damage, including your own; blasts push you 60% less; flashbangs and stun grenades hit you half as hard |
| Survival | **Quick Fix** (7) | Between fights | Health starts coming back 2.5 s after the last damage instead of 5 s |
| Survival | **Bloodthirst** (9) | Just got a kill | Each kill heals you to full |
| Survival | **Scavenger** (21) | Just got a kill | Each kill gives back one grenade and one equipment charge, up to what you spawn with |
| Survival | **Entrenched** (25) | Crouched/prone and still | 40% less bullet damage |
| Survival | **Hardline** (29) | Earning kill streaks | Every streak costs one kill less (never below 2) |
| Survival | **Last Stand** (41) | Once per life | The first lethal bullet or blast leaves you on 1 HP, and a shield blocks your next 3 bullet hits (up to 8 s); never saves you from melee |
| Survival | **Cold Blooded** (43) | Turrets and drones | Enemy Sentry Turrets and Attack Drones can't lock onto you (stray rounds still hurt) |
| Damage | **Point Blank** (start) | Within 8 m | Bullets and melee hit 40% harder |
| Damage | **Sleight of Hand** (5) | Reloading | Reload 35% faster (stacks with Overdrive) |

| Damage | **Demolitions** (27) | Grenades | Your Frag and Impact blasts reach 25% farther (Frag 9 m -> 11 m), same centre damage |
| Damage | **Deadeye** (31) | Beyond 30 m | Bullets hit 40% harder |
| Damage | **Tight Grip** (38) | Aiming down sights | 30% less recoil while aimed; hip fire unchanged |
| Damage | **Flanker** (47) | Hitting their back | Bullets and melee hit 60% harder |

Movement perks run inside the shared movement code (client prediction and the server agree). The server applies survival and damage perks, and bots carry perks that suit their personality. Handling perks (Sleight of Hand, Steady Aim, Tight Grip, Stalker) work on your own client like Overdrive does, and bots get Sleight of Hand, Steady Aim, Stalker and Lightweight too. Saved loadouts store perks by name, so older `loadout.txt` files load unchanged; the original perks keep their unlock levels.

**Last Stand in detail.** Once per life, the first bullet or blast that would kill you leaves you on 1 HP and raises a shield that blocks the **next 3 bullet hits** completely. One shot counts as one hit, so a shotgun blast uses a single charge however many pellets land, and every turret or drone bullet is a hit. **Melee and explosions go straight through the shield** and don't use charges: a knife or a grenade finishes off someone on Last Stand. Last Stand never saves you from a melee hit at all: melee kills in one hit. The shield lasts until its 3 charges are used or **8 seconds** pass, whichever comes first (so it can't carry over once health regeneration has refilled you). Three pips next to your health bar show the charges left. Everyone else sees a faint blue shell around a shielded player that flares each time it blocks a hit, with its own zap sound. Bots with Last Stand get exactly the same thing.

### Health and regeneration

Players and bots have **120 health** (it was 100; the bump makes most guns take one more body shot, so fights last a little longer). Shots to kill at full damage range, body / head: BR-1 Prototype 5 / 3 (was 4 / 2), Vanguard AR 5 / 3 (unchanged), Bulldog 4 / 2 (was 3 / 2), Hornet SMG 6 / 3 (was 5 / 3), Marksman M14 3 / 2 (unchanged), Longbow DMR 3 / 2 (was 2 / 1), Needle Bolt-Action 2 / 1 (unchanged). The weapon select shows the numbers for every gun. Things that were built to kill in one go still do: melee (150), the Old Faithful Musket (204 now, one body shot out to about 75 m as before), the Breacher Pump up close (14 damage a pellet now, 9 pellets), the Leviathan .50 and Railspike, and the Frag and Impact grenades (their damage against players went up by the same 20%, so the kill radius is unchanged: about 4.5 m and 2.5 m; against props, machines, zombies and doors they hit exactly as before). Stim Shot scales too (48 back, then 18 a second for 4 s). Bot retreat thresholds and the HUD's red low-health number are percentages of max health.

Health comes back on its own once you're out of the fight: **5 seconds** after you last took or dealt damage (2.5 s with Quick Fix), you start regenerating at **12 HP a second**, speeding up by 4 HP/s every second to **24 HP a second** after 3 s, up to full: about **5.7 s from 1 HP to 120** once it starts (it used to be 8 HP a second flat, about 12 s from 1 to 100). Taking a hit, or landing one (a hit a Last Stand shield blocks counts too), restarts the 5 seconds; firing and missing doesn't. The health bar pulses and glows green while you regenerate. The server runs it, so it's the same for people and bots, in every game mode (including Gun Game and solo test matches), and dead players don't regenerate.

### Blood

How hurt someone is shows as blood, more the lower their health (always as a fraction of max health, so it works whatever max health is), and it goes away as health comes back.

- **On your screen:** nothing above 85% health; below it, procedural blood splatters build up around the edges of your view in layers at **85 / 70 / 50 / 30 / 15%**, and **each new hit adds a splatter on the side it came from** (in front: the top edge, behind: the bottom, left and right: those edges). Near death it gets darker and denser, a faint red vignette creeps in from the screen edges, and below 15% it pulses gently. The centre of the screen always stays clear. As you regenerate the splatters fade back layer by layer; a Stim Shot's instant heal clears them in about half a second. Armour (Ballistic Vests, the Juggernaut suit) and Last Stand's shield soak hits before health drops, so they show nothing until your health itself falls. Everything clears at once when you die (the death tint takes over) and you respawn clean. On ultra-wide screens the splatters sit at the edges of the **HUD width** area (where you look), the vignette at the real screen edges.
- **On bodies (everyone, bots and zombies too):** players and bots show up to 8 blood marks on their body model, more as their health drops, each placed on the body part a hit landed on (head, chest, back, arms, legs; the server records the part from the bullet's exact hit point, and blasts, melee and zombie swipes by the side they came from). Every PC places the marks in the same spots, from the hit parts the server sends in each snapshot. They fade as health regenerates, clear at full health, and a ragdoll keeps its final marks. Zombies bleed a darker ichor, spread over the torso and head as they get hurt.
- **Settings > Video > Blood overlay:** **Full** (default), **Subtle** (fewer, fainter, smaller splatters and body marks) or **Off** (none on screen or on bodies); **Blood colour:** **Red** (default) or **Dark** (a dark maroon, easier on the eyes and for colour-blind players). Saved as `blood_overlay` and `blood_colour` in `settings.txt`; older settings files load as Full / Red.
- Cost: the screen overlay is one instanced draw call (splatter masks generated at startup, no image files; the vignette is four thin bands along the edges, so the middle of the screen isn't touched). Body marks add **no draw calls**: up to 8 small spheres per body go to the box shader as uniforms right before that body's own boxes, which paint a ragged, blocky splat where a sphere touches them; ragdolls carry a blood amount per box in their existing instanced draw. No per-frame allocations. The game log has a `[blood]` line every 10 s while the overlay shows (instances, GPU ms, marked bodies and CPU per frame). The self-test sections **Blood overlay** and **Body blood** check the steps against health, the hit direction, fading on regen and Stim, clearing on death, Subtle / Off, the masks, no allocations, the settings save, the recorded hit parts and directions, armour, two clients placing identical marks from the same snapshot, the packet round trip and the CPU for 32 bodies (budget 0.1 ms per frame).
- Network: the blood marks are one 32-bit word per player in every snapshot (protocol 33): 8 hit parts, a generation and the direction of the latest hit.

### Kill streaks

Each loadout carries **three kill streaks**. Kills in one life count up; reaching a streak's cost earns it, and an earned streak is **kept (even through death) until you use it**. Dying resets the count. Kills made *by* streaks never count toward the next one, and neither do kills after you've died (a grenade going off later, say). A streak kill gives normal kill XP.

Use an earned streak with its key: **4**, **5** and **6** by default, cheapest streak first (rebind them as *Kill streak 1-3*). Instant streaks go at once. The **Mortar Barrage**, **Strafe Run**, **Napalm Strike** and **Smoke Screen** start targeting: a marker shows where they'll land, **fire** calls them in, and aim or the streak key again cancels.

- **Turrets, drones and gunships can be destroyed** with bullets, grenades and enemy strikes (no headshot bonus on machines). A Supply Drop crate can't: it's taken, not destroyed. Your own bullets pass through yours. The kill feed shows who destroyed what. A health bar floats over yours and your team's at all times (over an enemy's once it's damaged), and while yours is up your HUD shows its health and seconds left above the streak icons.
- **The HUD** shows your three streaks at the bottom centre: key, kill cost, a pip per kill and a glow when it's ready, plus your current streak count. A banner announces each one you earn.
- **Bots** carry three random streaks and use them: mortars, strafe runs and napalm on the last enemy they saw or the biggest group, turrets facing where the enemies are, a smoke wall halfway to an enemy they've just seen, the rest straight away. Insane squads use the same logic.
- **Zombies has no kill streaks** (nor does Gun Game): the mode turns them off, so none of these are in it. The co-op mode has its own power-ups and perks instead.
- **For other weapons that counter streaks** (e.g. launchers): every streak machine is a `StreakEntity` with `IsAirborne` (Attack Drone, Hunter Drone, Gunship), `Health` / `MaxHealth`, `Hitbox` and `Targetable` (false for a crate). `Game.DamageStreakMachine(entity, attacker, amount, DamageKind, now)` applies a direct hit or blast on the server through the normal rules (team check, the streak's bullet and explosive multipliers, the kill-feed line), and `Game.StreakMachineHostile(entity, player)` says whether that player may target it. Grenade and strike blasts already hurt them through `StreakBlastEntities`.
- Streaks unlock with your level like perks: three to start, the others spread evenly. They're saved in `loadout.txt` (`loadout1.streaks=Recon Sweep, Mortar Barrage, Sentry Turret`); older files get the three starters, and a locked streak is swapped for a starter.
- Everything is decided on the server (counts, activation, damage). Strikes (mortar, strafe, napalm, smoke) are planned from one random seed, so clients draw the shells, fire and smoke without extra messages; turrets, drones, gunships and crates send 22 bytes each with every snapshot; a gunship round or Hunter Drone blast is one 24-byte event. Armour rides in your own streak-state message (12 bytes since protocol 29, which also made the earned-streak bits 16 wide). Streaks 9 and up use kill-feed ids 214-229, so weapon ids stop at 213.

### Launchers

**Launchers are secondaries** (you carry one instead of a pistol) that fire real projectiles: rockets and grenades fly, drop, can be dodged and go off on contact, with a blast that works like a grenade's (walls shield you, Flak Jacket and going prone help, your own blast hurts you, Demolitions widens it, blasts push people and throw ragdolls). They're the counter to kill streaks: every launcher hits turrets, drones, the Gunship and other streak machines hard, and the **Skylance AA locks on**: aim down its sights at an enemy's flying streak and hold it in the sight; a tone ticks faster as the lock builds, goes solid and a red **LOCKED** bracket closes on the target; fire and the rocket homes in. Ground streaks (the sentry) never lock and take dumb fire. Ammo is limited: the magazine plus a few spare rounds per life (shown as `magazine | spare`), refilled when you respawn.

| --- | --- | --- | --- | --- | --- |
| Mule RPG | dumb-fire rocket, slow, big blast | 150 / 6.5 m / +60 | 1 + 2 | sentry in 2 direct hits, drone in 1 (if you hit it) | level 6 |
| Clover Break-Action | single-shot grenade launcher, arcing | 130 / 5 m / +40 | 1 + 5 | sentry in 3 | level 9 |
| Carousel Drum Launcher | 6-round revolving grenade launcher (bounces once) | 100 / 4.2 m / +30 | 6 + 6 | sentry in 3 | level 14 |

| Gluepot Sticky Launcher | sticky charges (stick to walls and people), remote detonated | 125 / 4.5 m / - | 3 + 3 | sentry in 3 | level 22 |

- **Arming**: a round flies a few metres before it arms (the Mule RPG 8 m); an unarmed hit is a dud that only does its direct-hit damage. Rockets self-destruct after their fuse, grenades go off at theirs.
- **Sticky launcher**: hip-fire sticks a charge to whatever it hits (up to the magazine's three out at once); **aim and pull the trigger** to set them all off. The HUD shows how many you have out.
- **Wire guidance**: the rocket turns towards whatever is under your crosshair for as long as you keep the launcher in hand (switch away and the wire is cut); a "GUIDING" ring shows while one is on the wire.
- **Flares**: the Gunship carries one flare: it pops it when the first locked rocket closes in (45 m), and that rocket chases the flare instead, so a Gunship takes 2 locked Skylance hits (3 rockets with the flare). Attack and Hunter Drones have none.
- **Attachments**: launchers take only their own five: Thermal Tube Sight (2x, green tint), Quick-Lock Module (-30% lock time, +15% lock range), Spare Round (+1 round), Long Tube (+20% launch speed), Shoulder Pad (faster aim, less kick). Nothing made for guns fits a launcher.
- **Not in Gun Game** (the ladder is guns only) **and not in Zombies** (its weapons are built from parts; launchers aren't wall-buys or in the box).
- **Bots**: about a quarter of the bots on Normal and up (four in ten tacticians) carry a launcher. They bring it out for an enemy streak machine they can see (locking flying ones with the Skylance) and, on Hard and up, for enemies bunched together at a safe distance, then go back to their main gun.
- **Netcode**: the host simulates every projectile. A 38-byte spawn message starts it everywhere, each client flies its own copy with the same deterministic steps, guided and stuck ones get a 29-byte correction with the snapshots, and a 25-byte message ends it with the server's result. Your own rocket appears the moment you fire (predicted) and the server's copy takes over without a jump; a new rocket is flown forward by the shooter's latency (up to 100 ms) so it is where the shooter saw it. Protocol 30.
- **Modding**: launchers are weapon files in `Weapons/Launchers` with a `"launcher"` block (projectile, guidance, speeds, blast, arming, fuses, lock-on, cluster, thermobaric; see [Weapons/README.md](Weapons/README.md#launchers)). New flying kill streaks register how launchers treat them (`LauncherTargets.Register`: airborne, lock-on hits to kill, flares).

### Bullet penetration

**Bullets go through thin or soft walls when the round is big enough.** Every gun has a penetration power (from its class and calibre: pistols and SMGs low, rifles medium, DMRs and LMGs high, snipers very high; shotgun pellets almost none, slugs medium; launchers, the Toy Blaster and the Arc Carbine none, the Railspike most). Passing a box costs its thickness along the bullet's path (so an angled shot goes through more) times its material's resistance; the round goes on with the power it has left, its damage cut after each surface (it keeps the material's share, less the harder the wall was), and passes at most **3 surfaces** (touching boxes, such as a wall's core and its plaster linings, are one surface). A surface it can't get all the way through stops it at its front. **Never:** the terrain, the ground, rock, asphalt, the map's boundary, moving platforms, the Bocage hedgerows (earth banks), anything thicker than its material's limit (25 cm of concrete, 35 cm of brick, 6 cm of metal), crates and cars thicker than that. Headshots still count through a wall. **AP Rounds** (magazine slot) give 1.6x the power, the **Hollow Point Mag** 0.6x.

So a building's plaster interior walls (25 cm + linings) stop pistols and SMGs but not LMGs, DMRs and snipers, wooden floors and doors let most rifles through, and brick or concrete outside walls stop everything but the heaviest rifles (the 10 cm wood + 10 cm plaster check: the Needle passes both with 61% of its damage).

- **What a surface is made of** is the bullet-impact surface (the box's texture refined by colour and facing, a building part's own material, a door's wood or metal, the terrain's ground); props by their name (`"props"` rules in the file: sandbags are sand, crates and pallets wood, cars and trucks metal, the Bocage hedgerows earth that stops everything), else their biggest textured parts, else how they break.
- **Server-authoritative**: the host extends each pellet's ray through what it can pass and hits players behind with the rewound positions of lag compensation; breakable props, doors and glass along the way take the hit too. The shooter predicts the same tracer and hit marker; a hit through a wall shows a second, inner set of marker ticks. Bots get no wallhacks: they only shoot at people they see, except that an Insane base of fire may now put its suppressive fire on a fresh last known spot through a wall its gun goes through.
- **Both sides of the wall** get an impact mark (the exit hole 30% bigger) and a puff of dust (sparks off metal), the same on every screen: a shot that went through something sends its origin after the tracer ends (12 bytes; flag 64 in the Shot message, 128 = a hit through a wall). Older clients ignore it. No protocol change of its own.
- **Data**: `Materials/penetration.json` (`call-of-slop-penetration/1`): per material `resistPerCm`, `maxCm` (0 = never) and `damageKept`; per weapon class `base` + `perCalibre` x calibre; `shotgunPellets`; `maxSurfaces`; `props` rules. A weapon file can give `"penetration"` (an absolute power, -1 = derived) and attachments can change `"penetrationMult"` (see [Weapons/README.md](Weapons/README.md)). A map can switch it off with a top-level `"penetration": false` (on everywhere by default; see [Maps/README.md](Maps/README.md)).

### Melee

Press **V** for a quick rifle-butt. It reaches about 2.4 m and **kills in one hit** (150 damage against 120 health), from the front or behind. Entrenched (bullets only) and Flak Jacket (explosions only) don't reduce it, and Last Stand doesn't save you from it. It cancels a reload, has a 0.8 s cooldown, and you can't fire for a moment after swinging. It's resolved on the server with the same lag compensation as shots. Zombies and breakable props still take 55 damage from it (a built Zombies melee weapon has its own stats). Bots use it when you stay right up close to them: they need a moment in reach first (0.6 s on Easy, 0.35 s on Normal, 0.2 s on Hard, 0.18 s on Insane), so running past one isn't instant death.

### Bots

Bots play through exactly the same input commands as people (movement, mantling, stances, shooting, grenades, melee), so they follow the same rules. Difficulty (**Easy, Normal, Hard, Insane**) sets reaction time, aim error and turn speed ([Insane](#insane-bots-squads) also makes them play as squads). On top of that every bot has a **personality**, shown after its name, e.g. `[BOT] Brick (Rusher)`. A lobby gets a mix:

| Personality | Plays like |
|---|---|
| Rusher | Hunts the nearest enemy and fights up close with SMGs and shotguns; fast, twitchy strafing; barely retreats. |
| Marksman | Picks an open, preferably high perch, crouches or goes prone and holds long sightlines with DMRs and snipers; moves on after a kill. |
| Flanker | Takes side routes to get behind people (the path search avoids the direct line); commits to one strafe direction. |
| Anchor | Holds an open spot (or the objective) with rifles and LMGs, crouch-peeks, uses cover a lot, and only chases nearby. |
| Tactician | More grenades (including at where you ducked out of sight), pre-aims corners, retreats to cover to reload. |
| Chaotic | Any gun, any habit. |

Personalities also change engagement range, aggression, retreat health, strafing rhythm, cover use and perks (in Gun Game everyone gets the ladder's gun and the shared perks, so only the habits differ). In King of the Hill and Capture the Flag, each life a bot rolls whether it plays the objective or hunts, by personality: Anchors almost always go for it, Tacticians often, Rushers rarely. Bots navigate with a **waypoint graph** built for each map the first time it's played (a slice per tick, usually within a second or two; until then they steer straight): nodes on every surface you can stand on, linked where a player can really walk, step up, mantle (up to 1.7 m) or drop, checked with the game's own collision. They plan routes with A\*, cut corners when the way ahead is clear, climb ledges, step aside for each other in doorways, and re-plan when they get stuck. A bot that stays stuck escalates: after about 3 s it hops and backs off, after 6 s it avoids the spot, drops its goal and heads for the nearest walkable spot, and after 15 s (or 4 s off the walkable area, e.g. in a pit with no way out) it uses the same **Kill yourself** as the pause menu: a suicide, no kill for anyone, normal respawn. Holding a spot, the hill or a squad position, fighting, warmup, countdown and the results screen never count. Modes without respawns teleport instead (Zombies co-op bots join the nearest standing teammate; Last Man Standing goes to the nearest walkable spot). Each one is logged to `callofslop.log` as `[bots] stuck: ...` with the map, position and cause (once a minute per bot), and every match end logs the count for the map, so map trouble spots can be found and fixed. In a fight they keep to their weapon's range, strafe, duck behind cover to reload or when hurt, then peek back; out of a fight they chase where they last saw you, investigate gunfire, and glance around corners. They aim at the chest and drag their aim back down under recoil, so headshots are a minority of their kills.

**Bots and foliage.** Bots can't see through foliage, the way you can't: grass, bushes, hedges of bushes, shrubs and tree canopies hide you from them (tree trunks and the solid hedgerow props already block like walls), and so do cornfields. Bullets still go straight through plants. It goes by stance: lying in tall grass you're hidden from a bot 15 m away, but standing or crouching in knee-high grass your head shows above it and they see you; a crouch behind a chest-high bush hides you, standing behind it doesn't. Within 2.5 m a bot sees you whatever is in between. Hiding isn't silent: running near a bot (about 14 m, not with Dead Silence) or shooting gives your rough position away. When a bot knows roughly where you are in the cover (it saw you go in, heard you, or, for Insane squads, a squadmate who sees you called your spot), it may **fire blind** into the cover at its guess: short, slower bursts with a cone five times its normal spread around a spot that gets less accurate the longer it's been since it last knew anything, never at your head, and it gives up about 3 s after its last information. It never knows where you really are, so crawling away from where you were seen works. Only bots are affected (people see the plants on screen), the bots use every plant whatever your Foliage setting is, and none of it changes movement, bullets or the map's fingerprint. Under the hood the map's plants are rasterised once per map into a 1 m grid of cover layers (grass, brush, canopy) on a worker thread, and a sight line adds up the metres of foliage it crosses (1 m of dense leaves hides you) in about a microsecond (`Map.Concealed`, Source/Maps/FoliageCover.cs; Source/Game/BotFoliage.cs).

**How players and bots look.** Everyone shares one blocky body in the style of the legs and arms: a shirt with chest, belly and shoulders that meet the arms, a plate carrier (front and back plates, cummerbund, mag pouches and a patch in your team colour), a collar and neck, and a head with jaw, brow, nose, eyes and ears. Each name gets its own seeded look, the same on every machine and every match: skin tone, hair colour, a beard or not, and headwear (hair, a buzz cut, a helmet, a patrol cap or a team-colour bandana). Bots pick headwear by personality: Anchors always wear helmets, Tacticians mostly, Marksmen caps, Rushers bandanas or buzz cuts. A prestige hat replaces your headwear and sits on the head exactly as before. Zombies get the same treatment: a torn shirt over a bare belly, a slack jaw and a heavy brow. It's cosmetic only: hit boxes and the headshot line are unchanged. Beyond 30 m the small details (pouches, patch, collar, eyes, ears) are skipped, and a body costs at most 1.5x the draws of the old box body.
### Insane bots (squads)

**Insane** is Hard+ (faster reactions, tighter aim, faster turning) and, in team modes, the Insane bots on each team play as **squads of 3-4** (two bots make a pair; a bot alone plays solo). Each member has a role picked from its personality: a **leader** (Tacticians first) who picks where the squad goes, a **suppressor** (Marksmen, Anchors), a **flanker** (Flankers, Rushers) and, in a squad of four, a **support**. Squads share a **blackboard** of what their members have actually seen or heard (no wallhacks: an enemy nobody can see isn't on it, and contacts are forgotten after a few seconds), and plan together, one squad per server tick, about twice a second each:

- **Moving:** the squad heads for one shared goal (the mode's objective, the last contact, or a sweep towards the enemy's side) in a wedge around the leader. Near trouble it **bounds**: one pair moves 14 m ahead while the other holds, crouched, watching the way ahead, then they swap. If half the squad falls 25+ m behind, the leader waits and the rest **regroup**.
- **Attacking:** when a member spots you, the suppressor (and the leader) take spots with a line to where you were seen, keep their distance and keep you busy, with **suppressive fire** at your last known spot when you duck out of sight. The flanker goes round to your side or back (85-155 degrees off the suppressor's angle) on a route that avoids what you can see from where you were, waits at a staging point out of sight, and pushes when everyone is in place; it holds its fire until it has a good angle (unless you spot it). A support either sets up a **crossfire** from a second angle or, if it likes to flank, makes it a **pincer** from the other side. Their routes avoid each other, so they don't all come through one door. The push comes with a frag on your spot from someone who can't see you.
- **Trades and retreat:** a squadmate killed in view of you calls out your position and the nearest member comes to **trade** the kill. A squad of 3-4 down to its last member **retreats** towards its spawn, under smoke when the support carries it, and regroups.

In free-for-all, Insane bots are Hard+ individuals; in Zombies, Insane co-op bots spread their fire over different zombies and only the nearest one goes to revive a downed teammate while the others keep shooting. Pick Insane in the lobby's Difficulty row (single player and hosting); it's saved as `difficulty=Insane` in `settings.txt`, and older settings files load unchanged.

### Respawning

- **Loadouts only change between lives.** During a life you can still edit loadouts, and the changes apply the next time you spawn. The exceptions are the warmup and the 5-second pre-match countdown, when changes apply immediately.
- **Death cam and kill card.** When you die, the camera rises over your body, then turns to face whoever killed you and zooms in a little, following them for about 3 seconds. A **kill card** shows the killer's name, their gun with its attachments (optic marked), headshot, distance, how much health they had left and their streak (melee, grenades, streak rewards and killing yourself get their own versions). Click, or press the loadout key, to skip straight to the loadout screen. On wide screens the card stays next to the loadout window.
- **Kill notices.** When you kill someone, **KILLED <name>** appears under your crosshair in their colour (team colour in team modes), with tags under it: HEADSHOT, MELEE, the grenade or streak that did it (FRAG GRENADE, SENTRY TURRET...), LONGSHOT and the distance for gun kills from 40 m, DOUBLE / TRIPLE / QUAD KILL for kills within 2.5 s of each other (their lines stack), REVENGE on whoever killed you last, and every 5 kills in a row. It fades about 2 s after your last kill, next to the +XP popups. Only the killer sees it (not in Zombies); everyone's kill feed (top right) names both players and fades out.
- **Nobody is force-respawned.** When you die, the loadout screen opens after the death cam. Pick a loadout, then click **RESPAWN**. The button counts down the 3-second respawn delay, and clicking early queues it. You also start every session on this screen.
- Close the screen to just watch. Press the loadout key to reopen it.

### Mantling

Hold **forward + jump** at a ledge up to 1.7 m high (crates, low walls, window sills) to climb onto it. Windows are 1.3 m tall, so you go through them in a crouch: you land on the sill and carry on through. Keep holding forward to drop out the other side. Mantling is part of the shared movement code, so it's predicted and smooth online too.

### Slopes

On terrain maps (the High Ground pack, the Dev pack's Terrain Test) the ground's slope is measured over your footprint (a 0.4 m radius), not the single bump under your feet, so small noise in a hillside doesn't stop you or start a slide.
- **Walkable up to 45 degrees.** Walking uphill is full speed up to 25 degrees, then gradually slower: about 92% at 30, 82% at 35, 72% at 40 and 60% straight up a 45 degree slope. Going across or down a slope is full speed.
- **Grip:** while you move, a narrow steep patch (walkable ground within 0.45 m before and after it) that rises no more than a step (0.55 m) against the slope around it is crossed, so brief steep bumps don't stop you or kick you into a slide, and small terrain lips and edges are stepped over like stairs. Taller banks (up to 1.7 m) are mantled with forward + jump, as before.
- **Stuck to the ground:** walking over a crest or down a slope (up to the 45 degree limit) keeps you on the ground; you don't bounce or go airborne.
- **Steeper than 45 degrees** slides you down. The slide is capped at 8 m/s and you can steer across and down it (not up), so you can always steer out. Cliffs are still walls.

Boxes, ramps made of meshes and the like keep the old 42 degree rule. Bots use the same rules: their nav graph only links what a player can walk, routes prefer gentler ways up, they cut straight across hillsides when the line is walkable, and a bot that gets no closer to its next waypoint (walking up and sliding back) re-plans another way.

### Lobby size

Up to **32 players** (people and bots), but every map has its own limit: **8-10** on small maps, **12-16** on medium ones and **24-32** on large ones, worked out from the map's area (a map file can set its own with `"maxPlayers"`, see [Maps/README.md](Maps/README.md#player-limits)). The lobby shows **x / max players** under the bot slider, and the slider stops at the map's limit. With **Random** from a pack (or **True Random**), it goes up to the biggest map in the pool and the game picks among the maps that take everyone. The map list shows each map's limit.

- **Joining a full game:** a person takes a bot's place. If the map is full of people, the join is refused with "The server is full: x/y players on map".
- **Map vote:** only maps big enough for the people playing are offered. When a smaller map wins, bots it has no room for leave (people never do), and they come back on a bigger map: the bot count you set is remembered.
- **Spawns:** every map needs a spawn per player. Maps with fewer get extra spawns when they load (same floor, in sight of a hand-placed spawn, clear of walls), so the old maps play as they always did with more people. Spawning never puts you on top of someone.
- **Team Deathmatch** plays to 5 kills per player in bigger lobbies (40 up to 8 players, 80 at 16, at most 100).
- **Scoreboard:** columns are Player, **Level** (prestige and level, as in the lobby; `BOT` for bots), the mode's two numbers, Weapon and alive/dead. It shows nobody's health (your own is on your HUD). Above 12 players it switches to two compact columns (Blue and Red in team modes, the ranking split in two otherwise). The kill feed keeps 6 lines, and a burst of joins shares one line ("X and 9 others joined").
- **Bandwidth:** each client receives about 9 KB/s at 8 players, 13 KB/s at 16 and 21 KB/s at 32 (measured by the self-test over loopback, game data without UDP headers). The host sends that to every client.

### Server browser and public games

**Multiplayer** has three tabs:

- **Server browser:** lists games to join with name, map (with an orange **True Random** tag when the host plays True Random), players / the map's limit (and bots) and ping. Click Join. Games on your network show up automatically: the browser broadcasts on the local network and every hosted game answers. Public internet games show up when a master server is set (see below). The list refreshes every few seconds.
- **Host a game:** the map (**Change map...** opens the [map select screen](#map-select): random from a pack by default, one map, or True Random), port, UPnP, bots, **server name**, and **Advertise server**, which lists the game publicly through the master server.
- **Join by address:** type an IP and port directly.

**About public listing:** a public list needs something always online that hosts can report to and browsers can ask. That's the **master server**, built into the game: run `CallOfSlop.exe --master` (optionally followed by a port; the default is UDP 27050) on any always-on PC with that UDP port reachable. It tries UPnP itself. Then everyone enters that PC's address under **Settings > Player > Master server**. The master only stores addresses: names, maps, players and pings come straight from each game. Without a master server, the browser still finds every game on your LAN.

Single player works the same way: **Change map...** shows the current choice and opens the map select screen. With random picked, the lobby background tours the pack's maps (True Random: every pack's).

### Map select

**Change map...** (Single player and Host a game) opens the map select screen:

- **Left: the map packs**, one tile each in their `pack.json` order (Dev last), with the pack's name, map count, sizes ("7 small, 9 medium, 8 large") and a small picture: a collage of up to four of its maps, seen from above. **True Random** sits at the bottom.
- **Right: the open pack.** Its description, then **Random** at the top, then its maps, smallest first, each with a picture, size, player limit and description. Opening a pack always pre-selects **Random**. A map too small for your bots is shown in orange (the bots are cut to fit).
- **Click** selects, **double-click** (or **Enter**, or the orange **CHOOSE** button) takes it and returns to the lobby; double-clicking a pack tile takes that pack's Random. **BACK** or **Esc** leaves without changing anything. Keyboard: **Up/Down** through the maps, **Left/Right** (or Page Up/Down) through the packs. The lobby background follows the selection, and CURRENT marks what's chosen now.
- **True Random** is a pack that isn't a folder: every match is on a random map from **all** packs except **Dev** (its test maps aren't balanced for play; you can still pick them from the Dev pack). Like random from a pack, it only picks maps that take you and your bots, and the map vote afterwards offers maps from every pack. A pack can leave itself out with `"trueRandom": false` in its pack.json.
- The pictures are rendered by the game itself (no image files): each map once, into a small offscreen texture at 384x216, one per frame so the screen never freezes, and cached until the map's file changes. If the graphics card can't do it, plain coloured tiles are shown instead.

The choice is saved in `settings.txt` as before (`map_pack=<pack name>`, `map=<map>`, `map_random=1|0`); True Random is `map_pack=*all`. Older settings files load unchanged.

### Map vote

At the end of every match the results screen shows **three maps to vote on**, taken from the pack of the map you just played (with **True Random**: from every pack but Dev; from every map if that pack is too small): one small, one medium and one large where possible, never the map you just played. Click one or press **1 / 2 / 3**. You can change your vote until the 12-second timer runs out, and the live tally shows which map is leading. Only maps big enough for the people playing are offered (see [Lobby size](#lobby-size)): a map's player limit in the current mode must be at least the number of **human** players here, counting the host and anyone still loading in; bots don't count (they leave a smaller map and come back on a bigger one). If fewer than three maps are big enough the ballot has fewer options; if none is, the map you just played is offered again when it is big enough, otherwise the largest maps (the server log says so). If someone joins during the vote and an option becomes too small, that option is swapped in its slot for another map that fits (votes for it are dropped, so those players vote again; other votes keep counting), or removed if no other map fits. The same rule applies if the winner can't be used (a map file removed meanwhile): a random map that fits is used instead. Only human players vote; bots never do and aren't counted. Once every human has voted, the timer drops to 3 seconds. The next match starts on the map with the most votes, with ties broken at random among the tied maps; if no human votes (say, a solo host who doesn't click), one of the three is picked at random. Players who join during the results screen see the ballot and can vote.

**Maps are data files.** Each map is one `.json` file in a pack folder under `Maps`: its name, size, sky colour and a list of building ops (`Building`, `WallX`/`WallZ` with door and window holes, `Slab` with stairwells, `StairsX`/`StairsZ`, `Container`, `Car`, `Hill`, `Tree`, `Watchtower`, `Hangar`, `Bridge`, `TrainCar`...). To add a map, drop a file into a pack folder (or a whole pack folder into `Maps`) and click **Refresh maps** in the lobby; no restart or recompiling. In single player, **Reload map files** in the Esc menu rebuilds the map you're standing in from its file, for quick edit-and-look map making. Maps can also have **terrain**: an optional `"terrain"` object shapes the ground with hills, ridges, valleys, plateaus, cliffs, ramps and noise (a heightfield you walk on, shoot over and throw grenades across; slopes up to 45° can be walked, a bit slower uphill, steeper ground slides you down and cliffs are real walls; see [Slopes](#slopes)), and the ops are placed on the ground. The **Dev** pack's *Terrain Test* map shows it off. Terrain can also have **holes and caves** (`hole` and `cave` features): pits, sinkholes and skylights, and tunnels and chambers under the ground with rock walls and ceilings that get darker inside, which players, bots, bullets and grenades all use; the Dev pack's *Cave Test* map has a tunnel between two entrances through a chamber, a sinkhole into a side passage and a few pits. Anyone can make one: **[Maps/README.md](Maps/README.md)** is the map makers' guide, with a full example and every op. A file with a mistake is skipped with a message that names the file and the problem (also shown in the lobby), and `CallOfSlop.exe --check-map FILE` checks one without starting the game. Online, servers and clients identify maps by name plus a geometry fingerprint, so a player missing a host's custom map is told which file to get, and the server browser shows maps you don't have in orange.

**Foliage.** A map file can also have a `"foliage"` section: grass, bushes, shrubs and trees scattered over areas, or placed one by one (see [Maps/README.md](Maps/README.md#foliage)). Only tree trunks are solid. The rest is drawn with instancing, culled in 16 m chunks, thinned out with distance through a dither (no popping) and sways in the wind. The **Dev** pack's **Foliage Test** map is a flat 100 m meadow for trying it out. **No-go zones:** nothing grows indoors: plants under a roof, a floor above, a bridge deck or an awning, or inside a box or a cosmetic mesh, are left out (trees don't count as roofs), and paved surfaces thin them out by material (intact concrete, tiles and floors grow nothing; a map can mark cracked paving or busted paths with a small fraction, so an odd tuft or shrub comes through). Maps can add explicit `exclude` and `include` zones and turn the automatic rules off (see [Maps/README.md](Maps/README.md#no-go-zones)). Maps without foliage are unchanged. Lighting (sun, sky and ground ambient, fog) is shared by boxes and plants (`Source/Render/Lighting.cs`).

**Skies.** A map file can have a `"skybox"` section: a drawn sky with a zenith/horizon gradient, a sun disc and glow placed by a direction or by time of day and latitude, a moon with phases, stars and drifting clouds, or an image sky (a cubemap of 6 PNGs, or a PNG/HDR panorama). Presets (`clear`, `overcast`, `dusk`, `night`, `desert`, `alpine`) cover the common cases: `"skybox": "dusk"`. The map's lighting follows its sky (sun direction and colour, ambient), and fog fades distant things into the sky colour behind them. Maps without a skybox keep their flat sky colour and look exactly as before. The **High Ground** maps each have one, and the **Dev** pack's **Sky Test** map is made for trying them out (see [Maps/README.md](Maps/README.md#sky)). **Settings > Video > Sky quality**: Low draws the gradient, sun and moon; High (default) adds clouds and stars. The sky is drawn last in the opaque pass, only where nothing else covers the screen, and costs well under 0.2 ms of GPU time (`[sky]` lines in the log; `Source/Render/Sky`).

**Moving platforms.** A map file can have a `"movers"` section: rotating platforms, sliding platforms (back and forth, or round a looping path) and elevators, each built from a few boxes and running on a constant loop (see [Maps/README.md](Maps/README.md#movers)). Stand on one and it carries you (a turning platform turns you and your view with it), walk around on it as on solid ground, and jump off with its momentum. They push you out of their way rather than passing through you, and never crush you into a wall. Bullets, grenades and sight lines hit them where they are. Their motion is worked out from the server's clock on every PC, so they cost no network traffic and your own movement on them is predicted without jitter. Bots keep out of their paths. The **Dev** pack's **Physics Test** map has slow and fast spinning discs, a spinning bar to jump over, sliders, a ferry across a gap and a looping elevator up to a deck.

**Props.** Trash cans, dumpsters, wheelie bins, crates, pallets, oil drums, cones, barriers, benches, lamps, hydrants, bricks, rubble, newspapers, bottles, cardboard boxes, chairs, tables and more: 298 props ship in the `Props` folder, one JSON file each in category folders: the 61 starter props (`Street`, `Industrial`, `Debris`, `Furniture`, `Nature`), the indoor and everyday set in `Household`, `Office`, `Kitchen`, `Garden` and `Misc`: furniture, appliances, office kit, kitchen things, garden things, ducks and pets (see [Props/README.md](Props/README.md)), plus 114 outdoor props in `Vehicles` (cars of every body type, a bus, trucks, a forklift, bikes), `Rooftop` (air conditioners, vents, air ducts, chimneys, a water tower, satellite dishes, solar panels), `Utility` (power poles, transformers, manholes, fire escapes, scaffolding, ladders), `Signage` (traffic lights, road signs, a billboard, shop signs) and `Urban` (a bus shelter, a phone booth, a newsstand, an ATM, fences, barriers). The `Military` folder (58 props, see [Props/Military/README.md](Props/Military/README.md)) adds sandbags, barbed wire, tank traps, field guns, ammunition crates (shell crates and fuel racks explode), pallets, tents, a searchlight, a guard tower and the landmines, and in `Military/Vehicles` five tanks, four full-size parked planes (props can be up to 24 m), jeeps, trucks, an armoured car and a sidecar motorcycle, with Desert and Winter variants; the Dev pack's **Military Props** map shows them all. Maps place them one by one or scatter them with a `Clutter` op that keeps them clear of spawns, routes and doorways (see [Maps/README.md](Maps/README.md#props)). Solid props block players, bullets and bots like any box; small litter is cosmetic and fades out with distance. All of it is drawn instanced and culled in 24 m chunks, a few draw calls for hundreds of props; the game logs a `[props]` line every 5 seconds on maps with props. **Breakable props** (crates, boxes, bins, bottles, chairs, pallets, cones) break when shot, hit or blown up and shatter into pieces that bounce, settle and fade out; the explosive barrel goes off. The host decides what breaks and tells everyone, and every match starts with everything whole. Health follows the material: glass and paper break at a touch, plastic and wood take a few shots, metal more, and vehicles, concrete and big structures are unbreakable cover (the material health guide is in [Props/README.md](Props/README.md#material-health-guide)). The **Dev** pack's **Prop Gallery** shows the starter props, **Prop Gallery 2** the outdoor set, **Prop Gallery 3** the indoor set, **Prop Yard** is a small dressed street. The Classic and Collision Point maps don't use props. **Landmines** (`Props/Military`): a half-buried pressure-plate mine clicks when someone steps on it and goes off 0.35 s later (a quick sprint gets you out wounded), or when shot or caught in another blast; its blast is neutral and hurts everyone (the shooter gets the kills on their enemies, other deaths read "Landmine" and are nobody's kill), bots route round mines, zombies set them off, and a map can bring a breakable prop back with the Prop op's `respawn` (see [Props/README.md](Props/README.md#landmines)). The Dev pack's **Landmines** map shows them; no other map uses them. **Animated props** (`Props/Animated`, 65 of them: fans, roof turbines, a windmill and a wind turbine, flags, banners, swinging signs and lanterns, flickering lamps, neon signs, beacons, traffic and crossing lights, radar and satellite dishes, clocks, a ferris wheel and a carousel, a pumpjack, conveyor rollers, a shaking generator, a cement mixer, swings, wind chimes, a pendulum clock, a Newton's cradle, bobbing buoys and ducks, screens and arcade machines...) have parts that spin, swing, bob, shake, blink, pulse, flicker or cycle, set by an optional `"anim"` block on a part (see [Props/README.md](Props/README.md#animation)). It's cosmetic: colliders never move. The motion is worked out on the graphics card from the time and each prop's position (so a row of fans doesn't turn in lockstep, and flags and turbines follow the same gusts as the grass), costs nothing on the CPU, and props farther than 80 m (per prop) hold still and are drawn by the plain prop shader. The `[props]` line adds the animated props drawn moving and still and the animated pass's GPU time. The Dev pack's **Animated Props** map shows them all; existing maps don't use them. **Flags** fly national flags from a flag pool (`Props/Flags/flags.json`: the US, UK, French and Finnish flags): a Flag on a Pole picks one from its position (the same on every PC and every match, and mirrored flags match), and a map can name the flag per placement or limit its pool (see [Props/README.md](Props/README.md#flags)). The Cluttered and Dev maps use it; the Dev pack's **Flag Lineup** shows all four.

**Map shapes.** A map doesn't have to be a rectangle: an optional `"boundary"` section makes the playable area a circle, an oval, a polygon (concave is fine) or a smooth blob such as a bean, optionally with a seeded wobble so the edge is irregular, shown as a wall, a terrain cliff, a fence, a hedge, a line of boulders or props, or nothing (see [Maps/README.md](Maps/README.md#boundaries)). An invisible barrier runs exactly along the outline, so players, bots, grenades and debris never leave, and spawns, waypoints, foliage, clutter and the bots' routes all stay inside. The floor is drawn following the outline with a darker ground beyond it fading into the fog. Maps without a boundary are unchanged. The **Dev** pack's **Shape Test** map is a bean with a curved wall.

**Meshes and models.** Maps can also place round and sloped shapes and real 3D models, not only boxes: the `Mesh` op makes cylinders, cones, spheres (UV and geodesic), capsules, rings, ramps, pipes and rounded boxes from a few numbers, and the `Model` op places glTF 2.0 models (`.glb` / `.gltf`) from the `Models` folder, with their node hierarchy, materials and base colour textures (see [Maps/README.md](Maps/README.md#meshes-and-models) and [Models/README.md](Models/README.md)). Three small test models ship (a barrel, a traffic cone, a lamp post). All meshes share one GPU vertex and index buffer and are drawn instanced, one draw call per mesh and LOD, culled outside the view and switched to simpler LODs with distance, lit and fogged like the boxes; the game logs a `[mesh]` line every 5 seconds on maps with meshes. They are cosmetic for now (no collision), so map makers put a `Block` inside where players need cover. The **Dev** pack's **Mesh Test** map shows every shape plain and textured, a LOD line, the models and a field of 128 instanced shapes.

**Decals.** Maps can paint flat pictures onto their surfaces: oil stains, cracks, water stains, manhole covers, drain grates, road arrows, hazard stripes, graffiti, posters, grime and soot. Each decal is one JSON file in the `Decals` folder (format `call-of-slop-decal/1`): layers of simple shapes (circles, rings, rectangles, ragged splats, cracks, speckles, lines, stripes, with soft edges and grunge noise) and/or a small PNG, a size in metres, size, turn and brightness variation, a blend mode (`alpha` paint or `multiply` dirt) and the surfaces it may land on. The `Decal` and `DecalScatter` ops project them onto boxes, buildings, the terrain (never over a hole) and meshes, wrapping over kerbs and edges (see [Maps/README.md](Maps/README.md#decals) and [Decals/README.md](Decals/README.md)). They are cosmetic and not part of the map's fingerprint. A map's decals are baked once into one buffer, culled in 24 m chunks and faded with distance; decals on a door or breakable box vanish while it is open or broken. About 80 placeable decals ship: ground grime and litter (puddles, mud, leaves, gravel, tyre tracks, footprints), road and court markings, wall damage, signs, abstract posters and graffiti, things lying on the floor (covers, grates, rugs, litter, glass) and ceiling stains ([the catalogue](Decals/README.md#the-catalogue)). A map pack may also carry its own decals in `Maps/<Pack>/Decals` (seen only by that pack's maps; one with a global decal's name replaces it there, `"global:Name"` still means the global one; see [Decals/README.md](Decals/README.md#pack-decals)). The **Dev** pack's **Decal Test** map shows the system's features and **Decal Surfaces** shows every placeable decal. **Pack Decals** shows the Dev pack's own decals. **Bullet impacts** are decals too: every shot that ends on a wall, floor or the terrain leaves a hole picked for the surface (concrete, plaster, asphalt, brick, wood, metal, tiles, dirt, grass, sand, rock, snow, three or four variants each, sized by the gun's calibre), and grenades, launcher rounds and strikes leave a scorch, the same on every player's screen (they follow the server's hit points, no extra network traffic). **Settings > Video > Bullet impacts**: **High** (default, 1024 kept at once) **/ Medium** (512) **/ Low** (128) **/ Off**; each player keeps at most 64, the oldest fade out first, close shotgun pellets merge when the pool is busy, and holes on a door, window or breakable box vanish when it opens or breaks (props, drawn as models, take none). The decal pass logs a `[decals]` line every 5 seconds (decals and impacts drawn, draw calls, CPU and GPU time; target under 0.1 ms).

**Buildings.** Maps can place whole furnished buildings from the `Buildings` folder with one op (`{ "op": "Building", "name": "Small House", "at": [x, z], "yaw": 180 }`): walls with real door and window openings, floors, ceilings, stairs, roofs (flat, gable, hip, shed or none), porches, awnings, balconies and mezzanines, and furniture placed room by room by type (a bedroom gets a bed against the far wall with bedside tables and lamps, a kitchen a run of counters with a kettle on them...), never in a doorway or in front of a window. Each building is one folder (`building.json`, plus its own props and furnishing rules if it needs any; see [Buildings/README.md](Buildings/README.md)), with palettes, seeds, mirroring, turning and floor counts for variants. **Doors** open and shut with the interact key (F) and swing on their hinges; shut, they stop players and bullets; bots open them as they go; bullets, melee and grenades break them (wood takes about 5 rifle hits, metal 14), and a broken doorway stays open. **Window glass** stops you but not bullets: shoot it out (it shatters) and climb through the empty frame. The host decides and tells everyone, players joining mid-match get the doors and windows as they are, and every match starts with everything whole. The bots' routes run through doorways and up every staircase, and no foliage grows indoors. Building walls are drawn instanced (a whole street of buildings is a handful of draw calls; the game logs a `[buildings]` line). Ten starter buildings ship: a small house, a two-storey house, an apartment block, a corner shop, a diner, an office building, a warehouse with a mezzanine, a gas station, a garage and a ruined house; the **Dev** pack's **Building Yard** shows them all with variants. Ten more industrial ones (a factory with an assembly line, a brewery, a sawmill, a substation control house, a cold store, a recycling plant, a print shop, a chemical lab, a machine shop and a grain barn with silos) are on the Dev pack's **Buildings Industrial** map, and ten themed residential ones (a farmhouse, a 1960s ranch house, a Victorian townhouse, a mobile home, a beach bungalow, a duplex, a terrace of three row houses, a modern villa with a pool, a three-storey student dorm and a hunting lodge) line the Dev pack's **Residential Street**. `tools/buildings` previews and checks building files without the game.

Movement handles any stack of boxes: you stand on anything, walk up steps up to 0.55 m, and bump your head on ceilings.


Surfaces are textured with a few tiny patterns generated in code (concrete, brick, wood planks, metal panels, floor tiles, dirt), tinted by each block's colour. The material is picked automatically from each block's shape and colour: crates get planks, walls get brick or concrete, floors and roofs get tiles, sandy ground gets dirt. Proto Box keeps its prototype grid.

### Display

- **Windowed:** pick a size from your monitor's resolutions, or drag the window edges. The game remembers the size and position.
- **Borderless fullscreen:** a frameless window covering the monitor at its native resolution. Alt-tab is instant.
- **Fullscreen:** exclusive fullscreen at the resolution you choose.
- **UI scale:** menus and HUD scale with the window height automatically (about 1.2x at 1080p, 1.6x at 1440p). The slider adjusts on top of that, from 0.6x to 2x, and applies when you let go.
- **Foliage:** **Off / Low / Medium** (default) **/ High**. How much grass, how many bushes and shrubs, and how far away they're drawn, on maps that have foliage (try the **Dev** pack's **Foliage Test** map). Off draws none of it and costs nothing. Tree trunks are always there, because they're solid: they stop players and bullets. Grass, bushes and tree tops never do. The game logs a `[foliage]` line every 5 seconds on foliage maps (plants drawn, draw calls, CPU and GPU time) in callofslop.log.
- **Bullet impacts:** **Off / Low / Medium / High** (default). How many bullet holes stay on the map at once: 128, 512 or 1024 (each player at most 64; the oldest fade out). Off draws none and costs nothing. Saved as `impact_decals` in `settings.txt`; older files get High.
- **Head bob:** 0-100% (default 100%). How much the camera bobs as you move: two small dips per stride, timed to your legs' footfalls, and a slight side-to-side sway and roll once per stride. It grows with ground speed, from about 1 cm and 0.2 degrees at a walk to about 4.5 cm and 0.8 degrees at a full sprint. There's none in the air (jumping, falling, mantling) or while prone, half while crouch-walking, and it fades out as you aim down sights, so scopes stay steady. It eases back in after you land. Only the picture moves: your aim and your bullets always come from the steady eye, and nothing is sent over the network. 0% is the old, perfectly steady camera. Saved as `head_bob` in `settings.txt`; older settings files load with 100%.
- **HUD width:** on ultra-wide monitors the in-match HUD (session info, kill feed, health, ammo, match bar, banners, scoreboard) stays inside a centred area so it's easy to read. **16:9** (default) keeps it 2560 px wide on a 3440x1440 or 5120x1440 screen; **21:9** allows 3360 px; **Full width** uses the screen edges. On 16:9 or narrower screens all three are the same. The crosshair is always centred, the blood splatters sit at the edges of this area (see **Blood**), and the damage effects always cover the whole screen (a scope's lens is sized from the screen height, so on an ultra-wide screen more of the eyepiece shows at the sides).

- **Blood overlay:** **Full** (default) **/ Subtle / Off**, and **Blood colour:** **Red / Dark**. Blood splatters at the screen edges as your own health drops and blood marks on hurt players and zombies; see **Blood** above.
- **Name tags:** **All** (default) **/ Team only / Off**, plus **Teammate health bars** (off by default). Names float over players' heads, CoD style:
  - **Teammates** (everyone in Zombies) are tagged whenever they're on screen within 60 m, *through walls*, so you can find your friends. In their team colour (in Zombies everyone is on the one co-op side: the friendly blue, also in the HUD's points list and the scoreboard), fading from 30 m to 60 m.
  - **Enemies** (everyone in free-for-all and Gun Game) are tagged only while your crosshair is on them, they're within 40 m and you can actually see them: walls and smoke hide the tag, so it never gives anyone away. The tag lingers half a second (fading) after your crosshair leaves, and drops at once if they step behind cover. An enemy shown through walls by your Recon Pulse or Recon Sweep can be tagged by aiming at their outline. In the enemy team's colour (red without teams).
  - Bots show their names ("[BOT] ..."). Never your own tag, never on dead players. Through a magnified scope tags stay but are a quarter smaller. While you're dead, teammates stay tagged from the death camera and your killer is tagged.
  - Tags shrink with distance and scale with the window height like the HUD (so they're the same size on 1080p, 1440p, 21:9 and 32:9), stay inside the screen, and a tag that would cover a nearer one stacks above it or fades.
  - Cheap: one ray-box test per enemy and at most one line-of-sight ray every 0.1 s (for the enemy you're aiming at), no allocations. Saved as `name_tags` and `name_tag_health` in `settings.txt`; older files get All. The distances and sizes are data in `UI/NameTags.cs` (`NameTagRules`).

### Stances

| Stance | Height | Speed | Spread | Recoil | Notes |
| --- | --- | --- | --- | --- | --- |
| Standing | 1.8 m | 100% | 100% | 100% | Can jump and sprint |
| Crouched | 1.2 m | 50% | 75% | ~85% (per gun) | Fits behind low walls and crates. LMGs lose almost all sideways recoil |
| Prone | 0.6 m | 22% | 50% | ~65% (per gun) | Can't go prone in mid-air. Your hitbox is long and low, and your head is out front |

Standing speed is 6 m/s walking and **13.5 m/s sprinting** (before your weapon's mobility, aiming and perks); stance percentages are of the walking speed.

**Sprinting costs accuracy.** While you sprint, and for 0.3 s after you stop (the penalty fades out), your spread is multiplied by a per-class factor: shotguns x1.5, SMGs and pistols x2, assault rifles x2.75, DMRs, snipers and LMGs x3 (special weapons x2.5). The crosshair blooms to match. Holding Shift while standing still doesn't count, and a fast walk (Lightweight, Head Start, Afterburner) isn't sprinting. You still can't aim down sights while sprinting (aiming stops the sprint). Steady Aim and attachments stay multiplicative with it (Steady Aim sprinting: x0.65 of the sprinting cone); stance and movement terms apply on top as before. It runs in the shared simulation, so prediction, the server and bots agree: the server widens a cone a client sends while sprinting to at least 75% of the honest sprinting hip cone (`Source/Game/SprintSpread.cs`, where the class factors live).

You can't stand up where there's no headroom (for example under a container roof); from prone you'll get up to a crouch if that's all that fits. Stance is part of the shared 60 Hz simulation, so prediction, the server and lag compensation (which rewinds stance as well as position) all agree. Bots crouch for long-range shots; Marksmen and Hard snipers go prone, and bots crouch-peek in close fights and duck behind low cover to reload.

### Progression

You earn XP in **single player and multiplayer** alike. There are two tracks, both filled by the same play:

- **Account XP (levels):** +100 per kill, +50 more for a headshot, +25 more for a grenade kill, **+150 for finishing a match** and **+250 for winning it**. **Each level unlocks a weapon, grenade or equipment**, 48 levels in all. Perks, kill streaks and loadout slots unlock on top of that, spread evenly over the same levels. A level costs ~2,400-3,800 XP.
- **Weapon XP (attachments):** each gun earns its own XP: +100 per kill with it, +50 for a headshot, plus +150 per match for the primary you carried (+75 for the secondary). Its attachments unlock along a curve, with the first few quickly and the last ones slower.

The pacing is a rough target rather than a hard rule. A typical match is around 7 kills, which is ~1,000 XP on each track. So:

- **A gun is fully kitted out in 3-7 matches.** Guns with few attachment options (pistols) are on the short end, and guns with lots (rifles, DMRs) on the long end.
- **A new level, and with it a new weapon, comes at about the point your current gun is ~60% kitted.** That works out to roughly every 2-3 matches, so you get time with each gun before the next one shows up.

The lobby shows your level and next unlock, and the level bar at the bottom of the loadout screen opens the progression page, which lists every level. In a match, XP pops up by the crosshair, and banners announce level-ups and new attachments. Progress is saved to `progress.txt`, with weapon XP stored by weapon name (`wx.<name>=...`). Older saves carry over: their numbered weapon XP is converted to names, and old per-weapon kill counts become weapon XP.

- **Level 1:** BR-1 Prototype, Vanguard AR, Hornet SMG, Breacher Pump, Marksman M14, P9 Sidearm, Mk.23 Tactical.
- **Levels 2-48:** the other 43 weapons plus the Frag Grenade (level 4), Recon Pulse (8), Impact Grenade (13) and Smoke Grenade (20), in a fixed order. The tactical equipment sits on top of that: Stim Shot (5), Flashbang (10), Decoy (13), Motion Sensor (16), Stun Grenade (19), Trophy System (24), Deployable Cover (28), Tactical Insertion (32). The fun ones come last: Grinder Rotary, Railspike, Toy Blaster.
- Locked items appear as `[LOCKED] ... level N` (weapons) or `[LOCKED] ... N weapon XP` (attachments). Bots ignore progression.
- Weapons added as files unlock at the level their file asks for (`unlockLevel`), or at level 48.
- Unlocks are kept on each player's own PC.

### Prestige

At max level (48) the lobby's **PRESTIGE** button (under the level bar; greyed out before max level) resets your account for a hat. A confirmation dialog says what resets and which hat you get ("Prestige 1: unlocks the Beanie"). There are five prestiges, one hat each:

| Prestige | Hat |
| --- | --- |
| 1 | **Beanie**: a small red knit beanie with a folded cuff and a bobble |
| 2 | **Baseball Cap**: blue crown, brim forward |
| 3 | **Fedora**: pinched crown with a black band and a wide brim |
| 4 | **Top Hat**: tall black cylinder with a red band |
| 5 | **Ridiculous Top Hat**: about 3.5 times as tall as the top hat (1.4 m), sways as you move |

- **What resets (the CoD rule):** level and account XP go back to level 1 / 0 XP, and every gun's weapon XP is cleared, so weapons, grenades, equipment, perks, kill streaks, loadout slots and attachments all lock again and are earned again. Loadouts fall back to unlocked items on their own (as after Reset level).
- **What you keep:** your hats and your lifetime stats (kills, headshots, matches, wins). Settings > Reset level keeps your prestige too.
- **Wearing a hat:** pick it in the loadout's cosmetics slot (None or any unlocked hat; locked ones show "Prestige N"). Others see it on your head in third person, in the death cam and kill cam, and lying by your corpse; you never see it in first person.
- **Cosmetic only:** hats have no collision and don't change your hitbox, and prestige gives nothing else. Bots never prestige and never wear hats.
- Your prestige shows as **P2** before your level: in the lobby, on the HUD level line and in the scoreboard's **Level** column (`P2 L13`, with the hat the player wears beside it; bots show `BOT`).
- Saved in `progress.txt` as `prestige=N`; older saves load as prestige 0. Hat models are data: `Cosmetics/hats.json` (format `call-of-slop-cosmetics/1`; boxes in head space, `"round"` parts made of a few turned boxes).
- **Network:** your client sends its prestige and level after its name in the Hello; the roster carries prestige, level and hat for every player (3 bytes each, nothing in the snapshots). The server only uses the reported prestige for what it shows and to check the hat you pick (`Cosmetics.IsUnlocked`); it never affects gameplay. A level-up mid-match reaches everyone's scoreboard at your next respawn: the loadout packet carries your prestige and level too, and the server resends the roster only when they changed (nothing in the snapshots; older clients and servers simply skip the two bytes).

### Grenades and equipment

The loadout has a **Grenade** slot (2 per life) and an **Equipment** slot (1 per life), both refilled when you respawn. Projectiles are simulated by the server: they bounce off walls and floors, and blasts are blocked by walls. Everything is thrown at 22.5 m/s (plus a little lift and half your own speed), which carries about **34 m** on flat ground at the best angle (about 40 degrees up); a frag thrown that far lands with a few tenths of a second to spare before it goes off.

It beeps once a second, so enemies can hear where it is. |
| **Flashbang** (equipment, 2) | Level 10 | Goes off 1.4 s after the throw. Counters to the tactical gear: Flak Jacket halves flashes and stuns; turn away from a flash you hear land; shoot devices (enemy devices stop your bullets and take the damage, and their lamps are red, yours green); a grenade or streak blast tears them down; a Trophy System eats Flashbangs, Stuns, Decoys and Motion Sensors too. Devices vanish when the match ends or their owner leaves. Modes without equipment (Gun Game) hand out none. In Zombies, a flash or stun staggers the zombies it catches.

Bots on Normal and Hard throw frags (and sometimes impacts) at targets 6-15 m away, picking the angle that makes the grenade go off at the target (bounces and roll included); Tacticians throw more, also at where an enemy just ducked out of sight (up to 22 m away). Explosions shake your screen when they're close. Bots carry a tactical item that fits their personality (Rushers: flash, stun or stim; Marksmen: motion sensor, cover or trophy; Tacticians a bit of everything) and use it when it fits: a flash at an enemy in view or where one just ducked out of sight, a stim when hurt, a trophy when a grenade comes in, cover in a long gunfight.

### Ragdolls and blast knockback

When anyone dies (a player, a bot or a zombie) their blocky body goes limp as a **ragdoll** and falls the way the kill pushed it: along the bullet, harder for big-calibre and high-damage guns (a shotgun or sniper throws a body, a pistol nudges it), a headshot snaps the head back, a melee hit shoves the body away from the swing, and a grenade, exploding barrel or strike throws it from the blast. It keeps the speed it was running at. Bodies tumble over stairs, slopes, terrain, props and walls, settle, and stay for 14 s (zombies 7 s) before fading out; prestige hats either stay on or get knocked off (always on a headshot or a blast) and land on their side. Later blasts fling the bodies again, and loose debris from broken props too. Ragdolls are purely cosmetic: dead bodies never block bullets or movement, and each PC builds them from the kill message it already gets, so everyone sees about the same fall with no extra network traffic. At most 24 bodies (10 of them zombies) are around at once and 16 move at a time; resting bodies cost nothing but their drawing, which is a single instanced draw shared with the prop debris. Turn them off with the environment variable `CALLOFSLOP_RAGDOLLS=0` (the old flat corpse comes back). If your killer dies, the death camera turns to where their body ends up.

**Explosions push the living too.** Frag grenades (11 m/s at the centre, out to 9 m), impact grenades (9 m/s, 6 m), exploding props (9 m/s by default, a prop's `explode` block can set `knockback`), the Mortar Barrage (10 m/s per shell) and the Strafe Run (7 m/s) all knock you away from the blast, the push falling off with distance to nothing at the edge of the blast and lifting you a little off the ground. Walls, floors and an enemy's Deployable Cover shield you exactly as they shield you from the damage. One push is capped at 12 m/s, Flak Jacket cuts it by 60%, going prone halves it, and a mantle isn't interrupted. The server moves you (it's authoritative, so it replicates like any movement), and tells your client exactly which input the push came after, so your own prediction shows the shove the moment it arrives and never snaps back. **Teammates are never pushed by each other's blasts:** the game has no friendly fire, and a shove you can't stop would only be griefing; your own grenade does push you (grenade jumps), and strikes only push the caller's enemies, like their damage. Survivors of a blast are what gets pushed: whoever it kills becomes a ragdoll thrown by it.

### Gibs and gore

**Animals burst.** Shoot, knife or blow up an animal prop enough and it bursts into a pile of meaty gibs: chunky red and pink meat, a few bone-white bits, and a puff of feathers (pigeons, chickens, ducks, the little bird on a perch), white wool tufts (sheep) or fur (cats, dogs, cows). Bigger animals take more and throw more: a pigeon goes in one rifle shot, a cat in two, a dog in two or three, a sheep in four, a cow in about nine (pigeons 20 hp and 10 gibs, a cat 45 and 12, a dog 60 and 14, a sheep 110 and 18, a cow 250 and 24). A grenade, launcher round, landmine, exploding barrel or strike within 60% of its radius gibs an animal at once. Flocks (Pigeons, the Duck Family) go as one. Toys never do: rubber ducks, the duck decoy, teddy bears and the bird bath are not meat. Animals give no kill, no XP and no kill feed line (only a line in the game log), and come back next match (or after the map's `respawn` time).

**Close blast kills burst too.** A player, bot or zombie killed by a blast right next to it (the killing hit did 80 damage or more, or 60 more than the health they had left: about the inner quarter of a frag grenade, the inner two fifths of a landmine, a rocket's direct hit) is blown apart instead of falling as a ragdoll: meat and bone plus their torso, head, arms, a hand, legs and boots in their own uniform colours, flung by the blast; a prestige hat flies off on its own and lands on its side. Napalm fire never gibs; a blast at the edge of its reach gives a normal ragdoll. The death camera follows the torso chunk.

Gibs bounce, slide to a stop, lie there for about 15 s and dither out; meat that lands leaves a small blood splat (it counts as a bullet impact, so the **Bullet impacts** setting has to be on). Later blasts throw them about again. Everything is built on every PC from the break or kill message it already gets (the same burst on every screen, no extra traffic), at most 320 pieces exist at once (the oldest go first), and they're drawn in the same instanced call as prop debris and ragdolls. **Settings > Video > Gore:** **Full** (everything), **Reduced** (about half the gibs, no blood), **Off** (animals just poof into feathers or dust; blast kills are ragdolls).

### Destructible buildings

On the **World Tour** maps (and the Dev pack's **Destruction Test**) buildings can be blown apart. Every wall is made of panels about 1 x 1.25 m (door and window openings kept), every floor and roof of 2 x 2 m slabs, and each panel has health by its material (`Materials/destruction.json`):

- **Explosives do the work.** Frag and impact grenades, launcher rockets, kill-streak strikes (mortars, strafe runs, napalm), exploding props (barrels, gas bottles, shell crates) and landmines break the panels in reach that the blast can see (a wall in front shields the one behind). A frag next to a plastered or wooden wall blows a hole in it; brick needs a rocket (or a few frags); concrete takes several rockets or a strike.
- **Bullets** only chip the weak stuff: wood and plaster give way after a magazine or so, tiles barely notice, brick, concrete and metal don't care. **Melee** knocks through wood and plaster in a few blows.
- **What's left has to stand on something.** Support runs up from the ground through the panels, and a little way sideways (each material has a reach: plaster about 2.5 m, brick 3.5 m, concrete 4.5 m). Take out the wall under a floor and the floor sags and drops in slabs; take out a storey and what's above comes down. The ground-floor corners of every building are load-bearing (they never break), so a building is never wiped off the map.
- **Falling slabs hurt.** A piece that comes down on you lands with its weight: a concrete floor slab from a storey up kills, a plaster panel stings. The kill goes to whoever brought it down.
- Holes are real: bullets, grenades and sight go through them, you can walk and mantle through, decals on broken panels vanish, doors and glass set in a broken wall go with it, and furniture on a fallen floor is gone. Bots find the new ways through holes (and stop walking on floors that fell).
- Everything is whole again at the start of every match. The host decides what breaks (online it's the same for everyone; a player joining mid-match sees the damage done so far). The host's **Destruction** checkbox (Host page) turns it off; Zombies never breaks buildings.

Map makers switch it on per map (`"destructible": true`, or per building) and can add `DestructibleBox` blocks: see [Maps/README.md](Maps/README.md#buildings) and [Buildings/README.md](Buildings/README.md#destruction).

### Sound

Every weapon has its own **gunshot, reload and equip sound**, synthesised when the game starts from the weapon's stats: calibre gives depth and thump, there's crack and echo, suppressed guns go *thwip*, and energy, pneumatic and toy guns get their own recipes. Real firearms then get **recorded gunshots** layered in (`Audio/Samples/Guns`, from The Free Firearm Sound Library, CC0): each class picks a set of recordings from 2-3 real firearms (light and heavy pistols, SMGs, rifles, heavy rifles and LMGs, DMRs, lever-actions, bolt-action snipers, the .50 and the musket, pump and heavy shotguns), pitched by the weapon's calibre, trimmed by its tail, blended with the start of its own synthesised shot (crack, thump, mechanism) and matched to the synth's loudness. Shots are **snappy**: the recordings are cut right on the blast (no pre-roll), the crack is sharpened, the body is dry and short, and the limiter is held back so the transient stays sharp (the distant layer keeps the long tail). **No two guns sound the same**: every weapon has its own sonic identity derived from its name and stats (same on every client): which recorded firearms it mostly plays, a pitch offset, tone, body resonance, crack, mechanism click, synth blend and dryness (see `Weapons/README.md`, "voice" block to pin any of it; the log's `[gunvoice]` lines list them); barrel and muzzle attachments colour it a little more. Each shot picks one of its 4 variants at random with a small pitch and gain jitter. Suppressors muffle the recording under the synthesised *thwip*, and the distant layer blends in a mid-distance recording. If the sample files are missing the synthesised sounds are used, and the log's `[gunsamples]` lines say which set every weapon uses. Reloads follow the weapon type (mag swap, shell-by-shell plus pump, bolt, belt box). There are also hit, headshot, kill, hurt, death and respawn cues. Other players' shots and reloads are positioned in **3D** with OpenAL, so you can hear where people are.

- **Hits.** A body hit gives the shooter a dull flesh *thwack* with a short tick; a **headshot** is a meaty crunch (a bone-crack transient, a wet low thump, a squelch and a gritty tail) under a bright hitmarker ping, and a headshot kill adds a bell-and-boom accent on top of the kill sound. Hitting a turret or drone pings metal. Hitting a **teammate** (team modes and Zombies co-op, where it does no damage) gives a muted low *bonk* with a soft falling double beep instead, quieter than an enemy hit. Everyone else hears flesh hits and headshot crunches **in the world**, quieter, where they happened. Every hit sound has three variations, picked at random.
- **Footsteps** for every player, local, remote and bots. They follow the leg animation's gait (the same cadence: about 7 steps a second at walking speed, 10 at a sprint, and locked onto the drawn legs' foot plants when they're on screen), so a step sounds as a foot lands. Sprinting is loud and heavy and carries about 45 m, walking is soft (24 m), crouch-walking is nearly silent (6 m) and prone crawling is a cloth-and-grit scuffle. Nothing in the air; a jump has a push-off, and a landing thuds harder the faster you fell. The surface comes from what's under the foot: the terrain's painted material (grass, dirt, sand, rock where it's drawn as cliff, and snow on pale ground), a box's texture (concrete, brick and tiles sound like concrete; wood; metal; earthy and grassy hills), a prop's parts (a wooden crate is wood, an oil drum is metal) and movers (metal). Each surface has 4 walk and 4 run variations, played with pitch and volume jitter. Other players' steps are positional (important information: you can hear someone sprinting round the corner); your own are quieter. Footsteps have their own **12 voices**, so 32 running players can't take the voices the gunfire needs: a new step takes a free voice, else the farthest one if it is nearer, else it is dropped.
- **The gun mix** (`Source/Audio/Audio.GunMix.cs`). **Your own gun is the loudest thing you hear**: it plays at full gain (OpenAL's per-source cap, so the baked peak never goes past it), and another player's shot plays about **7.5 dB quieter** up close. With distance another player's shot follows one inverse-distance curve (from 5 m, about 5 dB down per doubling, still falling at 250 m) and crossfades at equal power into a level-matched **distant layer** from 25 m to 90 m: a mid-heavy report (a softened crack, a band-limited blast, a small boom and a long rolling echo; the recording's tail is high-passed), so far gunfire never gets louder than nearer gunfire. Measured offline through the same mixing path (the self-test's **Gun mix** section, median of the 42 real firearms, K-weighted loudness against your own shot): another player's shot is -7.5 dB at 5 m, -16 dB at 15 m, -23 dB at 30 m, -30 dB at 60 m, -33 dB at 80 m, -35 dB at 100 m, its energy below 150 Hz falling from 10% to 1% while the part above 2 kHz (the crack you place it by) stays about 10%. (Before: an enemy within 6 m was 2.5 dB *louder* than your own gun, and from 60 m on the bassy distant layer, 70% of it below 150 Hz, came out as loud as your own shot.) Suppressed shots stay about 18 dB under open ones far away. Explosions are untouched (a frag 15 m away is about 19 dB over a rifle fired from there), and launchers keep their place over rifles.
- **Distance.** Bullets passing within 3 m of you **whizz**, or **crack** for rifles, DMRs, snipers and LMGs. Shots hitting the world make an **impact** by surface (concrete chips, a metal ping, a wood thunk, a dirt puff), sometimes with a **ricochet** off metal, concrete and rock. Breaking props have three variations each.
- **OpenAL EFX** (part of the OpenAL binding) is used when the device passes a start-up canary: positional sounds lose their air with distance (a high shelf), and gunshots also lose their boom (a band-pass filter's low shelf: about -5 dB below 250 Hz at 30 m, -13 dB at 60 m), and every sound gets a light reverb send that suits the map: open terrain, urban streets, or a stony room for maps that are mostly roofed over. Without EFX everything plays dry, as before. The log's `[audio]` lines give the number of sounds, synthesis time, EFX and HRTF status, and once a minute in a match the sounds played, footsteps dropped by the voice cap and CPU per sound.
- **Settings > Audio**: **Effects volume** (everything but music), **Own gun volume** (your own gunshots and their frenzy layers, on top of the effects volume; 1.00 is the tuned mix above) and **Footstep volume** (on top of the effects volume), all default 1.00, saved as `effects_volume`, `own_gun_volume` and `footstep_volume` in `settings.txt`; older settings files load with the defaults. Each slider has a Test button.

    | A kill every | L1 | L2 | L3 | L4 | L5 FRENZY | L6 MAX FRENZY |

    | 1 s | 2 | 2 | 3 | 4 | 6 | 8 |
    | 2 s | 2 | 2 | 3 | 4 | 6 | 9 |
    | 3 s | 2 | 2 | 3 | 4 | 6 | 10 |
    | 4 s | 2 | 2 | 3 | 5 | 7 | 13 |
    | 5 s | 2 | 3 | 4 | 5 | 8 | 23 |
    | 6 s | 2 | 3 | 4 | 7 | never | never |
    | 8 s | 2 | 3 | 6 | never | never | never |

    So a good streak (a kill every 4-6 s) reaches level 4-5, a great one (every 3 s) MAX FRENZY in about 10 kills, and a kill every 12 s or slower never starts it. After a burst to level 4, it holds about 11 s, then eases down (level 2 at about 16 s) and is gone after about 26 s; after a maxed-out spree level 6 holds about 9.5 s, level 5 until 15 s, level 4 until 22 s, and it's gone after about 36 s. (Before 2026-10-22 the higher levels needed a kill every 1-2 s: level 6 took 15 kills a second apart and was out of reach at a kill every 2.5 s or slower, level 5 at 4 s or slower.)
  - Changes land on the **bar line** and crossfade: up within half a bar, down one level at a time (at most every two bars, over two bars), levels 6 and 5 included. Drops loop, so it never falls into a breakdown. **Dying** fades it out over 2 s with the filter closing, and it never plays in the death cam, menus or lobby. Your own gunfire ducks it a little (levels 1-4), and up to level 4 it sits under the menu music's level so the game stays on top.
  - **Tempo at levels 5 and 6**: levels 1-4 play the track at its own BPM; level 5 speeds it up and level 6 more, by multipliers per weapon class (the `"tempo": { "level5", "level6" }` of each class's `"music"` section: Pistol and Assault Rifle x1.10 / x1.20, SMG x1.12 / x1.25, DMR and Sniper x1.08 / x1.16 (the marching drums and braams keep their weight), Shotgun x1.10 / x1.22, LMG x1.08 / x1.18, Special x1.12 / x1.24). Tracks over 160 BPM get a smaller share of the boost (tapering to 40% of it from 208 BPM), so for example a 156 BPM track plays 156 / 171.6 / 187.2 BPM at levels 4 / 5 / 6 in the classic style, 168.5 / 181 for Sniper, and the 215 BPM monster 223.6 / 232.2. It's a real tempo change (the beat clock; the pitch stays), with the kick, the off-beat bass, the screech wah, the sirens and the dotted-8th echo following the beat. Going up lands on the bar line at once; going down (and a class switch to another tempo) glides over one bar, from bar line to bar line. The self-test section **Frenzy tempo** checks, for every class and every track it can pick, that the BPM climbs from level 4 to 5 to 6, and live per class that the bars really get shorter, every tempo change starts on a bar line, no 16th is ever skipped or mistimed, no beat jumps in loudness, the glides back down and no allocations (the level-6 loudness and CPU checks run at the faster tempos).
  - **Zombies** too: zombie kills are worth 0.4 of a player kill and the hold is 5 s (being downed counts as dying); the same six levels apply, so a horde gets there but not instantly: a zombie kill every second reaches MAX FRENZY on about the 22nd kill, every 2 s on about the 40th.
  - The music follows the local player's own meter. The server also runs the same heat model (Source/Game/Frenzy/FrenzyMeterCore.cs) for every player and bot from its kill events and sends each player's level and frenzy class to everyone (2 bytes in the snapshot, protocol 26), for frenzy effects and buffs. One hardbass track from the pool per frenzy, rendered by the same engine with stem gains (drums, bass, melodic parts): about the cost of one hardbass track at levels 3-6 (5 and 6 change gains and the tempo, plus the roar for two seconds) and less at levels 1-2 (the leads aren't rendered).
  - **Frenzy per weapon class**: your frenzy takes the character of the class of the weapon that got your most recent kill (Pistol, SMG, Assault Rifle, DMR, Sniper, Shotgun, LMG, Special, Launcher; a launcher's frenzy throws a lime spark shockwave off every blast and layers a rocket hiss and sub detonation on your shots). Kills without a gun (grenades and other throwables, kill streaks, melee) still add heat but keep the previous class. The per-class data lives in `Weapons/Frenzy/classes.json` (format `call-of-slop-frenzy-classes/1`): one entry per class with "music", "visual", "sound" and "buffs" sections.
  - **A music character per weapon class**: the frenzy music takes on the style of your frenzy class (the rule above; the server's replicated class, predicted locally on your own kill so it never lags). Each class has its own track pool, stem gains, effects on the track and instrument layers that come in level by level, defined in the `"music"` sections of `Weapons/Frenzy/classes.json` (synth code in `Source/Audio/FrenzyStyleRig.cs`):
    - **Pistol - Western outlaw**: a whistled melody, a galloping twangy bass and a whip crack, the whole track in a canyon slap-back echo.
    - **SMG - Chiptune breakcore**: square-wave arpeggios racing over chopped breakbeats, the track a little crunchy (fast tracks).
    - **Assault Rifle - Classic hardbass**: the track as it is (the frenzy before classes).
    - **DMR - Marching drums and brass**: a marching snare with rolls, a bass drum on the downbeats, brass stabs.
    - **Sniper - Cinematic braam**: the four-on-the-floor pulled back under a half-time sub boom and a huge reverb snare, a giant brass braam every two bars (slower tracks).
    - **Shotgun - Gabber stomp**: a distorted gabber kick tuned to the key, double hits at the end of the phrase, everything driven (harder tracks).
    - **LMG - Industrial grind**: palm-muted power-chord chugs, anvil clanks on the off-beats, a double kick at the top levels.
    - **Special - Glitch weird**: the track bit-crushed with beat-repeat stutters and random square blips (the weird track with steady drops).
    - **Launcher - Artillery barrage**: syncopated sub booms landing like shells, a falling whistle before each phrase, a bass drum and, at the top, a braam, the track in a long blast echo (harder tracks).

    A class change mid-frenzy waits for the next bar line and crossfades the two styles over one bar (the track keeps playing). Each class's level 6 stays in the same loudness window against the gunfire, and each class costs at most 1.5x the heaviest hardbass track. The self-test section **Frenzy classes** checks the data, determinism, a rhythm-and-spectrum fingerprint that differs between every pair of classes, the levels building up per class, level 6 per class, the bar-synced crossfade, CPU per class and allocations.

  - **Frenzy buffs** (host setting on the host page, On by default, saved as `frenzy_buffs`; it applies to solo games too): from frenzy level 3, guns of your frenzy class get a small buff that grows up to level 6. It only applies to that class's guns, and it works for bots and in Zombies too:

    | Class | Buff | Level 3 | Level 4 | Level 5 | Level 6 |
    |---|---|---|---|---|---|
    | Pistol | Quick draw: draw/swap time | x0.90 | x0.83 | x0.77 | x0.70 |
    | SMG | Run and gun: spread from moving (firing out of a sprint) | x0.85 | x0.77 | x0.68 | x0.60 |
    | Assault Rifle | Steady hands: recoil kick | x0.94 | x0.91 | x0.88 | x0.85 |
    | DMR | Snap aim: aim-down-sights time | x0.92 | x0.88 | x0.84 | x0.80 |
    | Sniper | Held breath: spread while aimed | x0.85 | x0.78 | x0.72 | x0.65 |
    | Shotgun | Choke: pellet spread | x0.94 | x0.91 | x0.88 | x0.85 |
    | LMG | Belt fed: reload time / move-speed penalty | x0.94 / x0.85 | x0.91 / x0.77 | x0.88 / x0.68 | x0.85 / x0.60 |
    | Special | Vampire rounds: health back per kill | +10 HP | +15 HP | +20 HP | +25 HP |
    | Launcher | Hot loader: reload time | x0.90 | x0.83 | x0.77 | x0.70 |

    The server decides the frenzy, and clients predict the buffs from the replicated level. Move speed and minimum spread are checked on the server with a 1.5 s grace after a frenzy ends, so prediction never gets rubber-banded. The game has no sprint-to-fire delay or scope sway, so the SMG buff cuts the moving-spread penalty and the Sniper buff tightens the aimed cone. The self-test section **Frenzy buffs** checks that the server and client meters agree, the snapshot round trip, the class rule, every buff per level, the setting off, bots, the server grace and determinism.
  - **Settings > Audio > Kill frenzy music** (On by default) and **Frenzy volume** (0.80, on top of the music volume), saved as `frenzy_music` and `frenzy_volume`; older settings files load with the defaults. The self-test section **Frenzy music** checks the heat model (the kill patterns reaching each level, the kills-needed table above and the pacing targets: SelfTestFrenzyPacing.cs), bar-synced changes, the easing down, death and the setting off, the volume per level (level 6 against the measured gunfire-and-explosion reference), the ducking per level, the limiter at the loudest sliders, the sliders still multiplying, determinism, allocations and CPU (at most 1.5x the heaviest hardbass track; level 6 no dearer than level 4).
- **Frenzy visuals** (per weapon class): while you're in kill frenzy (the same levels 1-6), your shots take on the look of the class of the weapon that got your most recent kill, subtle at levels 1-2 and strong at 5-6:
  - **Pistol**: gold tracers and muzzle sparks, a quick-draw glint that sweeps along the gun when you draw it or get a kill. **SMG**: neon cyan tracers, speed lines streaking in from the screen edges while you move fast. **Assault Rifle**: hot orange tracers, heat shimmer rising off the barrel as you keep firing. **Marksman (DMR)**: crisp white tracers, a ring of sparks bursting out where each shot lands. **Sniper**: long glowing tracer trails (up to 1.4 s), and each kill sends one slow vignette pulse. **Shotgun**: fiery pellets, embers drifting down where they land and up from the bottom of the screen. **LMG**: heavy spark showers from the ejected brass, a barrel that glows red-hot with sustained fire. **Special**: rainbow tracers with a split glitch ghost, and a slow chromatic flicker at the screen edges.
  - On your screen: your gun glows in the class colour (fading out as you aim down the sights), a tint in the class colour at the screen edges pulses with the frenzy music (never more than 0.25 alpha, only in the outer 16% of the screen, so it never covers where you aim), and a **FRENZY meter** (class icon, six segments, "SMG FRENZY 3" / "MAX SMG FRENZY") sits just above the kill streak HUD.
  - Other players in frenzy (bots too) show it to everyone: their tracers take their class colour and sparks, their gun glows, and from level 5 a slow ring of light circles at their feet, so you can see who's on a spree. Their level and class come from the server.
  - Nothing flashes faster than 3 Hz (the edge pulse is at most 2.1 Hz, the glitch flicker 2.5 Hz with soft ramps; the kill pulse is one slow swell).
  - **Settings > Video > Frenzy visuals**: **Full** (default), **Subtle** (the colours and gun glow with about a third of the sparks, a fainter edge tint and no screen effects) or **Off** (none of it, meter included); saved as `frenzy_visuals`, older settings files load as Full.
  - Cost: all sparks, trails and gun glows are streaks drawn in one instanced draw call for the world and one for your gun (a fixed pool of 2048, no per-frame allocation), the screen effects are a handful of ImGui gradients. The game log has a `[frenzyfx]` line every 5 s while any is drawn (streaks, draw calls, CPU and GPU ms). The self-test section **Frenzy visuals** checks that every class has its own look, the level scaling and setting, no strobing above 3 Hz, the edge tint limits, the `visual` overrides (and that the shipped file matches the built-in looks), other players' replicated level and class, no allocations, and the CPU cost of 16 players at level 6 firing LMGs (budget 0.1 ms per frame). The looks are built in, written out in the `"visual"` section of each class in `Weapons/Frenzy/classes.json`, and can be tuned there (colour, accent, tracerWidth, sheath, trailLife, muzzleSparks, impactSparks, brassSparks, sparkSpeed, sparkGravity, sparkLife, barrelGlow, edgeAlpha, rainbow, label).
- **Frenzy gun sound** (per weapon class): while you're in kill frenzy, your own gun takes on the sound of your frenzy class (the class of your most recent kill), growing with the level: a class layer under every shot (Pistol: ricochet whine, twangy bass and spur ring; SMG: buzzy square-wave bursts and chiptune blips; Assault Rifle: a distorted hardbass kick, off-beat hat and donk; DMR: a marching snare and rim shot, flammed at the top; Sniper: a whip crack and a cinematic braam; Shotgun: a gabber kick, doubled then tripled; LMG: an industrial clang, grind and belt rasp; Special: bit-crushed stutters), with more sub thump, mechanical clacks, saturation and echo at each tier (levels 1-2, 3-4, 5-6), a driven copy of your shot (saturated, low end boosted) crossfaded in, a small pitch shift (snappier or heavier by class) and, at levels 5-6, the layer spread left and right.
  - Only your own gun changes; other players' guns keep their normal sound so you can still tell them apart by ear. Your normal shot is unchanged, so the MAX FRENZY loudness reference above still holds; a level-6 shot is at most about 1.4x (+3 dB) as loud as a normal one.
  - **Settings > Audio > Frenzy gun sound**: **Full** (default), **Subtle** (the class layer at half strength and half the pitch shift; your shot stays clean and centred) or **Off**; saved as `frenzy_gunsound`, older settings files load as Full.
  - Cost: everything is baked at start-up (8 classes x 3 tiers x 2 variants plus one driven copy per weapon, about 4 MB, a few tens of ms; the game log has a `[frenzygun]` line); a shot only picks buffers and gains (no allocation) and plays them on 10 voices of their own, so they never steal gunfire voices. The tuning lives in the `"sound"` section of each class in `Weapons/Frenzy/classes.json` (signature, levels: the intensity at levels 1-6, never going down; layer, drive, sub, clack, tail, width, pitch). The self-test section **Frenzy gun sound** checks every class has a sound entry with its own signature, every level is at least as intense as the one before, the loudness of a level-6 shot for every weapon and class, the bakes, the per-shot cost, the parser fallbacks and the setting.
- The music is rendered on its own background thread into a small queue of OpenAL streaming buffers (about 0.2 s), without allocating; it costs about 1% of one CPU core (the self-test measures it).

### Zombies (in development)

A World at War style **Zombies** mode (co-op for 1-4, new maps) is being built. Milestone 1, the **modular weapon builder**, is playable now as a sandbox: main menu > **WORKBENCH (ZOMBIES PREVIEW)**.

- A weapon is a tree of **parts** (123 so far, in `Parts/`): the **grip** is the root and holds one or more **receivers** (a pistol grip 3, a rifle grip 9, up to 16 on the late-game frames and the push cart), and each receiver has its own barrels, **splitters**, feed, ammo, a **damage multiplier** slot and two **receiver upgrade** slots (behind and beside it). Stocks, optics, foregrips, a **shared feed** (one hopper feeding several receivers) and utility parts go on the grip.
- The **grip fixes the fire style**: volley grips fire every receiver at once, rotate grips take turns. **Splitters never change the total damage** (rarer ones are more accurate or have more outputs); damage comes from multipliers and upgrades. **Weight** is the limit: rarer frames and weight-relief parts (slings, harnesses, an anti-grav coil, helium balloons) carry more, so huge guns come late in a run.
- The **push cart** is a real cart: you push it along the ground with both hands on the bar (it can't climb steps or steep slopes, and it stops at walls), and it doesn't fire while you push it. **F parks it**; **tap F** at its bar to **man its gun** (you stand at the bar, the mouse turns the gun up to 60 degrees either side, 15 down and 30 up, and the fire key fires the cart's build); **F** (or jump / sprint) steps off back to your other weapon, and **holding F** at the cart pushes it again. (An auto-firing turret may come later as a separate deployable.)
- The **melee slot**: build a melee weapon from a hilt, a head and mods (machete, nail bat, sledgehammer, fire axe, chainsaw sword, a frying pan, a frozen fish...) with its own damage, swing speed, reach, cleave and stun. It replaces the knife only in the workbench range (and Zombies later); normal matches keep the standard melee.
- The workbench shows every part (all unlocked in the sandbox), a live 3D preview, the receiver slots, stat changes before you fit a part, and a plain reason when something doesn't fit. Four build slots and the melee slot are saved in `workbench.txt`; the **standard builds** (`Parts/Builds/`, what the mystery box and wall weapons will give) load as presets. Sandbox toggles: weapon slots 3-4 (in Zombies an upgrade bought on the map, per run; the range also has its station) and practice dummies. **Test fire** opens the **Workbench Range**.
- New keys: **F** interact (cart, slot station) and **3** for weapon slot 3 (slot 4 is unbound by default); the swap key and mouse wheel cycle through every slot you have.
- Every barrel fires from its own muzzle, minigun receivers spin up, and one trigger pull counts as one hit per target (a Last Stand shield loses one charge, however many barrels hit). The standard weapons are unchanged.
- The design (component model, rules, stat pipeline, the user's decisions, rarity tiers, run progression and drop tables, the cart, the melee slot, example builds and the open questions) is in [docs/zombies/WEAPON-BUILDER.md](docs/zombies/WEAPON-BUILDER.md).

**The Zombies mode (milestone 2)** is playable on the dev map **Zombies Test**: pick that map, then the game mode **Zombies** (single player with bots, or host for up to 4).

- **Rounds**: a handful of slow zombies in round 1, more and tougher every round (health +100 a round to round 9, then +10 percent), runners from round 3 and sprinters from round 5; at most 24 alive at once. A 10 s break between rounds. The round is the red tally bottom-left.
- **Zombies** come through **boarded windows**: they tear the boards off, climb in and chase the nearest player standing, through open doors. **Hold F** at a window to put boards back (10 points each).
- **Points** (personal): 10 a hit, 60 a kill, 100 a headshot kill, 130 a melee kill. Spend them on **doors and debris** (unlock the next area and its spawners), **wall guns** (chalk outlines; ammo if you already have it), the **mystery box** (a complete build; the teddy bear moves it), **perk machines** (Juggernog, Speed Cola, Double Tap, Quick Revive, Second Wind), the **weapon-slot upgrade** (2 -> 4 slots) and the **power switch** (some buyables need it). Hold F to buy; the prompt shows the price.
- It's a **roguelite run**: you start with the Wall Rifle, the Wall Pistol and a Machete; zombies drop **parts**, salvage piles give **scrap**, and a **workbench** (F) lets you rebuild your guns with the parts you own this run, break parts down and craft new ones.
- **Downed** at 0 health: a teammate revives you by holding F on you; you lose your perks; after 30 s you bleed out and come back next round with the start gear, and your **built weapons drop where you went down**: anyone can pick them up (hold F) for 5 minutes. **Second Wind** (start room) gets you back up on your own once, solo or co-op. Guns have **reserve ammo** in Zombies (magazine | reserve).
- Co-op: built guns and dropped builds replicate to every player (protocol 19). The design, every number and the map format are in [docs/zombies/ZOMBIES-MODE.md](docs/zombies/ZOMBIES-MODE.md).

## Where your saves live

Your own files (`progress.txt` with level, XP, weapon XP and prestige; `loadout.txt` with loadouts and hat; `settings.txt`; `workbench.txt`; audio mixes `audio_mix.json` and `AudioMixes/`) are kept in a **save folder outside the game**, so they **carry over to every new build automatically**:

- **Windows:** `%APPDATA%\CallOfSlop\` (paste that into Explorer's address bar), **Linux:** `~/.local/share/CallOfSlop/`.
- **Settings > Player > Saves** shows the folder and has an **Open save folder** button.
- **Portable mode:** put an empty `portable.txt` next to `CallOfSlop.exe` and the saves stay next to the game (USB sticks, dev copies). **`--save-dir <path>`** on the command line uses any folder (it wins over both).
- **Moving from an older build:** older builds kept the saves next to the game. On startup, any save the save folder doesn't have yet is **copied** from next to the game (`[saves] migrated progress.txt from <folder>` in `callofslop.log`); on the very first run of a freshly unzipped build it also looks for your most recent other Call of Slop build beside it (sibling folders, e.g. the previous tester zip) and copies from there. The originals are never moved or deleted. If both have a file, the save folder's copy wins and the other one is left alone (logged).
- **Safe saving:** every save is written to a temp file and swapped in, so a crash can't leave half a file, and the previous save is kept as `NAME.bak` (e.g. `progress.txt.bak`). A damaged save loads its backup (the damaged copy is kept as `NAME.corrupt`). Each file starts with a `version=1` line; files without one (older builds) load exactly as before, and a save written by a *newer* build than the one you're running is never saved over (the lobby and Settings > Player say so).
- Game data (maps, weapons, props, `classes.json`, `hats.json`, ...) stays next to the game, as does `callofslop.log`. The smoke test (`--smoketest`) plays with a throwaway copy of your saves in the temp folder, and the self-test uses its own temp folder, so neither can change your progress.

## Development and version control

The repository holds only the source: `Source/`, `Maps/`, `Weapons/`, `Attachments/`, `tools/`, the project file and the docs. Build output (`bin/`, `obj/`) is ignored. Your personal game files live in the save folder (see [Where your saves live](#where-your-saves-live)), not in the repo; if you run in portable mode from the project folder, `.gitignore` keeps them (and their `.bak` copies) out of commits.

- **Get started:** clone the repo, then run `Start.bat` (or `dotnet build -c Release`). NuGet fetches the BRUTAL packages on the first build.
- **Automatic checks:** with `.github/workflows/build.yml` in the repo, every push runs **Build and self-test** on GitHub Actions. It builds on Windows, runs `CallOfSlop.exe --selftest` and attaches the logs to the run. A red X on a commit means it didn't build or a check failed; open the run to see which.
- **Line endings:** `.gitattributes` keeps text files LF in the repo and batch files CRLF, so diffs stay clean whichever editor or OS touched a file.

## How it works

**Netcode: prediction, interpolation and lag compensation**

Both sides run the same fixed **60 Hz** simulation (`World.Simulate`), independent of frame rate. Rendering blends between ticks, so motion is smooth at any FPS.

| Problem | What the game does |
| --- | --- |
| Your own movement lagging behind your keys | **Client-side prediction.** Your input is simulated on your PC immediately, every tick. |
| Server disagreeing with your prediction | **Reconciliation.** Each snapshot tells you the last input the server ran. Your client resets to the server's state, replays the inputs the server hasn't seen yet, and fades any leftover error out over about 100 ms instead of snapping. |
| Other players jittering or teleporting | **Entity interpolation.** Remote players are drawn a little in the past (about 70 to 300 ms, adapting to measured network jitter), smoothly between buffered snapshots. If packets drop, they're briefly extrapolated along their last velocity. |
| Having to lead targets by your ping | **Lag compensation.** The server keeps 2 s of position history per player and rewinds targets to the exact tick you were seeing when you fired (up to 400 ms back). If it looked like a hit, it is a hit. |
| Clients stuttering on the host's screen | **Server jitter buffer.** The server holds about 2 ticks of each client's input and consumes one per tick. If a packet is late, it assumes you're still holding the same keys, and the late packet is dropped when it arrives. |
| Packet loss | Every input packet repeats your last 4 commands, so a lost packet costs nothing. |
| 32 players in one packet | **Compact snapshots.** Positions are sent to 1/256 m and angles to 0.1 mrad (24 bytes a player); your own state comes exact, so prediction never chases rounding. Scores, loadouts and perks go out only when they change (repeated for half a second) plus a slow refresh. Players more than 40 m away, and the dead, update at 15 Hz instead of 30 (deaths and respawns still go out at once). A snapshot that still doesn't fit 1200 bytes is split into self-contained parts. |
| Standing on a moving platform | **Stamped mover clock.** A platform's pose is a pure function of the server tick. Each input you send carries the tick the server will run it at (your client steers this from the snapshots), and the server runs it at exactly that tick, so prediction, replays and the server all see the platform in the same place. Other players on platforms are drawn riding them, and shots at them are rewound with the platform too. |

Movement is now server-authoritative, so clients can't teleport. Shots are still resolved only on the server.
Hit markers appear instantly from your own prediction, and the server confirms them. Hitting a teammate (bullets, melee or a grenade; never in Free-for-all) shows a cyan "no entry" sign with FRIENDLY under the crosshair instead of the red/yellow marker, since teammates take no damage.

**Testing bad connections on one PC:** add `--lag=150` (extra milliseconds on everything that side sends, plus some jitter) and/or `--loss=5` (percent of packets dropped):

```sh
Start.bat --lag=150 --loss=3
```

On clients, the window title shows ping, the current interpolation delay, and the size of the last prediction correction ("fix ... cm").

**Physics**

All collision goes through one module, `Source/Physics`:
- `PhysicsWorld` is the current map's collision world (`World.Physics`): one BVH (`Bvh.cs`, surface-area-heuristic build) over every static collider (map boxes, prop collider boxes, oriented boxes, triangle meshes via `IMeshCollider`, e.g. `TriangleMeshCollider.FromMesh` from the mesh pipeline), plus the terrain heightfield and the movers posed at a tick. Broken props switch their boxes off.
- `IWorldQuery` (`World.Query`) is the one query interface: `Raycast` (distance, or the closest hit with point, normal and shape), `SphereCast`, `CapsuleCast`, `OverlapBox`, `OverlapCapsule`, `OverlapBody` (the classic player box), `PointInside`, all with a `QueryFilter` (layers: boxes, props, terrain, movers, mover sweeps, oriented boxes, meshes; the mover tick; shapes to ignore). Bullets, lag-compensated shots, line of sight, grenades, explosions, bots and their nav graph, mantling, kill streaks, props and movers all use it.
- **Movement** goes through `World.Mover` (`IMover`). `ClassicMover` is the original movement, unchanged on maps without terrain (the self-test proves bit-identical results); on terrain both movers follow `SlopeRules` (protocol 14: the footprint's slope, 45 degree limit, slower uphill, grip and terrain steps, capped steerable slides; see [Slopes](#slopes)). `SweptMover` is a capsule character controller: sweep and slide (it can't tunnel, even at sprint speed into a 5 cm wall), step-up (0.55 m steps climb, 0.70 m block), ground snap down stairs and slopes, 42 degree slope limit on boxes and meshes (steeper ground slides you down; terrain uses `SlopeRules`), crouch and prone capsules, mantling, riding and being pushed by movers. It reads "up" and gravity from `PhysicsWorld.Gravity`, so a later gravity system can change them per zone.
- The host picks the movement with `physics=classic` (default) or `physics=swept` in `settings.txt`; it travels in the Welcome and the server info (protocol 13), and clients predict with the host's choice.
- Cost: a ray cast is about 0.5 us on the biggest map (the old box scan took about 3 us), 32 players' movement takes 15-30 us per tick classic and 15-200 us swept (the high end on terrain maps).

**Arms and gun animation**

Your gun is held by box arms (sleeves in your player colour, tan gloves). Everything is procedural, with no animation files:
- `Render/ArmAnchors.cs` knows where the hands go on each gun model (grip, handguard or pump, magazine well, bolt or slide, muzzle), including foregrips, lasers and magazine attachments, and picks the reload style: box magazine, pistol mag drop, revolver speedloader, shell-by-shell tube, break-open, bolt action, LMG box or muzzle loader.
- `Render/ViewModelAnimator.cs` moves the gun (hip and ADS, breathing sway, walk bob, sprint, jump and landing dip, equip, a rifle-butt or pistol-whip melee, the reload of each style timed to the weapon's reload time, the ledge plant while mantling, recoil kick) and works out where both hands are.
- `UI/WorldLabels.cs` (`Hud.Project`, `Hud.WorldLabel`) puts HUD text at 3D positions: the frame's real view and projection, drawn on ImGui's background list (over the world, under the HUD). The name tags (`UI/NameTags.cs`, drawn by `UI/UiNameTags.cs`) and the Zombies dropped-build labels use it.
- `Render/HeadBob.cs` is the camera head bob (see **Head bob** under Display). With it on, the gun's own walk bob follows the camera's footfalls and is smaller, so the two don't fight or double up.
- `Render/Arms.cs` solves each arm with two-bone IK (shoulder, elbow pole, wrist) as a small hierarchy: shoulder, upper arm, forearm, hand.
- `Render/ThirdPersonArms.cs` gives other players the same arms, with simple reload, sprint and melee poses from the game's reload and melee events.

The shoulders are fixed to the camera, not the screen edges, so on wide and ultrawide screens the arms come in from the bottom and aren't stretched. When you aim through a magnified optic, the off hand moves back onto the magazine so it stays out of the lens.

**Legs and locomotion**

Players have box legs (trousers in a darker shade of their colour, knee pads, boots) as scene graph nodes: pelvis -> thigh -> shin -> foot per side, posed every frame by `Render/LegAnimator.cs`. The legs are presentation only: hit boxes, collision and movement are unchanged (the torso box was shortened so torso and legs fill the old body's space).
- **Gait** from the player's drawn velocity relative to where they face (forward, backwards, strafing, diagonals), with one continuous phase: cadence rises with speed (3.7 gait cycles, i.e. 7.4 steps, per second at the 6 m/s walking speed and 5 cycles at the 13.5 m/s sprint) and the stride follows, so planted feet don't slide. The **walk** (at or below 6 m/s) has short steps, feet planted 58% of the cycle, an 11 cm foot lift, a small hip bob (high at mid-stance) and a slight lean; the **run** (sprint speed) has a 2.7 m stride, feet down only 32% of the cycle with a flight phase, a 32 cm foot lift with an early heel kick, hips 8 cm lower, more bounce (low at mid-stance) and a 0.2 rad forward lean. Between the two every parameter blends by speed (smoothstep from 6 to 13.5 m/s), so there is no pop. Steps are shorter and quicker sideways and on slopes. Planted feet lock to the spot they touched down on.
- **Crouch-walk** (lower hips, one foot back, short low steps), **prone crawl** (legs straight back, one knee drawn up and out at a time), **idle** (feet stay put; turning in place or drifting makes them shuffle back under the hips, one foot at a time), **jump** (legs tucked), **falling** (legs down, one forward), **landing** (hips dip by how hard you landed), **mantling** (lead leg up on the ledge).
- **Foot IK on the ground:** each foot casts one short ray down through `World.Query` (map boxes, props, oriented boxes, meshes, terrain and moving platforms at the drawn mover tick) for players within 40 m of the camera; farther players use the flat gait. Feet stand on stairs, slopes, terrain and platforms, tilt a little to the slope, the pelvis sinks (up to 60 cm, the upper body follows at most 25 cm so the head stays near the hit box) to keep both feet in reach, and a foot still out of reach is held up rather than stretched. Each leg is solved with the same two-bone IK as the arms (`Arms.SolveTwoBone`, knee pole forward).
- Remote players animate from their interpolated snapshot velocity (plus on-ground and mantling flags carried in the snapshots they already get), bots from their simulated velocity; the velocity is smoothed and the phase integrated, so 15/30 Hz snapshots don't make the gait jitter.
- **First person:** you see your own legs when you look down (drawn 10 cm behind your feet, without the pelvis, torso, gun or arms; nothing comes near the camera). Set the environment variable `CALLOFSLOP_FPLEGS=0` to hide them.
- Cost: about 2 us per player per frame on the CI runner including the two rays, no allocations. The self-test's **Legs** section checks the IK, that the idle legs fit the hit box, foot planting at walk, jog, run, backwards, strafe, diagonal, ADS and crouch speeds, a walk-to-sprint-and-back sweep at 240 Hz for pops (foot, hips, cadence), idle turning, jump, fall, landing and mantle poses, planted feet against an independent ground ray on a staircase (classic and swept movement, walking and sprinting) and 30 and 40 degree ramps, that hit and collision volumes are unchanged, zero allocations and the cost. The smoke test's legs step films a stand-in player walking up the Physics Test stairs and sprinting (`smoke_legs_walk.bmp`, `smoke_legs_run.bmp`, `smoke_legs_firstperson.bmp`, `[smoke] legs` lines with speed, gait, feet and cost).

**Scene graph (object hierarchy)**

Things built from parts are held as a tree of parented nodes (`Source/Scene`, see [Source/Scene/README.md](Source/Scene/README.md)): each node has a local position, rotation and scale, a cached world matrix that is only recomputed when it or a parent moved, optional named attachment points (sockets such as `muzzle`, `grip`, `optic_mount`, `hand_l`, `seat_0`) and something to draw (a box today, or a mesh from the mesh pipeline, drawn instanced). The first-person view is camera -> gun -> body, magazine, optic, muzzle device and underbarrel parts (the magazine node moves during a reload) and camera -> shoulder -> upper arm -> forearm -> hand for each arm; other players are body -> head and visor, legs (pelvis -> thigh -> shin -> foot), gun in hand and both arms; moving platforms are a frame with their boxes and a riders node; turrets are base -> head -> barrels with a muzzle socket and drones are body -> rotors and gun pod. glTF models load straight into node trees. The draws are the same as before, in the same order (the self-test compares every matrix with the old drawing code). Setting the environment variable `CALLOFSLOP_SCENEGRAPH=0` falls back to the old immediate drawing; the smoke test logs a `[smoke] scene graph:` line with nodes, draws and CPU time per frame.

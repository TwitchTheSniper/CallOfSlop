# Call of Slop: player manual

Archived modes' manual: archive/MANUAL-ARENA.md.

Moved out of the [README](../README.md) on 2026-11-11. **Only [Sandbox and constructs](#sandbox-and-constructs-in-development), Controls, Display, Sound, Weather, the dev windows, Updates and Saves describe the game being built now.** Matches, loadouts, perks, kill streaks, bots, Zombies and Co-op are the archived arena modes: history, not a guide for new work.

## Play

Double-click **`Start.bat`**. It builds the game if anything changed (the first build downloads the BRUTAL packages), then shows the BRUTAL logo for a few seconds (the BRUTAL licence asks for it before gameplay; click or press a key to skip it) and opens the **lobby**:

| Lobby option | What it does |
| --- | --- |
| **Single player** | You against up to 31 bots (as many as the map takes, see [Lobby size](#lobby-size); Easy, Normal, Hard or Insane), or **No bots (test mode)** with the slider at 0. Fully offline, nothing touches the network. The game pauses while the Esc menu is open. |
| **Multiplayer: Host** | Starts a match others can join. It opens the port on your router automatically with **UPnP** (can be turned off), and you can fill empty slots with bots. Real players replace bots as they join. The address friends should use appears at the top-left of your screen. |
| **Multiplayer: Join** | Paste the host's **invite code** (or type their address) and join. Esc cancels while connecting. See [Playing with friends](#playing-with-friends). |
| **Settings** | Five tabs. **Player:** name, sensitivity, invert Y, FOV, network stats. **Multiplayer:** server lists, run a server list, public address lookup, invite links ([Playing with friends](#playing-with-friends)). **Controls:** up to three bindings per action (primary, second, third), each any key or mouse button; any of them works the action. **Video:** windowed / borderless fullscreen / fullscreen, resolution, text size (Auto or 75-200%), HUD width, name tags, head bob, frenzy visuals, gore, VSync, Max FPS (Unlimited, 30-360 or a custom 20-1000; used with VSync off) plus optional lower caps for menus and for when the window is in the background (these apply with VSync on too; the lowest wins; the F9 window shows the cap as a blue line and the limiter's wait as its own area). **Audio:** master, music, effects, own gun and footstep volume, music style, kill frenzy music, frenzy gun sound. Changes apply immediately and are saved to `settings.txt` (in the [save folder](#where-your-saves-live)); the same screen is in the Esc menu during a match. |

In a match, **Esc** opens the menu (Resume, Change loadout, **Kill yourself**, Settings, Back to lobby, Leave game, Quit). The two ways out are kept apart: **BACK TO LOBBY** (the host, in a hosted game) ends the match and takes everyone to the lobby room, still connected, with their names, team picks, loadouts, the bots and the lobby settings kept, so the host can change the map, mode or bots and start again (in Zombies the run is cleared). The host's other way out is the red **CLOSE SERVER (main menu)** (the lobby room's top-right button too): it disconnects everyone and closes the router port, so while anyone else is connected it asks first. Clients are told why ("The host closed the server..."), and a connection that drops on its own says it timed out, on both sides. As a client, **LEAVE GAME (main menu)**: only you leave and the match goes on for the others. Single player has **LEAVE MATCH (main menu)**. After a Zombies run, BACK TO LOBBY and another mode give everyone their own multiplayer guns back. Two different builds can't play together: the joiner is refused at once with both version numbers (update the older one).

- **Kill yourself (respawn)** closes the menu and kills you through the normal server path, then the usual death flow follows (death cam, then the loadout screen; in Gun Game you respawn on your own). It counts as a **suicide**: a death for you, no kill for anyone, your kill streak resets, and it never scores for a team or changes your Gun Game weapon. It's greyed out while you're dead or the match isn't live (warmup, countdown, results), and the server accepts it at most once a second. Online, clients ask the server, which decides.
- **No bots (test mode):** set the bot slider to 0 in Single player (or *Fill with bots* to 0 when hosting) to try weapons, attachments, perks and mode objectives on your own. Deploy (or Ready) starts the match straight away. While you're the only one in the match **the match clock stops and nobody can win**: team scores (hill points, flag captures) still count but stop one short of the limit, so the match never ends on its own. In team modes you're simply on a team by yourself. As soon as another person joins a hosted game, the normal rules apply again. The bot count is saved in `settings.txt` as before.

To test on one PC: run `Start.bat` twice. Host in one window and join `127.0.0.1` in the other.

- The first time you host, Windows Firewall asks whether to allow Call of Slop. Click **Allow**.
- If the host's address says "LAN only - UPnP unavailable", turn on UPnP in your router's settings or forward UDP 60000. Same-network play works either way.
- "Behind a second NAT" means a second router or your ISP's carrier-grade NAT. Use a LAN or a virtual LAN tool like Tailscale or ZeroTier.
- The game has no console window; its log is written to `callofslop.log` next to the exe.
- Text boxes take plain text only: pasting an image or a file does nothing (the log says `[ui] paste ignored: the clipboard has no text`), and pasted text is cut to printable ASCII. Names, server names and other text from other players are cleaned the same way, and a broken or hostile network packet is dropped with a `[net] dropped a bad ... packet` log line instead of closing the game.

Command-line shortcuts (skip the lobby): `CallOfSlop.exe host [port]`, `CallOfSlop.exe join <ip> [port]`, plus `--no-upnp`, `--lag=ms`, `--loss=%` for testing, and `--zombies-round N` / `--test-kit` (hosting Zombies: start at round N, the Horde Test kit; not saved).

### Pre-match lobby

When you **host or join** a game you land in the **lobby room** first (**HOST A GAME** on the Multiplayer page goes straight there: there is no separate host settings page any more), a menu in front of the map (drawn slowly orbiting behind it), before anyone is in the match:
- **Players:** name, rank (prestige/level) and hat, team (`*` = picked), ping, ready tick, a crown for the host. Bots are listed as filler.
- **Teams** (team modes): Join Blue / Join Red / Auto with the usual rules (*Picking teams*), but **no switch cooldown** in the lobby. The host has **SHUFFLE** (everyone on Auto, random even split) and **BALANCE** (picks kept, the rest split evenly).
- **Next match:** the map with its size, player limit and description, the mode and its goal, the pack (which the vote draws from), a settings line and a rules line, then the match settings in **collapsible sections** by category. The **host** changes them live and everyone sees it at once; **clients see the same sections read-only** and follow every change. Settings are locked while the start countdown runs.

  | Section (open by default?) | Settings |
  | --- | --- |
  | **MATCH** (open) | mode and its rules, pack and map list (host only; maps too small for the people here, or not for this mode, are greyed out: the same rule as the map vote), **Random map**, score limit (Auto / Fixed, with what it means), **time limit** |
  | **BOTS** (open) | bot count (people who join take a bot's place), difficulty and what it plays like, **bot gear** (Match players / Everything / Starter) |
  | **TEAMS** (team modes) | team selection (Manual / Auto only), max team size difference, **team balance** (Auto / Off / Humans vs Bots). SHUFFLE and BALANCE stay beside the team buttons |
  | **WORLD** | gravity, frenzy buffs, **destruction** |
  | **LOBBY AND CHAT** | auto-start (and its seconds), **Return to lobby between matches**, **Allow voice chat**, **Dead players' chat reaches only the dead** |
  | **SERVER** (host only) | **server name** (live: browsers and server lists see the new name within a second), **Share on our server lists** and **Run one if none answers** (the listing restarts when you tick them), and the port and UPnP (read-only here; they apply when you host, so change them in **Settings > Multiplayer > Hosting**) |

  The host's choices are saved to `settings.txt` when the match starts or the host leaves the lobby, and the next lobby opens with them (the Multiplayer page says what it will open with).
- **LOADOUT** opens the loadout screen (you spawn with the selected loadout; it can still change during the countdown). Your hat is shown beside it.
- **Chat:** type and press Enter (the same chat continues in the match, see Text chat and voice chat). Lines are printable ASCII, at most 120 characters (pasting an image or anything odd is safe), at most 4 lines at once then one every 1.5 s each (checked by the server too); the last 50 lines are kept.
- **READY UP** (or F3). The host's **START** works once every other person is ready (it readies the host too); **FORCE START** works any time. With *Auto-start* on, the countdown starts by itself once everyone is ready, or that many seconds after the first person readies. A **5-second countdown** follows; if someone un-readies it's cancelled (not a forced one; the host can **CANCEL** any). People leaving never stall it.
- At zero the match starts: everyone spawns, and the normal 5-second match countdown runs with the loadout screen open (the lobby replaces the first warmup). The map was already loaded and drawn in the lobby, so the start is quick.
- **People who join during a match** skip the lobby and join the match, as before.
- **Return to lobby between matches** (host setting, the lobby room's LOBBY AND CHAT section, default **off**, saved as `lobby_return`): on, everyone comes back to the lobby after the results screen and the map vote (with the voted map); off, the next match's warmup starts straight away.
- **Single player** has no lobby room: its menu page already has every setting, and the in-map warmup starts the match.
- The **server browser** shows what a game is doing: **In lobby** (green: join now and ready up), Warmup, Starting, In match or Results.
- Online it's server-authoritative: the lobby state (map, settings, every player's ping, ~30 bytes + 3 per player) is sent on every change and once a second; chat goes through the server (protocol 32).

### Appearance

Main menu > **APPEARANCE** is who you are in a match: your hat and the look of your soldier. Everything on it is cosmetic (no hitbox or gameplay change) and saves at once.
- **The model:** on the left your soldier stands on a plinth holding a gun, turning slowly, wearing everything picked here (hat included). **Drag** it to turn it yourself. It's drawn with the same model code as players in a match.
- **Hat:** *No hat* and the five prestige hats, each with a little drawing. Hats unlock with prestige (the rules are unchanged); locked ones are greyed with a padlock and the prestige they need (*LOCKED - Prestige 3*). One choice for your whole profile, worn with every loadout.
- **The look:** one picker per thing bots vary on, with only looks bots already use: **Skin Tone** (6 tones), **Hair Colour** (6), **Headwear** (Hair, Buzz Cut, Helmet, Patrol Cap, Bandana), **Beard** (Clean-Shaven or Beard), **Helmet / Cap Colour** (Olive, Tan, Black, Grey-Green) and **Outfit Colour** (the 8 free-for-all player colours). Colours are swatches, the rest named buttons; the picked one has an orange outline.
- **Auto** on every axis is the look the game picks from your name, as it always has (and as bots get theirs), so nothing changes for you until you pick something. The heading says what Auto gives you, e.g. *Skin Tone - Auto (Medium)*. A hat replaces the headwear (hair keeps its back part under it), as before.
- **RANDOM** picks a random option on every axis (your hat stays). **RESET** puts every axis back to Auto (your hat stays).
- **Team modes:** the team colour still goes where it always did: shirt, sleeves, shoulders, trousers, the team patch and a bandana. That keeps sides readable, so in team modes the **Outfit Colour** is ignored. Without teams (free-for-all, Gun Game, co-op and Zombies, where players already wore their slot colour) your outfit colour replaces the slot colour, on the body and wherever the slot colour showed (name tag, kill feed). Skin, hair, headwear, beard, helmet colour and hat show in every mode.
- **Everyone sees it:** your client sends the look with every loadout (on joining and each respawn), the server checks it and puts it in the roster, which everyone (joiners too) gets. 3 bytes per player, a nibble per axis (0 = Auto). Bots always wear their name's look. Protocol 45.
- **Saved** in `appearance.txt` in the [save folder](#where-your-saves-live): `hat=fedora`, `skin=tan`, `hair=auto`, `headwear=helmet`, `beard=beard`, `gear=olive`, `outfit=green`. **Older saves:** the first time this build runs, the hat comes from `loadout.txt`'s old `hat=` line (that line is no longer written there) and the look is all Auto. A word the game doesn't know (a removed variant, a typo) loads as Auto for that axis; the same goes for unknown values from the network.

### Health and regeneration

Players and bots have **120 health** (it was 100; the bump makes most guns take one more body shot, so fights last a little longer). Shots to kill at full damage range, body / head: BR-1 Prototype 5 / 3 (was 4 / 2), Vanguard AR 5 / 3 (unchanged), Bulldog 4 / 2 (was 3 / 2), Hornet SMG 6 / 3 (was 5 / 3), Marksman M14 3 / 2 (unchanged), Longbow DMR 3 / 2 (was 2 / 1), Needle Bolt-Action 2 / 1 (unchanged). The weapon select shows the numbers for every gun. Things that were built to kill in one go still do: melee (150), the Old Faithful Musket (204 now, one body shot out to about 75 m as before), the Breacher Pump up close (14 damage a pellet now, 9 pellets), the Leviathan .50 and Railspike, and the Frag and Impact grenades (their damage against players went up by the same 20%, so the kill radius is unchanged: about 4.5 m and 2.5 m; against props, machines, zombies and doors they hit exactly as before). Stim Shot scales too (48 back, then 18 a second for 4 s). Bot retreat thresholds and the HUD's red low-health number are percentages of max health.

Health comes back on its own once you're out of the fight: **5 seconds** after you last took or dealt damage (2.5 s with Quick Fix), you start regenerating at **12 HP a second**, speeding up by 4 HP/s every second to **24 HP a second** after 3 s, up to full: about **5.7 s from 1 HP to 120** once it starts (it used to be 8 HP a second flat, about 12 s from 1 to 100). Taking a hit, or landing one (a hit a Last Stand shield blocks counts too), restarts the 5 seconds; firing and missing doesn't. The health bar pulses and glows green while you regenerate. The server runs it, so it's the same for people and bots, in every game mode (including Gun Game and solo test matches), and dead players don't regenerate.

### Blood

How hurt someone is shows as blood, more the lower their health (always as a fraction of max health, so it works whatever max health is), and it goes away as health comes back.

- **On your screen:** nothing above 85% health; below it, procedural blood splatters build up around the edges of your view in layers at **85 / 70 / 50 / 30 / 15%**, and **each new hit adds a splatter on the side it came from** (in front: the top edge, behind: the bottom, left and right: those edges). Near death it gets darker and denser, a faint red vignette creeps in from the screen edges, and below 15% it pulses gently. The centre of the screen always stays clear. As you regenerate the splatters fade back layer by layer; a Stim Shot's instant heal clears them in about half a second. Armour (Ballistic Vests, the Juggernaut suit) and Last Stand's shield soak hits before health drops, so they show nothing until your health itself falls. Everything clears at once when you die (the death tint takes over) and you respawn clean. On ultra-wide screens the splatters sit at the edges of the **HUD width** area (where you look), the vignette at the real screen edges.
- **On bodies (everyone, bots and zombies too):** players and bots show up to 8 blood marks on their body model, more as their health drops, each placed on the body part a hit landed on (head, chest, back, arms, legs; the server records the part from the bullet's exact hit point, and blasts, melee and zombie swipes by the side they came from). Every PC places the marks in the same spots, from the hit parts the server sends in each snapshot. They fade as health regenerates, clear at full health, and a ragdoll keeps its final marks. Zombies bleed a darker ichor, spread over the torso and head as they get hurt.
- **Settings > Video > Blood overlay:** **Full** (default), **Subtle** (fewer, fainter, smaller splatters and body marks) or **Off** (none on screen or on bodies); **Blood colour:** **Red** (default) or **Dark** (a dark maroon, easier on the eyes and for colour-blind players). Saved as `blood_overlay` and `blood_colour` in `settings.txt`; older settings files load as Full / Red.
- Cost: the screen overlay is one instanced draw call (splatter masks generated at startup, no image files; the vignette is four thin bands along the edges, so the middle of the screen isn't touched). Body marks add **no draw calls**: up to 8 small spheres per body go to the box shader as uniforms right before that body's own boxes, which paint a ragged, blocky splat where a sphere touches them; ragdolls carry a blood amount per box in their existing instanced draw. No per-frame allocations. The game log has a `[blood]` line every 10 s while the overlay shows (instances, GPU ms, marked bodies and CPU per frame).
- Network: the blood marks are one 32-bit word per player in every snapshot (protocol 33): 8 hit parts, a generation and the direction of the latest hit.

### Bullet penetration

**Bullets go through thin or soft walls when the round is big enough.** Every gun has a penetration power (from its class and calibre: pistols and SMGs low, rifles medium, DMRs and LMGs high, snipers very high; shotgun pellets almost none, slugs medium; launchers, the Toy Blaster and the Arc Carbine none, the Railspike most). Passing a box costs its thickness along the bullet's path (so an angled shot goes through more) times its material's resistance; the round goes on with the power it has left, its damage cut after each surface (it keeps the material's share, less the harder the wall was), and passes at most **3 surfaces** (touching boxes, such as a wall's core and its plaster linings, are one surface). A surface it can't get all the way through stops it at its front. **Never:** the terrain, the ground, rock, asphalt, the map's boundary, moving platforms, the Bocage hedgerows (earth banks), anything thicker than its material's limit (25 cm of concrete, 35 cm of brick, 6 cm of metal), crates and cars thicker than that. Headshots still count through a wall. **AP Rounds** (magazine slot) give 1.6x the power, the **Hollow Point Mag** 0.6x.

So a building's plaster interior walls (25 cm + linings) stop pistols and SMGs but not LMGs, DMRs and snipers, wooden floors and doors let most rifles through, and brick or concrete outside walls stop everything but the heaviest rifles (the 10 cm wood + 10 cm plaster check: the Needle passes both with 61% of its damage).

- **What a surface is made of** is the bullet-impact surface (the box's texture refined by colour and facing, a building part's own material, a door's wood or metal, the terrain's ground); props by their name (`"props"` rules in the file: sandbags are sand, crates and pallets wood, cars and trucks metal, the Bocage hedgerows earth that stops everything), else their biggest textured parts, else how they break.
- **Server-authoritative**: the host extends each pellet's ray through what it can pass and hits players behind with the rewound positions of lag compensation; breakable props, doors and glass along the way take the hit too. The shooter predicts the same tracer and hit marker; a hit through a wall shows a second, inner set of marker ticks. Bots get no wallhacks: they only shoot at people they see, except that an Insane base of fire may now put its suppressive fire on a fresh last known spot through a wall its gun goes through.
- **Both sides of the wall** get an impact mark (the exit hole 30% bigger) and a puff of dust (sparks off metal), the same on every screen: a shot that went through something sends its origin after the tracer ends (12 bytes; flag 64 in the Shot message, 128 = a hit through a wall). Older clients ignore it. No protocol change of its own.
- **Data**: `Materials/penetration.json` (`call-of-slop-penetration/1`): per material `resistPerCm`, `maxCm` (0 = never) and `damageKept`; per weapon class `base` + `perCalibre` x calibre; `shotgunPellets`; `maxSurfaces`; `props` rules. A weapon file can give `"penetration"` (an absolute power, -1 = derived) and attachments can change `"penetrationMult"` (see [Weapons/README.md](../Weapons/README.md)). A map can switch it off with a top-level `"penetration": false` (on everywhere by default; see [Maps/README.md](../Maps/README.md)).

### Melee

Press **V** for a quick rifle-butt. It reaches about 2.4 m and **kills in one hit** (150 damage against 120 health), from the front or behind. Entrenched (bullets only) and Flak Jacket (explosions only) don't reduce it, and Last Stand doesn't save you from it. It cancels a reload, has a 0.8 s cooldown, and you can't fire for a moment after swinging. It's resolved on the server with the same lag compensation as shots. Zombies and breakable props still take 55 damage from it (a built Zombies melee weapon has its own stats). Bots use it when you stay right up close to them: they need a moment in reach first (0.6 s on Easy, 0.35 s on Normal, 0.2 s on Hard, 0.18 s on Insane), so running past one isn't instant death.

### Mantling

Hold **forward + jump** at a ledge up to 1.7 m high (crates, low walls, window sills) to climb onto it. Windows are 1.3 m tall, so you go through them in a crouch: you land on the sill and carry on through. Keep holding forward to drop out the other side. Mantling is part of the shared movement code, so it's predicted and smooth online too.

### Slopes

On terrain maps (the Legacy pack's High Ground maps, the Dev pack's Terrain Test) the ground's slope is measured over your footprint (a 0.4 m radius), not the single bump under your feet, so small noise in a hillside doesn't stop you or start a slide.
- **Walkable up to 45 degrees.** Walking uphill is full speed up to 25 degrees, then gradually slower: about 92% at 30, 82% at 35, 72% at 40 and 60% straight up a 45 degree slope. Going across or down a slope is full speed.
- **Grip:** while you move, a narrow steep patch (walkable ground within 0.45 m before and after it) that rises no more than a step (0.55 m) against the slope around it is crossed, so brief steep bumps don't stop you or kick you into a slide, and small terrain lips and edges are stepped over like stairs. Taller banks (up to 1.7 m) are mantled with forward + jump, as before.
- **Stuck to the ground:** walking over a crest or down a slope (up to the 45 degree limit) keeps you on the ground; you don't bounce or go airborne.
- **Steeper than 45 degrees** slides you down. The slide is capped at 8 m/s and you can steer across and down it (not up), so you can always steer out. Cliffs are still walls.

Boxes, ramps made of meshes and the like keep the old 42 degree rule. Bots use the same rules: their nav graph only links what a player can walk, routes prefer gentler ways up, they cut straight across hillsides when the line is walkable, and a bot that gets no closer to its next waypoint (walking up and sliding back) re-plans another way.

### Lobby size

Up to **32 players** (people and bots), but every map has its own limit: **8-10** on small maps, **12-16** on medium ones and **24-32** on large ones, worked out from the map's area (a map file can set its own with `"maxPlayers"`, see [Maps/README.md](../Maps/README.md#player-limits)). The lobby shows **x / max players** under the bot slider, and the slider stops at the map's limit. With **Random** from a pack (or **True Random**), it goes up to the biggest map in the pool and the game picks among the maps that take everyone. The map list shows each map's limit.

- **Joining a full game:** a person takes a bot's place. If the map is full of people, the join is refused with "The server is full: x/y players on map".
- **Map vote:** only maps big enough for the people playing are offered. When a smaller map wins, bots it has no room for leave (people never do), and they come back on a bigger map: the bot count you set is remembered.
- **Spawns:** every map needs a spawn per player. Maps with fewer get extra spawns when they load (same floor, in sight of a hand-placed spawn, clear of walls), so the old maps play as they always did with more people. Spawning never puts you on top of someone.
- **Team Deathmatch** plays to 5 kills per player in bigger lobbies (40 up to 8 players, 80 at 16, at most 100).
- **Scoreboard:** columns are Player, **Level** (prestige and level, as in the lobby; `BOT` for bots), the mode's two numbers, Weapon and alive/dead. It shows nobody's health (your own is on your HUD). Above 12 players it switches to two compact columns (Blue and Red in team modes, the ranking split in two otherwise). The kill feed keeps 6 lines, and a burst of joins shares one line ("X and 9 others joined").
- **Bandwidth:** each client receives about 9 KB/s at 8 players, 13 KB/s at 16 and 21 KB/s at 32 (measured by the self-test over loopback, game data without UDP headers). The host sends that to every client.

### Server browser and public games

**Multiplayer** has a **HOST A GAME** button, which opens your lobby room straight away (every match setting is there, see [Pre-match lobby](#pre-match-lobby); a line under it says which mode, map and bots it opens with), and two tabs:

- **Server browser:** lists games to join with name, map (with an orange **True Random** tag when the host plays True Random), players / the map's limit (and bots), ping and where it was found (**LAN**, **list**, or both: a game found twice is one row). Click Join. Games on your network show up automatically: the browser broadcasts on the local network and every hosted game answers. Internet games show up from your **server lists** (see below). Games running a different build are listed too, with a note: *Your build is older - update to join* (the host has a newer protocol), *The host's build is older* (they must update), or, for a different but compatible release, both version numbers. Different protocol versions can't join each other, so those rows have no Join button (see [Updates](#updates)). The list refreshes every few seconds.
- **Join by code or address:** paste an invite code or `callofslop://` link, or type an address (`ip`, `ip:port` or a host name; the port box is used when none is given).

### Playing with friends

Nobody needs to run or pay for anything:

1. **Host** (Multiplayer > HOST A GAME). The lobby room shows your address and an **invite code** like `ABCD-EFGH-JKMN-PQRS`, with **Copy invite link** and **Copy code** buttons (the code is also at the top-left of the screen in a match). Send it to your friends.
2. **Friends join** with Multiplayer > Join by code or address: paste the code (or link) and press Join. A typo is caught by the code's check digits, and a code from a different build says so.
3. **After that, the server browser just works.** When you host, the game looks for a server list your group already has; if none answers within a second or two, **your game runs one** (UDP 27050, opened on the router with UPnP like the game port) and puts it in your invite code. Anyone who joins you (by code, by address or on your network) adds that list to **Settings > Multiplayer > Server lists** by themselves, so next time everyone's games show up in everyone's browser. If several hosts started lists, they settle on one: an automatic list hands over to a hand-started one (or to the automatic one with the lower id) at its next check, once a minute, and the browser asks every list you know anyway.

The code holds your public address, so the game asks a public **STUN** server (Google's or Cloudflare's: one 20-byte request, nothing else) when you host; turn that off in Settings > Multiplayer if you like (the code then uses the router's or your LAN address). Your game must be reachable: UPnP on, or UDP port 27015 forwarded. Behind carrier-grade NAT (the settings say so when they spot it) friends outside can't reach you directly: let one of them host.

**Settings > Multiplayer** also has:
- **Server lists:** the lists you know, comma separated (up to 8; typed or learned). A group can also put an always-on list in **masters.txt** next to `CallOfSlop.exe` (one `host[:port]` per line) before sharing its zip.
- **Run a server list for friends on this PC:** keeps a list running while the game is open, without hosting. Without the game, run **`RunServerList.bat`** from the release folder (the same as `CallOfSlop.exe --master [port]`): a console window shows what it does (close it to stop it; the log is `serverlist.log`). Friends add this PC's public address under Server lists, or just join one of your group's games by code once.
- **Make invite links open the game** (Windows): registers `callofslop://` links for your Windows account only, so a friend can click your link in Discord or a browser; the same place removes it or points it at a newer build. Nothing is registered unless you click it.

**What sharing means:** anyone who knows a server list's address sees the games on it: name, map, mode, player count and the host's IP address and port (what LAN broadcasts always showed). Lists are run by players, never by a company, and keep nothing else. Untick **Share on our server lists** to stay off them; invite codes still work. Details and the options considered (including a serverless DHT list, which was declined): [docs/net/SERVER-DISCOVERY.md](net/SERVER-DISCOVERY.md).

Single player works the same way: **Change map...** shows the current choice and opens the map select screen. With random picked, the lobby background tours the pack's maps (True Random: every pack's).

### Map select

**Change map...** (Single player) opens the map select screen (hosting: the lobby room's MATCH section has the pack and map list instead):

- **Left: the map packs**, one tile each in their `pack.json` order (Dev last), with the pack's name, map count, sizes ("7 small, 9 medium, 8 large") and a small picture: a collage of up to four of its maps, seen from above. **True Random** sits at the bottom.
- **Right: the open pack.** Its description, then **Random** at the top, then its maps, smallest first, each with a picture, size, player limit and description. Opening a pack always pre-selects **Random**. A map too small for your bots is shown in orange (the bots are cut to fit).
- **Click** selects, **double-click** (or **Enter**, or the orange **CHOOSE** button) takes it and returns to the lobby; double-clicking a pack tile takes that pack's Random. **BACK** or **Esc** leaves without changing anything. Keyboard: **Up/Down** through the maps, **Left/Right** (or Page Up/Down) through the packs. The lobby background follows the selection, and CURRENT marks what's chosen now.
- **True Random** is a pack that isn't a folder: every match is on a random map from **all** packs except **Dev** (its test maps aren't balanced for play; you can still pick them from the Dev pack). Like random from a pack, it only picks maps that take you and your bots, and the map vote afterwards offers maps from every pack. A pack can leave itself out with `"trueRandom": false` in its pack.json.
- The pictures are rendered by the game itself (no image files): each map once, into a small offscreen texture at 384x216, one per frame so the screen never freezes, and cached until the map's file changes. If the graphics card can't do it, plain coloured tiles are shown instead.

The choice is saved in `settings.txt` as before (`map_pack=<pack name>`, `map=<map>`, `map_random=1|0`); True Random is `map_pack=*all`. Older settings files load unchanged.

**Maps are data files.** Each map is one `.json` file in a pack folder under `Maps`: its name, size, sky colour and a list of building ops (`Building`, `WallX`/`WallZ` with door and window holes, `Slab` with stairwells, `StairsX`/`StairsZ`, `Container`, `Car`, `Hill`, `Tree`, `Watchtower`, `Hangar`, `Bridge`, `TrainCar`...). To add a map, drop a file into a pack folder (or a whole pack folder into `Maps`) and click **Refresh maps** in the lobby; no restart or recompiling. In single player, **Reload map files** in the Esc menu rebuilds the map you're standing in from its file, for quick edit-and-look map making. Maps can also have **terrain**: an optional `"terrain"` object shapes the ground with hills, ridges, valleys, plateaus, cliffs, ramps and noise (a heightfield you walk on, shoot over and throw grenades across; slopes up to 45° can be walked, a bit slower uphill, steeper ground slides you down and cliffs are real walls; see [Slopes](#slopes)), and the ops are placed on the ground. The **Dev** pack's *Terrain Test* map shows it off. Terrain can also have **holes and caves** (`hole` and `cave` features): pits, sinkholes and skylights, and tunnels and chambers under the ground with rock walls and ceilings that get darker inside, which players, bots, bullets and grenades all use; the Dev pack's *Cave Test* map has a tunnel between two entrances through a chamber, a sinkhole into a side passage and a few pits. Anyone can make one: **[Maps/README.md](../Maps/README.md)** is the map makers' guide, with a full example and every op. A file with a mistake is skipped with a message that names the file and the problem (also shown in the lobby), and `CallOfSlop.exe --check-map FILE` checks one without starting the game. Online, servers and clients identify maps by name plus a geometry fingerprint, so a player missing a host's custom map is told which file to get, and the server browser shows maps you don't have in orange.

**Foliage.** A map file can also have a `"foliage"` section: grass, bushes, shrubs and trees scattered over areas, or placed one by one (see [Maps/README.md](../Maps/README.md#foliage)). Only tree trunks are solid. The rest is drawn with instancing, culled in 16 m chunks, thinned out with distance through a dither (no popping) and sways in the wind. The **Dev** pack's **Foliage Test** map is a flat 100 m meadow for trying it out. **No-go zones:** nothing grows indoors: plants under a roof, a floor above, a bridge deck or an awning, or inside a box or a cosmetic mesh, are left out (trees don't count as roofs), and paved surfaces thin them out by material (intact concrete, tiles and floors grow nothing; a map can mark cracked paving or busted paths with a small fraction, so an odd tuft or shrub comes through). Maps can add explicit `exclude` and `include` zones and turn the automatic rules off (see [Maps/README.md](../Maps/README.md#no-go-zones)). Maps without foliage are unchanged. Lighting (sun, sky and ground ambient, fog) is shared by boxes and plants (`Source/Render/Lighting.cs`).

**Skies.** A map file can have a `"skybox"` section: a drawn sky with a zenith/horizon gradient, a sun disc and glow placed by a direction or by time of day and latitude, a moon with phases, stars and drifting clouds, or an image sky (a cubemap of 6 PNGs, or a PNG/HDR panorama). Presets (`clear`, `overcast`, `dusk`, `night`, `desert`, `alpine`) cover the common cases: `"skybox": "dusk"`. The map's lighting follows its sky (sun direction and colour, ambient), and fog fades distant things into the sky colour behind them. Maps without a skybox keep their flat sky colour and look exactly as before. The **High Ground** maps each have one, and the **Dev** pack's **Sky Test** map is made for trying them out (see [Maps/README.md](../Maps/README.md#sky)). **Settings > Video > Sky quality**: Low draws the gradient, sun and moon; High (default) adds clouds and stars. The sky is drawn last in the opaque pass, only where nothing else covers the screen, with one shader per kind of sky (procedural High, procedural Low, cube map, panorama) so no pixel runs code its sky doesn't use; it costs well under 0.2 ms of GPU time on a desktop GPU (`[sky]` lines in the log; `--gl-bench` logs a "sky alone" line per sky map, the cost of a full screen of sky at High and at Low; `Source/Render/Sky`).

**Baked lighting.** Maps can have torches, candles, chandeliers, lamps, spotlights and glowing windows (`LightSource` ops, and props that carry their own lights). Their light, the sun's shadows and how much sky each spot sees are baked once into a 3D light grid stored with the map, and every surface, player, zombie and gun reads it per pixel, so a hundred lights cost no more to draw than one. Maps without lights look exactly as before. The **Dev** pack's **Light Test** shows it; **Settings > Video > Lighting**: Off, Baked, or Baked + flashes (default: muzzle flashes and blasts light lit maps too, at most four at once). See [Maps/README.md](../Maps/README.md#lighting) and [docs/render/LIGHTING.md](render/LIGHTING.md).

**Moving platforms.** A map file can have a `"movers"` section: rotating platforms, sliding platforms (back and forth, or round a looping path) and elevators, each built from a few boxes and running on a constant loop (see [Maps/README.md](../Maps/README.md#movers)). Stand on one and it carries you (a turning platform turns you and your view with it), walk around on it as on solid ground, and jump off with its momentum. They push you out of their way rather than passing through you, and never crush you into a wall. Bullets, grenades and sight lines hit them where they are. Their motion is worked out from the server's clock on every PC, so they cost no network traffic and your own movement on them is predicted without jitter. Bots keep out of their paths. The **Dev** pack's **Physics Test** map has slow and fast spinning discs, a spinning bar to jump over, sliders, a ferry across a gap and a looping elevator up to a deck.

**Props.** Trash cans, dumpsters, wheelie bins, crates, pallets, oil drums, cones, barriers, benches, lamps, hydrants, bricks, rubble, newspapers, bottles, cardboard boxes, chairs, tables and more: 298 props ship in the `Props` folder, one JSON file each in category folders: the 61 starter props (`Street`, `Industrial`, `Debris`, `Furniture`, `Nature`), the indoor and everyday set in `Household`, `Office`, `Kitchen`, `Garden` and `Misc`: furniture, appliances, office kit, kitchen things, garden things, ducks and pets (see [Props/README.md](../Props/README.md)), plus 114 outdoor props in `Vehicles` (cars of every body type, a bus, trucks, a forklift, bikes), `Rooftop` (air conditioners, vents, air ducts, chimneys, a water tower, satellite dishes, solar panels), `Utility` (power poles, transformers, manholes, fire escapes, scaffolding, ladders), `Signage` (traffic lights, road signs, a billboard, shop signs) and `Urban` (a bus shelter, a phone booth, a newsstand, an ATM, fences, barriers). The `Military` folder (58 props, see [Props/Military/README.md](../Props/Military/README.md)) adds sandbags, barbed wire, tank traps, field guns, ammunition crates (shell crates and fuel racks explode), pallets, tents, a searchlight, a guard tower and the landmines, and in `Military/Vehicles` five tanks, four full-size parked planes (props can be up to 24 m), jeeps, trucks, an armoured car and a sidecar motorcycle, with Desert and Winter variants; the Dev pack's **Military Props** map shows them all. Maps place them one by one or scatter them with a `Clutter` op that keeps them clear of spawns, routes and doorways (see [Maps/README.md](../Maps/README.md#props)). Solid props block players, bullets and bots like any box; small litter is cosmetic and fades out with distance. All of it is drawn instanced and culled in 24 m chunks, a few draw calls for hundreds of props; the game logs a `[props]` line every 5 seconds on maps with props. **Breakable props** (crates, boxes, bins, bottles, chairs, pallets, cones) break when shot, hit or blown up and shatter into pieces that bounce, settle and fade out; the explosive barrel goes off. The host decides what breaks and tells everyone, and every match starts with everything whole. Health follows the material: glass and paper break at a touch, plastic and wood take a few shots, metal more, and vehicles, concrete and big structures are unbreakable cover (the material health guide is in [Props/README.md](../Props/README.md#material-health-guide)). The **Dev** pack's **Prop Gallery** shows the starter props, **Prop Gallery 2** the outdoor set, **Prop Gallery 3** the indoor set, **Prop Yard** is a small dressed street. The Classic and Collision Point maps don't use props. **Landmines** (`Props/Military`): a half-buried pressure-plate mine clicks when someone steps on it and goes off 0.35 s later (a quick sprint gets you out wounded), or when shot or caught in another blast; its blast is neutral and hurts everyone (the shooter gets the kills on their enemies, other deaths read "Landmine" and are nobody's kill), bots route round mines, zombies set them off, and a map can bring a breakable prop back with the Prop op's `respawn` (see [Props/README.md](../Props/README.md#landmines)). The Dev pack's **Landmines** map shows them; no other map uses them. **Animated props** (`Props/Animated`, 65 of them: fans, roof turbines, a windmill and a wind turbine, flags, banners, swinging signs and lanterns, flickering lamps, neon signs, beacons, traffic and crossing lights, radar and satellite dishes, clocks, a ferris wheel and a carousel, a pumpjack, conveyor rollers, a shaking generator, a cement mixer, swings, wind chimes, a pendulum clock, a Newton's cradle, bobbing buoys and ducks, screens and arcade machines...) have parts that spin, swing, bob, shake, blink, pulse, flicker or cycle, set by an optional `"anim"` block on a part (see [Props/README.md](../Props/README.md#animation)). It's cosmetic: colliders never move. The motion is worked out on the graphics card from the time and each prop's position (so a row of fans doesn't turn in lockstep, and flags and turbines follow the same gusts as the grass), costs nothing on the CPU, and props farther than 80 m (per prop) hold still and are drawn by the plain prop shader. The `[props]` line adds the animated props drawn moving and still and the animated pass's GPU time. The Dev pack's **Animated Props** map shows them all; existing maps don't use them. **Flags** fly national flags from a flag pool (`Props/Flags/flags.json`: the US, UK, French and Finnish flags): a Flag on a Pole picks one from its position (the same on every PC and every match, and mirrored flags match), and a map can name the flag per placement or limit its pool (see [Props/README.md](../Props/README.md#flags)). The Cluttered and Dev maps use it; the Dev pack's **Flag Lineup** shows all four.

**Map shapes.** A map doesn't have to be a rectangle: an optional `"boundary"` section makes the playable area a circle, an oval, a polygon (concave is fine) or a smooth blob such as a bean, optionally with a seeded wobble so the edge is irregular, shown as a wall, a terrain cliff, a fence, a hedge, a line of boulders or props, or nothing (see [Maps/README.md](../Maps/README.md#boundaries)). An invisible barrier runs exactly along the outline, so players, bots, grenades and debris never leave, and spawns, waypoints, foliage, clutter and the bots' routes all stay inside. The floor is drawn following the outline with a darker ground beyond it fading into the fog. Maps without a boundary are unchanged. The **Dev** pack's **Shape Test** map is a bean with a curved wall.

**Meshes and models.** Maps can also place round and sloped shapes and real 3D models, not only boxes: the `Mesh` op makes cylinders, cones, spheres (UV and geodesic), capsules, rings, ramps, pipes and rounded boxes from a few numbers, and the `Model` op places glTF 2.0 models (`.glb` / `.gltf`) from the `Models` folder, with their node hierarchy, materials and base colour textures (see [Maps/README.md](../Maps/README.md#meshes-and-models) and [Models/README.md](../Models/README.md)). Three small test models ship (a barrel, a traffic cone, a lamp post). All meshes share one GPU vertex and index buffer and are drawn instanced, one draw call per mesh and LOD, culled outside the view and switched to simpler LODs with distance, lit and fogged like the boxes; the game logs a `[mesh]` line every 5 seconds on maps with meshes. They are cosmetic for now (no collision), so map makers put a `Block` inside where players need cover. The **Dev** pack's **Mesh Test** map shows every shape plain and textured, a LOD line, the models and a field of 128 instanced shapes.

**Space pack and planets (gravity fields).** A map can declare a gravity field: `"gravity": { "type": "point", "center": [0, 0, 0] }` pulls everything towards one point, so a ball becomes a planet you walk all the way round (the usual straight-down gravity is the default, and every other map plays bit for bit as before). **Pocket Planet** (`Maps/Space/02-Planet.json`, 16 players) is a 56 m planet with a light pull (11 m/s2): Blue's outpost and flag on the north pole, Red's on the south pole, four hills round the equator between two great monoliths, trench berms, watchtowers, craters and boulders, under a starfield with a gas giant hanging in the sky. The curve is real: the horizon is about 13 m away for someone standing, so people come into view head first over it. "Up" is away from the centre wherever you are: your view rolls with the ground (walking round never turns you, the game carries your view from one spot's frame to the next), jumps, grenades, launcher rounds, ragdolls, gibs and debris fall towards the centre, and bots find their way over the whole sphere. Nothing extra goes over the network: everyone works out "up" from the position and the map. See [Maps/README.md](../Maps/README.md#planets-point-gravity) for the planet ops (`Planet`, `SurfaceMesh`, `SurfaceBlock`, `Crater`, `SurfaceScatter`, `SurfaceSpawn`...) and what doesn't work on a planet yet (mantling, the death camera, flying kill streaks). Planet surfaces are solid meshes: unlike the plain `Mesh` op, they collide.

**Gravity setting (host).** *Gravity* on the Single player page and in the lobby room's WORLD section (25% to 200%, default 100%, saved as `gravity` in `settings.txt`) multiplies every map's own gravity: straight-down maps, planets and every gravity zone. Players, grenades, launcher rounds, ragdolls, gibs and debris all fall with it, so at 50% you jump twice as high and twice as long, and at 200% half as high. Pocket Planet's own pull is 11 m/s2, as a small world should be (normal is 18). A planet never plays under its own floor, though: below it a sprint jump could fly right off the sphere, so Pocket Planet plays at no less than 60%, and the lobby room says so. Clients get the setting from the host, so movement prediction matches, and the server browser shows it next to any game that isn't at 100%. Bots keep the map's nav graph (it's built at 100%, the same for every setting) and don't hop about in fights in low gravity over a void.

**Materials and effects.** Parts, props and extrusions share a small library of materials (`Materials/Surfaces.json`: steel, painted steel, aluminium, rubber, glass, wood, copper, fabric, concrete, dirty steel, rust and more): each holds a number into one table, paint is a tint over its material, and a material changed in the file changes everything made of it. Metal catches the sun and the sky, edges wear, and a hurt part rusts and scorches by its health. Flames, smoke, sparks, dust and blasts are one pool of particles (`Materials/Particles.json`), run by the GPU on OpenGL 4.6 and in a smaller pool on 4.1. **Settings > Video**: **Materials** and **Particles** are each Low, Medium (default) or High; **Post effects** are Low (default: none), Medium (bloom on what glows and heat haze over flames) or High (ambient occlusion too), each effect with its own switch. A new burning part needs one line of data: see `"flame"` in [docs/render/MATERIALS.md](render/MATERIALS.md).

**Decals.** Maps can paint flat pictures onto their surfaces: oil stains, cracks, water stains, manhole covers, drain grates, road arrows, hazard stripes, graffiti, posters, grime and soot. Each decal is one JSON file in the `Decals` folder (format `call-of-slop-decal/1`): layers of simple shapes (circles, rings, rectangles, ragged splats, cracks, speckles, lines, stripes, with soft edges and grunge noise) and/or a small PNG, a size in metres, size, turn and brightness variation, a blend mode (`alpha` paint or `multiply` dirt) and the surfaces it may land on. The `Decal` and `DecalScatter` ops project them onto boxes, buildings, the terrain (never over a hole) and meshes, wrapping over kerbs and edges (see [Maps/README.md](../Maps/README.md#decals) and [Decals/README.md](../Decals/README.md)). They are cosmetic and not part of the map's fingerprint. A map's decals are baked once into one buffer, culled in 24 m chunks and faded with distance; decals on a door or breakable box vanish while it is open or broken. About 80 placeable decals ship: ground grime and litter (puddles, mud, leaves, gravel, tyre tracks, footprints), road and court markings, wall damage, signs, abstract posters and graffiti, things lying on the floor (covers, grates, rugs, litter, glass) and ceiling stains ([the catalogue](../Decals/README.md#the-catalogue)). A map pack may also carry its own decals in `Maps/<Pack>/Decals` (seen only by that pack's maps; one with a global decal's name replaces it there, `"global:Name"` still means the global one; see [Decals/README.md](../Decals/README.md#pack-decals)). The **Dev** pack's **Decal Test** map shows the system's features and **Decal Surfaces** shows every placeable decal. **Pack Decals** shows the Dev pack's own decals. **Bullet impacts** are decals too: every shot that ends on a wall, floor or the terrain leaves a hole picked for the surface (concrete, plaster, asphalt, brick, wood, metal, tiles, dirt, grass, sand, rock, snow, three or four variants each, sized by the gun's calibre), and grenades, launcher rounds and strikes leave a scorch, the same on every player's screen (they follow the server's hit points, no extra network traffic). **Settings > Video > Bullet impacts**: **High** (default, 1024 kept at once) **/ Medium** (512) **/ Low** (128) **/ Off**; each player keeps at most 64, the oldest fade out first, close shotgun pellets merge when the pool is busy, and holes on a door, window or breakable box vanish when it opens or breaks (props, drawn as models, take none). The decal pass logs a `[decals]` line every 5 seconds (decals and impacts drawn, draw calls, CPU and GPU time; target under 0.1 ms).

**Buildings.** Maps can place whole furnished buildings from the `Buildings` folder with one op (`{ "op": "Building", "name": "Small House", "at": [x, z], "yaw": 180 }`): walls with real door and window openings, floors, ceilings, stairs, roofs (flat, gable, hip, shed or none), porches, awnings, balconies and mezzanines, and furniture placed room by room by type (a bedroom gets a bed against the far wall with bedside tables and lamps, a kitchen a run of counters with a kettle on them...), never in a doorway or in front of a window. Each building is one folder (`building.json`, plus its own props and furnishing rules if it needs any; see [Buildings/README.md](../Buildings/README.md)), with palettes, seeds, mirroring, turning and floor counts for variants. **Doors** open and shut with the interact key (F) and swing on their hinges; shut, they stop players and bullets; bots and co-op enemies open them as they go and shut them behind them (see [Bots](archive/MANUAL-ARENA.md#bots)); bullets, melee and grenades break them (wood takes about 5 rifle hits, metal 14), and a broken doorway stays open. **Window glass** stops you but not bullets: shoot it out (it shatters) and climb through the empty frame. The host decides and tells everyone, players joining mid-match get the doors and windows as they are, and every match starts with everything whole. The bots' routes run through doorways and up every staircase, and no foliage grows indoors. Building walls are drawn instanced (a whole street of buildings is a handful of draw calls; the game logs a `[buildings]` line). Ten starter buildings ship: a small house, a two-storey house, an apartment block, a corner shop, a diner, an office building, a warehouse with a mezzanine, a gas station, a garage and a ruined house; the **Dev** pack's **Building Yard** shows them all with variants. Ten more industrial ones (a factory with an assembly line, a brewery, a sawmill, a substation control house, a cold store, a recycling plant, a print shop, a chemical lab, a machine shop and a grain barn with silos) are on the Dev pack's **Buildings Industrial** map, and ten themed residential ones (a farmhouse, a 1960s ranch house, a Victorian townhouse, a mobile home, a beach bungalow, a duplex, a terrace of three row houses, a modern villa with a pool, a three-storey student dorm and a hunting lodge) line the Dev pack's **Residential Street**. `tools/buildings` previews and checks building files without the game. **Stairs must give 2.1 m headroom:** every staircase in the game (buildings, map ops, escalators, props used as steps) is walkable standing, without crouching: 2.1 m clear over every step, steps of at most 0.55 m, 1.0 m clear between the sides and room at both ends. The generator lengthens each stairwell in the floor above to keep the slab's edge clear of a climbing player's head, and the self-test's "Stairs" section finds every flight on every map and in every building and walks it standing with both movers (see [Buildings/README.md](../Buildings/README.md#stairs)).

Movement handles any stack of boxes: you stand on anything, walk up steps up to 0.55 m, and bump your head on ceilings.


Surfaces are textured with a few tiny patterns generated in code (concrete, brick, wood planks, metal panels, floor tiles, dirt), tinted by each block's colour. The material is picked automatically from each block's shape and colour: crates get planks, walls get brick or concrete, floors and roofs get tiles, sandy ground gets dirt. Proto Box keeps its prototype grid.
### Controls

These are the defaults; everything except Esc and the mouse wheel can be rebound in **Settings > Controls**. ### Display

- **Windowed:** pick a size from your monitor's resolutions, or drag the window edges. The game remembers the size and position.
- **Borderless fullscreen:** a frameless window covering the monitor at its native resolution. Alt-tab is instant.
- **Fullscreen:** exclusive fullscreen at the resolution you choose.
- **Text size:** how big all text is, with the menus and the HUD around it (windows, columns, padding, the tool wheel and its rings grow with it). **Auto** (default) follows your monitor's scaling where it asks for more than the resolution gives: a 1080p laptop set to 150% in Windows starts at 150%, a 4K monitor at 150% stays at 100% (its height already makes text twice as big as at 1080p). Auto shows the percent it picked. **Small** (85%), **Normal** (100%), **Large** (125%) and **Extra large** (150%) are quick picks, and the slider goes from 75% to 200% in 5% steps, applied when you let go. Changes apply at once, with the settings open; windows you sized keep their proportion. Underneath, the UI still scales with the window height (about 1.2x at 1080p, 1.6x at 1440p), and the text size multiplies that. Text stays sharp at every size: ImGui draws each glyph at the size it is shown. Saved as `text_size` in `settings.txt` (`auto` or a percent); older files load as Auto, or keep the old UI scale slider's value as a percent if it was moved.
- **Foliage:** **Off / Low / Medium** (default) **/ High**. How much grass, how many bushes and shrubs, and how far away they're drawn, on maps that have foliage (try the **Dev** pack's **Foliage Test** map). Off draws none of it and costs nothing. Tree trunks are always there, because they're solid: they stop players and bullets. Grass, bushes and tree tops never do. The game logs a `[foliage]` line every 5 seconds on foliage maps (plants drawn, draw calls, CPU and GPU time) in callofslop.log.
- **Bullet impacts:** **Off / Low / Medium / High** (default). How many bullet holes stay on the map at once: 128, 512 or 1024 (each player at most 64; the oldest fade out). Off draws none and costs nothing. Saved as `impact_decals` in `settings.txt`; older files get High.
- **Head bob:** 0-100% (default 100%). How much the camera bobs as you move: two small dips per stride, timed to your legs' footfalls, and a slight side-to-side sway and roll once per stride. It grows with ground speed, from about 1 cm and 0.2 degrees at a walk to about 4.5 cm and 0.8 degrees at a full sprint. There's none in the air (jumping, falling, mantling) or while prone, half while crouch-walking, and it fades out as you aim down sights, so scopes stay steady. It eases back in after you land. Only the picture moves: your aim and your bullets always come from the steady eye, and nothing is sent over the network. 0% is the old, perfectly steady camera. Saved as `head_bob` in `settings.txt`; older settings files load with 100%.
- **HUD width:** on ultra-wide monitors the in-match HUD (session info, kill feed, health, ammo, match bar, banners, scoreboard) stays inside a centred area so it's easy to read. **16:9** (default) keeps it 2560 px wide on a 3440x1440 or 5120x1440 screen; **21:9** allows 3360 px; **Full width** uses the screen edges. On 16:9 or narrower screens all three are the same. The crosshair is always centred, the blood splatters sit at the edges of this area (see **Blood**), and the damage effects always cover the whole screen (a scope's lens is sized from the screen height, so on an ultra-wide screen more of the eyepiece shows at the sides).

- **Blood overlay:** **Full** (default) **/ Subtle / Off**, and **Blood colour:** **Red / Dark**. Blood splatters at the screen edges as your own health drops and blood marks on hurt players and zombies; see **Blood** above.
- **Name tags:** **All** (default) **/ Team only / Off**, plus **Teammate health bars** (off by default). Names float over players' heads, CoD style:
  - **Teammates** (everyone in Zombies) are tagged whenever they're on screen within 60 m, *through walls*, so you can find your friends. In their team colour (in Zombies everyone is on the one co-op side: the friendly blue, also in the HUD's points list and the scoreboard), fading from 30 m to 60 m.
  - **Enemies** (everyone in free-for-all and Gun Game) are tagged only while your crosshair is on them, they're within 40 m and you can actually see them: walls and smoke hide the tag, so it never gives anyone away. The tag lingers half a second (fading) after your crosshair leaves, and drops at once if they step behind cover. An enemy shown through walls by your Recon Pulse or Recon Sweep can be tagged by aiming at their outline. In the enemy team's colour (red without teams).
  - Bots show their names ("[BOT] ..."). Never your own tag, never on dead players. Through a magnified scope tags stay but are a quarter smaller. While you're dead, teammates stay tagged from the death camera and your killer is tagged.
  - Tags shrink with distance and scale with the window height like the HUD (so they're the same size on 1080p, 1440p, 21:9 and 32:9), stay inside the screen, and a tag that would cover a nearer one stacks above it or fades.
  - Cheap: one ray-box test per enemy and at most one line-of-sight ray every 0.1 s (for the enemy you're aiming at), no allocations. Saved as `name_tags` and `name_tag_health` in `settings.txt`; older files get All. The distances and sizes are data in `UI/NameTags.cs` (`NameTagRules`).

### Stances

| Stance | Height | Speed | Spread | Recoil | Notes |
| --- | --- | --- | --- | --- | --- |
| Standing | 1.8 m | 100% | 100% | 100% | Can jump and sprint |
| Crouched | 1.2 m | 50% | 75% | ~85% (per gun) | Fits behind low walls and crates. LMGs lose almost all sideways recoil |
| Prone | 0.6 m | 22% | 50% | ~65% (per gun) | Can't go prone in mid-air. Your hitbox is long and low, and your head is out front |

Standing speed is 6 m/s walking and **13.5 m/s sprinting** (before your weapon's mobility, aiming and perks); stance percentages are of the walking speed.

**Sprinting costs accuracy.** While you sprint, and for 0.3 s after you stop (the penalty fades out), your spread is multiplied by a per-class factor: shotguns x1.5, SMGs and pistols x2, assault rifles x2.75, DMRs, snipers and LMGs x3 (special weapons x2.5). The crosshair blooms to match. Holding Shift while standing still doesn't count, and a fast walk (Lightweight, Head Start, Afterburner) isn't sprinting. You still can't aim down sights while sprinting (aiming stops the sprint). Steady Aim and attachments stay multiplicative with it (Steady Aim sprinting: x0.65 of the sprinting cone); stance and movement terms apply on top as before. It runs in the shared simulation, so prediction, the server and bots agree: the server widens a cone a client sends while sprinting to at least 75% of the honest sprinting hip cone (`Source/Game/SprintSpread.cs`, where the class factors live).

You can't stand up where there's no headroom (for example under a container roof); from prone you'll get up to a crouch if that's all that fits. Stance is part of the shared 60 Hz simulation, so prediction, the server and lag compensation (which rewinds stance as well as position) all agree. Bots crouch for long-range shots; Marksmen and Hard snipers go prone, and bots crouch-peek in close fights and duck behind low cover to reload.

### Grenades and equipment

The loadout has a **Grenade** slot (2 per life) and an **Equipment** slot (1 per life), both refilled when you respawn. Projectiles are simulated by the server: they bounce off walls and floors, and blasts are blocked by walls. Everything is thrown at 22.5 m/s (plus a little lift and half your own speed), which carries about **34 m** on flat ground at the best angle (about 40 degrees up); a frag thrown that far lands with a few tenths of a second to spare before it goes off.

### Ragdolls and blast knockback

When anyone dies (a player, a bot or a zombie) their blocky body goes limp as a **ragdoll** and falls the way the kill pushed it: along the bullet, harder for big-calibre and high-damage guns (a shotgun or sniper throws a body, a pistol nudges it), a headshot snaps the head back, a melee hit shoves the body away from the swing, and a grenade, exploding barrel or strike throws it from the blast. It keeps the speed it was running at. Bodies tumble over stairs, slopes, terrain, props and walls, settle, and stay for 14 s (zombies 7 s) before fading out; prestige hats either stay on or get knocked off (always on a headshot or a blast) and land on their side. Later blasts fling the bodies again, and loose debris from broken props too. Ragdolls are purely cosmetic: dead bodies never block bullets or movement, and each PC builds them from the kill message it already gets, so everyone sees about the same fall with no extra network traffic. At most 24 bodies (10 of them zombies) are around at once and 16 move at a time; resting bodies cost nothing but their drawing, which is a single instanced draw shared with the prop debris. Turn them off with the environment variable `CALLOFSLOP_RAGDOLLS=0` (the old flat corpse comes back). If your killer dies, the death camera turns to where their body ends up.

**Soft joints and a relaxed rest.** Every joint (neck, shoulders, elbows, hips, knees, the legs against each other, the arms against the chest) bends freely within a comfortable range; nearer its limit a spring pushes back, stiffening sharply towards the limit, with damping so nothing bounces or jitters, and a hard backstop just past the limit stops any bend that would break or turn a body inside out. Once a body slows down its limbs drift for a couple of seconds towards a relaxed pose (arms by the sides with the elbows a little bent, legs straight with the knees a little bent): never lifted against gravity, so a body lying on its back slides its arms in along the floor and settles like someone limp, not a mannequin. Shots push harder than before (about 1.75 times, up to 10 m/s for snipers and shotguns at close range) and land on the particle they hit, with some spread to its neighbours and a little lift, so an off-centre hit twists the body; blasts are scaled to stay above the strongest shots. Every number (where the soft range starts, the stiffness, its curve, the damping, the backstop, the relax pull, the push scale and cap, the blast scale) is in `Ragdolls/Ragdolls.json`, and the F7 weapon tweak window's **Ragdoll tuning** button opens a slider for each (live, on your PC only). `CallOfSlop --ragdoll-shots [map] [--ragdoll-legacy] [--ragdoll-only rifle,frag]` takes picture strips of seven deaths (pistol, rifle, sniper, shotgun, headshot, running, frag; `--ragdoll-legacy` with the old tuning for comparison) and quits.

**Near things fight back for a moment (active ragdolls).** When the killing hit only just did enough (it was less than 30 HP, or less than 30%, more than the health left), the body doesn't go limp at once: for 0.4 to 1.5 s (longer the nearer it was) soft "muscles" try to keep it up, and how depends on how it died: shot in the leg, that knee buckles and it sags onto that side; in the chest, it staggers back away from the shot clutching the wound (or folds over it); in an arm, it spins towards that side; a head hit that barely killed wobbles and topples; a melee kill staggers away from the swing with the arms up; burning, it flails; electrocuted (a zapped zombie), it jitters; killed at a run, it carries on into a forward stumble. A simple balance controller holds the torso up over the hips and steps a foot to catch the fall, and the muscles fade out smoothly so the body hands over to the limp ragdoll (anything still kneeling or sitting tips over). Big overkill (a headshot with plenty to spare, blasts, a point-blank shotgun, a sniper) stays instantly limp. The server puts the hit body part, the cause and the overkill in the kill message (and a dead zombie's in the zombie update), so every PC plays the same reaction, picked from the kill alone. At most 4 bodies are powered at once, 2 of them zombies (a horde's other kills go limp), and a legless crawler or slug only claws forward once. The reactions are a table in `Ragdolls/Ragdolls.json` ("reactions": when it applies by cause, hit region, running or legless; the lean, stagger, turn, support, balance, stepping, flailing and per-limb pose targets), so more can be added without code; the thresholds, times, caps and muscle strength are in its tuning. `--ragdoll-shots --ragdoll-only act_leg,act_chest,...` pictures each reaction.

**Explosions push the living too, and every survivor feels it.** Every blast shoves whoever it doesn't kill: frag grenades (11 m/s at the centre, out to 9 m), impact grenades (9 m/s, 6 m), every launcher (each weapon file's `launcher` `knockback`, or by default `5 + damage / 25`: about 11 m/s for the Mule RPG, 9 for the Carousel; cluster bomblets push with their share), landmines (12 m/s) and exploding props (9 m/s by default, a prop's `explode` block can set `knockback`), the Mortar Barrage (10 m/s per shell), the Hunter Drone (9), the Strafe Run (7), the gunship's rounds (6) and the napalm strike's bombs (4). The push throws you away from the blast **and up off the ground**, and falls off gently with distance (with the square root of what's left of the radius, down to 15% at the very edge), not in the straight line the damage uses: whoever survives a blast is near its edge, where a straight line left almost nothing. For about half a second after a push you're **staggered**: you can hardly steer in the air and your feet skid when you land, so the shove carries you instead of being walked out in a few frames. A frag 3 m away throws a survivor about 4 m and half a metre up; a near miss at the edge of a blast still hops you a metre or so. You feel it too: the camera shakes, the view kicks away from the blast and you stumble. Walls, floors and an enemy's Deployable Cover shield you exactly as they shield you from the damage. One push is capped at 12 m/s, Flak Jacket cuts it by 60%, going prone halves it, and a mantle isn't interrupted. Bots are thrown the same way and pick themselves up. The server moves you (it's authoritative, so it replicates like any movement), and tells your client exactly which input the push came after, so your own prediction shows the shove (and the stagger) the moment it arrives and never snaps back. **Teammates are never pushed by each other's blasts:** the game has no friendly fire, and a shove you can't stop would only be griefing; your own grenade does push you (grenade jumps), and strikes only push the caller's enemies, like their damage. Whoever a blast kills becomes a ragdoll thrown by it.

### Gibs and gore

**Animals burst.** Shoot, knife or blow up an animal prop enough and it bursts into a pile of meaty gibs: chunky red and pink meat, a few bone-white bits, and a puff of feathers (pigeons, chickens, ducks, the little bird on a perch), white wool tufts (sheep) or fur (cats, dogs, cows). Bigger animals take more and throw more: a pigeon goes in one rifle shot, a cat in two, a dog in two or three, a sheep in four, a cow in about nine (pigeons 20 hp and 10 gibs, a cat 45 and 12, a dog 60 and 14, a sheep 110 and 18, a cow 250 and 24). A grenade, launcher round, landmine, exploding barrel or strike within 60% of its radius gibs an animal at once. Flocks (Pigeons, the Duck Family) go as one. Toys never do: rubber ducks, the duck decoy, teddy bears and the bird bath are not meat. Animals give no kill, no XP and no kill feed line (only a line in the game log), and come back next match (or after the map's `respawn` time).

**Close blast kills burst too.** A player, bot or zombie killed by a blast right next to it (the killing hit did 80 damage or more, or 60 more than the health they had left: about the inner quarter of a frag grenade, the inner two fifths of a landmine, a rocket's direct hit) is blown apart instead of falling as a ragdoll: meat and bone plus their torso, head, arms, a hand, legs and boots in their own uniform colours, flung by the blast; a prestige hat flies off on its own and lands on its side. Napalm fire never gibs; a blast at the edge of its reach gives a normal ragdoll. The death camera follows the torso chunk.

Gibs bounce, slide to a stop, lie there for about 15 s and dither out; meat that lands leaves a small blood splat (it counts as a bullet impact, so the **Bullet impacts** setting has to be on). Later blasts throw them about again. Everything is built on every PC from the break or kill message it already gets (the same burst on every screen, no extra traffic), at most 320 pieces exist at once (the oldest go first), and they're drawn in the same instanced call as prop debris and ragdolls. **Settings > Video > Gore:** **Full** (everything), **Reduced** (about half the gibs, no blood), **Off** (animals just poof into feathers or dust; blast kills are ragdolls).

### Destructible buildings

On the **World Tour** maps (and the Dev pack's **Destruction Test**) buildings can be blown apart. Every wall is made of panels about 1 x 1.25 m (door and window openings kept), every floor and roof of 2 x 2 m slabs, and each panel has health by its material (`Materials/destruction.json`):

- **Explosives do the work.** Frag and impact grenades, launcher rockets, kill-streak strikes (mortars, strafe runs, napalm), exploding props (barrels, gas bottles, shell crates) and landmines break the panels in reach that the blast can see (a wall in front shields the one behind). A frag next to a plastered or wooden wall blows a hole in it; brick needs a rocket (or a few frags); concrete takes several rockets or a strike.
- **Bullets** only chip the weak stuff: wood and plaster give way after a magazine or so, tiles barely notice, brick, concrete and metal don't care. **Melee** knocks through wood and plaster in a few blows.
- **What's left has to stand on something.** Support runs up from the ground through the panels, and a little way sideways (each material has a reach: plaster about 2.5 m, brick 3.5 m, concrete 4.5 m). Take out the wall under a floor and the floor sags and drops in slabs; take out a storey and what's above comes down. The ground-floor corners of every building are load-bearing (they never break), so a building is never wiped off the map.
- **Falling slabs hurt.** A piece that comes down on you lands with its weight: a concrete floor slab from a storey up kills, a plaster panel stings. The kill goes to whoever brought it down.
- Holes are real: bullets, grenades and sight go through them, you can walk and mantle through, decals on broken panels vanish, doors and glass set in a broken wall go with it, and furniture on a fallen floor is gone. Bots find the new ways through holes (and stop walking on floors that fell).
- Everything is whole again at the start of every match. The host decides what breaks (online it's the same for everyone; a player joining mid-match sees the damage done so far). The host's **Destruction** checkbox (the lobby room's WORLD section) turns it off; Zombies never breaks buildings.

Map makers switch it on per map (`"destructible": true`, or per building) and can add `DestructibleBox` blocks: see [Maps/README.md](../Maps/README.md#buildings) and [Buildings/README.md](../Buildings/README.md#destruction).

### Sound

Every weapon has its own **gunshot, reload and equip sound**, synthesised when the game starts from the weapon's stats: calibre gives depth and thump, there's crack and echo, suppressed guns go *thwip*, and energy, pneumatic and toy guns get their own recipes. Real firearms then get **recorded gunshots** layered in (`Audio/Samples/Guns`, from The Free Firearm Sound Library, CC0): each class picks a set of recordings from 2-3 real firearms (light and heavy pistols, SMGs, rifles, heavy rifles and LMGs, DMRs, lever-actions, bolt-action snipers, the .50 and the musket, pump and heavy shotguns), pitched by the weapon's calibre, trimmed by its tail, blended with the start of its own synthesised shot (crack, thump, mechanism) and matched to the synth's loudness. Shots are **snappy**: the recordings are cut right on the blast (no pre-roll), the crack is sharpened, the body is dry and short, and the limiter is held back so the transient stays sharp (the distant layer keeps the long tail). **No two guns sound the same**: every weapon has its own sonic identity derived from its name and stats (same on every client): which recorded firearms it mostly plays, a pitch offset, tone, body resonance, crack, mechanism click, synth blend and dryness (see `Weapons/README.md`, "voice" block to pin any of it; the log's `[gunvoice]` lines list them); barrel and muzzle attachments colour it a little more. Each shot picks one of its 4 variants at random with a small pitch and gain jitter. Suppressors muffle the recording under the synthesised *thwip*, and the distant layer blends in a mid-distance recording. If the sample files are missing the synthesised sounds are used, and the log's `[gunsamples]` lines say which set every weapon uses. Reloads follow the weapon type (mag swap, shell-by-shell plus pump, bolt, belt box). There are also hit, headshot, kill, hurt, death and respawn cues. Other players' shots and reloads are positioned in **3D** with OpenAL, so you can hear where people are.

- **Hits.** A body hit gives the shooter a dull flesh *thwack* with a short tick; a **headshot** is a meaty crunch (a bone-crack transient, a wet low thump, a squelch and a gritty tail) under a bright hitmarker ping, and a headshot kill adds a bell-and-boom accent on top of the kill sound. Hitting a turret or drone pings metal. Hitting a **teammate** (team modes and Zombies co-op, where it does no damage) gives a muted low *bonk* with a soft falling double beep instead, quieter than an enemy hit. Everyone else hears flesh hits and headshot crunches **in the world**, quieter, where they happened. Every hit sound has three variations, picked at random.
- **Footsteps** for every player, local, remote and bots. They follow the leg animation's gait (the same cadence: about 7 steps a second at walking speed, 10 at a sprint, and locked onto the drawn legs' foot plants when they're on screen), so a step sounds as a foot lands. Sprinting is loud and heavy and carries about 45 m, walking is soft (24 m), crouch-walking is nearly silent (6 m) and prone crawling is a cloth-and-grit scuffle. Nothing in the air; a jump has a push-off, and a landing thuds harder the faster you fell. The surface comes from what's under the foot: the terrain's painted material (grass, dirt, sand, rock where it's drawn as cliff, and snow on pale ground), a box's texture (concrete, brick and tiles sound like concrete; wood; metal; earthy and grassy hills), a prop's parts (a wooden crate is wood, an oil drum is metal) and movers (metal). Each surface has 4 walk and 4 run variations, played with pitch and volume jitter. Other players' steps are positional (important information: you can hear someone sprinting round the corner); your own are quieter. Footsteps have their own **12 voices**, so 32 running players can't take the voices the gunfire needs: a new step takes a free voice, else the farthest one if it is nearer, else it is dropped.
- **The gun mix** (`Source/Audio/Audio.GunMix.cs`). **Your own gun is the loudest thing you hear**: it plays at full gain (OpenAL's per-source cap, so the baked peak never goes past it), and another player's shot plays about **7.5 dB quieter** up close. With distance another player's shot follows one inverse-distance curve (from 5 m, about 5 dB down per doubling, still falling at 250 m) and crossfades at equal power into a level-matched **distant layer** from 25 m to 90 m: a mid-heavy report (a softened crack, a band-limited blast, a small boom and a long rolling echo; the recording's tail is high-passed), so far gunfire never gets louder than nearer gunfire. Measured offline through the same mixing path (the self-test's **Gun mix** section, median of the 42 real firearms, K-weighted loudness against your own shot): another player's shot is -7.5 dB at 5 m, -16 dB at 15 m, -23 dB at 30 m, -30 dB at 60 m, -33 dB at 80 m, -35 dB at 100 m, its energy below 150 Hz falling from 10% to 1% while the part above 2 kHz (the crack you place it by) stays about 10%. (Before: an enemy within 6 m was 2.5 dB *louder* than your own gun, and from 60 m on the bassy distant layer, 70% of it below 150 Hz, came out as loud as your own shot.) Suppressed shots stay about 18 dB under open ones far away. Explosions are untouched (a frag 15 m away is about 19 dB over a rifle fired from there), and launchers keep their place over rifles. Those are the voices as tuned (every mixer level at 0 dB). The default mix (SeabMix2, see Audio mixer) adds its levels on top: your own shot leads another player's at 5 m by about 13.4 dB, another player's shot is about -42.5 dB under your own at 80 m, a frag 15 m away is about 25 dB over a rifle there, and the launchers (left at 0 dB) sit about 10 dB under your own rifle.
- **Distance.** Bullets passing within 3 m of you **whizz**, or **crack** for rifles, DMRs, snipers and LMGs. Shots hitting the world make an **impact** by surface (concrete chips, a metal ping, a wood thunk, a dirt puff), sometimes with a **ricochet** off metal, concrete and rock. Breaking props have three variations each.
- **OpenAL EFX** (part of the OpenAL binding) is used when the device passes a start-up canary: positional sounds lose their air with distance (a high shelf), and gunshots also lose their boom (a band-pass filter's low shelf: about -5 dB below 250 Hz at 30 m, -13 dB at 60 m), and every sound gets a light reverb send that suits the map: open terrain, urban streets, or a stony room for maps that are mostly roofed over. Without EFX everything plays dry, as before. The log's `[audio]` lines give the number of sounds, synthesis time, EFX and HRTF status, and once a minute in a match the sounds played, footsteps dropped by the voice cap and CPU per sound.
- **Settings > Audio**: **Effects volume** (everything but music), **Own gun volume** (your own gunshots and their frenzy layers, on top of the effects volume; 1.00 is the tuned mix above) and **Footstep volume** (on top of the effects volume), all default 1.00, saved as `effects_volume`, `own_gun_volume` and `footstep_volume` in `settings.txt`; older settings files load with the defaults. Each slider has a Test button.
- **Building has sounds** (Sandbox): a soft tick as a ghost locks onto a socket and another as it turns, a clunk when a part lands (a click to a deep thud with its mass, flavoured metal, wood, stone or rubber), the attach tool's arc and the attach tool's ratchet while a part goes on, unbolts and pops, link clicks, a short soft "no" on a refused click, and small physics gun cues. Other players' building is positional, and a big paste is a short rattle. Mixer row: *Building* (see Audio mixer; docs/sandbox/CONSTRUCTS.md "Building sounds").

### Audio mixer

A debug window for tuning the game's sound landscape: a level slider for every kind of sound, so you can try different balances and send the result to the developers.

**Opening it:** press **F8** (rebindable in Settings > Controls as *Audio mixer (debug window)*) or click **Open audio mixer** in **Settings > Audio**. It works in the main menu, in the lobby and live in a match. In a match the mouse is freed while it's open; F8 or Esc closes it and gives the mouse back to the game. It only changes what *you* hear, never anyone else's game. While it's closed it costs nothing (no meters run).

**What's in it:**
- **Levels** in dB (-50 to +50; Ctrl+click a slider to type a value, Ctrl+wheel moves it 0.5 dB, Ctrl+Shift+wheel 0.1 dB), each with a **mute** box, a **reset** button (R), its **default** and a live **meter** (RMS bar, peak line, peak-hold tick) with the number of sounds playing. 0 dB is the sound as tuned; the built-in defaults are the *SeabMix2* mix (see below), so some rows start boosted or cut, and **R** / **Revert to defaults** go back to it. A boost really applies (+20 dB is 10x, +50 dB about 316x): each sound's OpenAL cap rises with it, and boosted music goes through the music limiter instead of clipping. The output itself can't go past full scale, so watch the **CLIP** light when you push levels up. The rows, by group:
  - *Master*: everything, on top of Settings > Audio's master volume.
  - *Guns*: own gun; own gun suppressed; other players' guns (near layer); distant gunfire layer / tail; other players' suppressed guns; the frenzy gun-sound layer; reload / equip / dry fire.
  - *Launchers*: own launcher; other players' launchers and rocket motors; lock-on tones / detonator.
  - *Explosions & impacts*: explosions (grenades, rockets, props, kill streak blasts, landmine blasts); bullet impacts and ricochets; bullet whizz / crack-by; breaking props, doors, glass; gore / gibs squelch; body hits heard in the world.
  - *Hit feedback*: hit marker; headshot; kill confirm; friendly-fire marker; hurt / death / shield. (A wallbang hit plays the normal hit marker sound: its extra ticks are visual only.)
  - *Movement*: own footsteps; other players' footsteps; own jump / land / prone; others' jump / land / prone; melee.
  - *Gear & streaks*: tactical gear; the landmine click; kill streaks; zombies (everything zombies make); zombie voices and zombie footsteps (each on top of the zombies row, 0 dB by default; zombie footsteps also follow Settings > Audio's footstep volume); co-op enemies (an extra level on top of the gun rows for Co-op mission soldiers).
  - *UI & notifications*: UI / menu clicks; notifications (level up, streak ready, mode events; there is no announcer voice).
  - *Voice chat*: other players' voices, on top of Settings > Audio's voice volume and each player's volume. Its meter is measured from the voice frames as they are queued (boost and all).
  - *Music*: menu music; lobby music; kill frenzy levels 1 to 6 (a live match has no other music).
- **Distance (gun mix shape):** gunshot reference distance, rolloff (with the resulting dB per doubling shown), max distance, distance bass cut and its floor, air absorption (treble loss) and its floor, the near/distant crossfade start and end, and the music limiter ceiling for the frenzy (with its deepest gain reduction so far).
- **Master out (est.):** the estimated total level with a **CLIP** light, the number of voices playing, and the frenzy limiter's headroom. The effect meters are estimated from each sound's gain and envelope (OpenAL mixes them); the music is measured.
- **Test sounds** (choose a weapon, or your current one, and a direction): your own shot; an enemy shot at 5 / 30 / 80 m; an explosion at 15 m; gibs; a zombie groan and a zombie sprinter's step at 8 m; footsteps (yours, an enemy's at 10 m, a landing); hit marker, headshot, kill and friendly-hit sounds; and **Preview frenzy**: forces the kill-frenzy music and your gun's frenzy layer to level 0-6 for 5-60 s, in the lobby too.

**The default mix (SeabMix2):** since 2026-10-23 the built-in levels are the user's own mix: own gun +20 dB, other players' guns +14.1 dB (near layer) and +10 dB (distant layer), explosions +20.1 dB, bullet whizz +12.3 dB, breaking props +5 dB, gore +7.3 dB, body hits in the world +3.9 dB, hit marker +8.4 dB, headshot +15.7 dB, kill confirm +13 dB, hurt / death +10 dB, own footsteps -8 dB and other players' footsteps -4.1 dB. Every other level is 0 dB and the distance values are unchanged. Every player gets it with no `audio_mix.json`. The boosts are heard in full (each sound's OpenAL cap rises with its bus), so the output runs hot in a firefight and the CLIP light shows it; turn Settings > Audio's master volume down if it's too loud for you.

**Saving your mix:**
- **Save** writes `audio_mix.json` in your save folder (next to `settings.txt`; it carries over to new builds). It's loaded every time the game starts. **Load** reads it back, **Revert to defaults** goes back to the built-in mix (Save afterwards to keep that).
- Type a name and **Save as...** to keep named presets in `AudioMixes/` (in the save folder), then pick one and **Load preset**.
- **Copy to clipboard** copies the whole mix as JSON: paste it in a message to send it to the developers.
- The file is plain JSON: `version`, the `game` build, the time it was `saved`, then every level by key (`"gun.own": {"db": -2.5, "mute": false, "default": 0}`) and every distance value by key. Missing keys keep their default, unknown keys are ignored and out-of-range values are clamped, so files from older or newer builds still load. A level still at the `default` saved next to it, when the built-in default has changed since, loads as the new default: a file saved before SeabMix2 became the default keeps every level you moved and gets SeabMix2 for the rest (a level you set back to exactly its old default counts as untouched; a level without a saved `default`, such as a hand-edited bare number, loads as written). Delete the file to go back to the defaults. The tester package (`tools/package.ps1`, `Package.bat`) never includes it.

**For developers (baking a mix in):** every default lives in one table, `Source/Audio/AudioMixDefaults.cs`, under the same keys as the JSON. To make a player's mix the game's own, copy each `db` (and each distance value) from their file into that row's default, set `BakedMix` to its name and update the expected table (`BakedLevels`) in `SelfTestAudioMixer.cs`. Old saves then move their untouched levels to the new defaults on their own (above). The self-test checks that with no `audio_mix.json` every sound plays exactly as before the mixer existed times its default level (shot layers, falloff, crossfade, distance filter, music trims), that each boost passes the per-voice cap in full, and ("Gun mix") that your own shot still leads another player's at 5 m by at least 6 dB with the default levels (+13.4 dB with SeabMix2, +7.5 dB for the voices as tuned).

### Weapon tweak window (dev)

A debug window for balancing weapons live: change any stat of any gun while you play, see what it does to the time to kill, and save the numbers you like into the weapon files.

**Opening it:** press **F7** (rebindable in Settings > Controls as *Weapon tweaks (debug window)*). Dev builds always have it; a release build only with **Settings > Graphics > Allow the weapon tweak window**. It works in the menus, in the lobby and live in a match; like the Audio mixer it frees the mouse, and F7 or Esc closes it. Closed, it costs one check a frame.

**What's in it:**
- **The weapons by class** on the left (`Weapons/<Class>/*.json`); a changed weapon is orange with a `*`.
- **Weapon tab:** every stat its file holds as a slider, grouped as Damage, Handling (fire mode, rate, burst, magazine, reload, spread, recoil scale, mobility, zoom, equip and aim times), Penetration, the `recoil` block and (launchers) the `launcher` block. Each row shows the file's value (and the live one when a class multiplier changes it) and a reset button (R). The sliders cover a sensible range; Ctrl+click types any value the weapon file allows (the `Weapons/README.md` ranges). Look and sound numbers (length, bulk, accent, caliber, bright, tail) and the model and voice blocks aren't in it: they're baked into meshes and sounds at start-up. **Revert this weapon** drops its own changes.
- **Class multipliers tab:** damage, fire rate, recoil, spread, range, reload time and mobility multipliers (x0.25 to x4) for the picked weapon's class, applied on top of every weapon of the class (and of its own changes; whole numbers are rounded, the file ranges still clamp). **Revert class** sets them back to 1.
- **Feel numbers** over the tabs, live and (when changed) as the file has them: DPS, shots to kill, and time to kill at 5, 15, 30 and 50 m (against full health, body shots, every pellet landing, reloads counted), plus head shots to kill.
- **Infinite ammo** (host only, any mode): players' guns (not bots') never run dry or reload, and grenades and equipment are never used up, for testing explosions and craters. Clients follow the host's setting; it is off in each new game.
- **Save to weapon files** writes every changed weapon's live values into its file: in the game's `Weapons` folder and, in a dev build run from the repository, the repository's `Weapons` folder too. Only the changed values' text is replaced (a missing key is added after the key before it, a missing `recoil` block is added), so the file keeps its layout and a diff shows just those numbers; each new text is loaded back first and must read as exactly the tweaked weapon (so `--check-weapon` passes). The saved values are the new baseline: the window shows nothing changed afterwards. **Reset all to files** drops every change.

**What it never touches:** nothing is saved until you press Save; until then the weapon fingerprint (what decides who can join whom), attachment fits and unlock XP all go by the files, and progress and loadouts are untouched. After a Save the fingerprint follows the new files, so friends need the same files to join.

**Multiplayer:** only the host can change values; on a client the window is read-only and shows the host's. Every change goes to every player (Msg.WeaponTweaks, protocol 60; at most 10 updates a second while a slider is dragged), a joining player gets the current set (the host sends the live numbers wherever they differ from the files as it loaded them, so this also covers values saved during the session), and a client's weapons go back to its own files when it leaves. While the weapons differ from their files the scoreboard says **TWEAKED WEAPONS**. Code: `Source/Weapons/WeaponTweaks.cs` (state, apply, save), `WeaponFilePatch.cs` (the minimal file edit), `Source/UI/UiWeaponTweaks.cs`, `Source/Game/GameWeaponTweaks.cs`.

### Weather

Maps with a `weather` section (the Dev map **Streamed Terrain** has one) run a weather simulation round the map: the
clouds in the sky come from it and drift with its wind, and tropical storms form over the warm sea to the south-east,
grow into hurricanes (with an eye and spiral rain bands), move west and die over land, or turn north-east into the
westerlies. Weather runs fast: an hour of it a second by default, so a storm's whole life takes a few minutes. When one
passes over you the sky clouds over and darkens.

Press **F11** (rebindable as *Weather map*) for the weather map: the region from above (satellite view or rain radar),
every storm with its class, wind, pressure and heading, where you are, the weather over you, and the time speed
(paused to 6 hours a second). Right-click the map, or press **Seed a storm**, to start a tropical depression there.
F11 or Esc closes it. Each PC runs its own copy from the map's seed (not synced between players yet). Design and
numbers: docs/weather/WEATHER.md.

### Story window

Sandbox keeps a story of what happens in a world: who joined, who killed whom, whose construct was wrecked, stripped or
towed, who launched, jumped and discovered what. Patterns over those events (in `Story/Patterns/`) spot stories as they
happen: a score settled, vultures stripping a wreck, a good turn returned. The story is saved with the world.
It can also hold people with a mind of their own: they have needs, choose goals, plan with the same verbs as players,
gossip about what they see and hold grudges about what they hear (`Story/People/`, casts in `Story/Casts/`). Those in

### Performance window

**Opening it:** press **F9** (rebindable in Settings > Controls as *Performance window*). Each press cycles: the full window, a small corner overlay, off. It works everywhere: the main menu, the lobby, every mode, host or client, and release builds. The full window frees the mouse like the Audio mixer (Esc closes it); the overlay leaves the mouse to the game.

**What it shows:**
- **Frame time** for the last ~10 s (600 frames) with guide lines at 16.7 ms (60 fps) and 33.3 ms (30 fps); fps, min / avg / max and the 1% low (the average of the slowest 1% of frames) over the graph, and the three worst frames marked in red with how long ago they were.
- **CPU by area per frame**, stacked in colour under the frame-time line (the gap up to the line is time outside every timed area), and the **server tick** graph: the slowest tick in each frame against the 8 ms budget.
- **CPU tree** (main thread, over the last second): average, self (minus its children) and peak ms per frame for each area: events, input, the game update (net receive, the host's ticks: match and mode, Zombies and its horde, Co-op, projectiles, props / logic / destruction, player moves, bots and nav, snapshots; a client's prediction; frame state and sounds), audio, every render pass (buildings, terrain, props, meshes, foliage, decals, sky, players, entities, effects, view model, HUD, ragdolls), the ImGui UI (ImGui's new frame, the HUD windows, menus, dev windows, this window itself, and ImGui's draw), the swap (waiting for vsync or the GPU) and loading (map switches, the collision world build). Sort it as a tree, by average or by peak. The music thread's mixing time is shown beside it.
- **GPU passes:** the same render passes timed on the GPU with timestamp queries, read back a few frames later so it never stalls; "unavailable" on a driver without timer queries. Each pass is stamped where it starts and where it ends, and the time between passes has its own line ("between passes"): in a CPU-bound frame the GPU finishes what it was given and waits for the CPU, and that wait used to be billed to the next pass. Reading a query back (glGetQueryObject) makes most drivers submit the commands so far, which can start such a wait right there, so no renderer should read its timer inside a timed pass. The sky's own timer did, so the Sky row could take in the CPU time of the horde drawn after it (the likely reason it read 0.85 ms on the developer's PC and 3.2 ms on a tester's on Horde Stress). "Empty (timer check)" is an empty pass just before the sky: it should read about 0; if it doesn't, the per-pass times are off on that driver.
- **Counters:** draw calls, triangles and instances per frame (the 3D renderers; ImGui isn't counted), bytes allocated per frame (main thread and all threads), frames with a garbage collection per generation, the managed heap and working set, players and bots, zombies by speed, co-op soldiers, props (broken), decals, ragdolls, projectiles, tracers, blasts, smoke; online also network in / out per second, snapshots per second and their average size, and ping (client).

**Buttons:** **Pause** freezes the graphs; **Copy snapshot** puts all of it as text on the clipboard (paste it into a bug report); **Write to log** writes the same text to `callofslop.log` as `[perf]` lines; **Corner overlay** switches to the overlay (fps, a small frame graph, the three busiest areas, GPU time, the tick and draw calls).

**Cost:** closed, each timed area is one check of a flag and nothing is recorded but the frame time; open, each area costs two clock reads (tens of nanoseconds on Windows), nothing allocates per frame (the working set is read once a second), and the GPU timer makes no queries until the window first opens. Code: `Source/Perf/` (`Perf.cs` the scopes and history, `PerfGpu.cs` the GPU timer, `PerfCounters.cs`, `PerfStats.cs`), `Source/UI/UiPerf.cs`, `Source/App/Program.Perf.cs`; self-test section **Perf window**. `CallOfSlop.exe --perf-shot` plays a short single-player match, screenshots the window and the overlay (`smoke_perf_window.bmp`, `smoke_perf_overlay.bmp`, full size) and logs `[perf-shot]` lines, then quits (throwaway save copy, like the smoke test). `--perf-shot "Map" [--stress-size N]` plays that map instead (a Zombies map in Zombies with no bots; Horde Stress at N zombies). `--perf-hold S` keeps the window up S seconds instead of 5; while it is up, every frame over 2 ms (or with the UI over 1 ms) is logged as a `[perf-spike]` line with the areas and UI parts that took the time, and a closing `[perf-shot]` line gives the frame and UI medians, p99 and the peak of each UI part.

**ImGui's own cost** (2026-10-29): the UI's frame start skips the GLFW backend's per-frame monitor scan (two display-driver calls per monitor every frame on Windows, X server round trips on Linux; `Source/UI/UiPlatformFrame.cs`), and ImGui is drawn by `Source/UI/ImGuiRenderer.cs`, which never reads GL state back (the package's renderer made about twenty glGet calls a frame, each a wait for the driver thread with a threaded driver) and uploads all vertices in one go. `--imgui-backend-frame` and `--imgui-backend-draw` bring back the package's versions, to compare. Self-test section **UI frame spikes** runs headless ImGui frames with the HUD and this window and fails (on Windows, CPU time) if any frame costs far more than the median.

**Allocations per frame.** Steady frames should allocate nothing on the main thread (the GC then never pauses play). `CallOfSlop.exe --alloc-frames "Horde Stress" [--stress-size N] [--frames 300] [--warmup 300] [--views closed,window,overlay]` plays the map, waits for the warm-up frames, then for each perf view runs that many frames and logs `[alloc-frames]` lines: bytes per frame on the main thread and all threads, the GC counts, the bytes each perf area allocated itself (`Perf.TrackAllocs`), and the game's finer sections (`AllocProfile` marks). It counts frames, not seconds, so a slow software-GL box measures the same frames as a fast PC (in the container: under `xvfb-run` like `--light-shots`). `--alloc-types` adds the runtime's allocation-tick events by type and thread (one per ~100 KB). As a host and a client on one machine: start `--alloc-frames "Horde Stress" --alloc-host --alloc-humans 2 --alloc-stay --no-upnp`, then a second copy with `--alloc-frames "Horde Stress" --alloc-join 127.0.0.1 --no-upnp` (its log is `alloc-client.log`); `--alloc-spectate` measures a dead player's frames, `--alloc-warmup` the warmup. Self-test section **Frame allocations** draws the HUD and the perf window headless over a loopback host and client on Horde Stress and fails on any steady allocation. For text that has to be a string every frame, use `TextCache.Of($"...")` (`Source/UI/TextCache.cs`); text going straight into an ImGui call is free as a plain `$"..."` argument, but not through a `?:` between two `$"..."` (that makes a string).

### Look-at inspector and prop editor (dev)

Two tools for testers reporting problems with models: name exactly what you're looking at, and fix a prop on the spot and send the fix. Dev builds always have them; a release build only with **Settings > Graphics > Allow the dev tools**. Closed, they cost a few checks a frame and allocate nothing.

**Look-at inspector:** press **F6** (rebindable as *Look-at inspector*) in a match. A panel names what the crosshair is on, with its outline drawn over the world: a prop's name, file and the part you're on (part number, size, offset, rotation, colour, material, glass / glow, its `anim` type, axis, rpm and pivot), the placed copy's position, yaw and scale; a building's file, shell box number and whether it's a door or window glass; a plain map box's corners; or the terrain. It also names the **map op** that made it (`op #8 PlaceProp`, numbered from 1 in the map file's `ops` list, as the map loader's error messages count), the hit point and the surface normal. Things no single op made (foliage, Clutter, the boundary) say so. Part and box numbers count from 1, like the prop loader's messages (`part #3`).

**Copy reference:** **F5** (rebindable as *Copy the look-at reference*) puts one short line on the clipboard for a Playtest Desk report, and works with the panel closed too, e.g. `Animated Props / Props/Animated/Anemometer.json "Anemometer" part #8 of 12 (anim spin y 90 rpm) / Maps/Dev/AnimatedProps.json op #8 PlaceProp / at (-33.8, 1.6, -61.4)`. The same text reads well dictated.

**Prop editor:** point at a prop and press **F10** (rebindable as *Prop editor*; offline or hosting only, F10 or Esc closes it). It edits that prop live:
- **Placed prop:** position, yaw and scale of the copy you pointed at.
- **Parts:** pick a part in the list (outlined in blue in the world); change its size, offset, rotation, colour and material; **Add box**, **Duplicate**, **Delete**. Parts a prefab copied in with `use` are shown but not editable (edit the used prop).
- **Animation:** the axis (x, y, z, -x, -y, -z), pivot and rpm (spin) or angle (swing); with *Change every part with the same anim block* on, a rotor's parts change together (the Animated Props map's wind sensor fixed in one click).
- **Undo / Redo**, **Revert all**. Every edit is loaded with the real prop loader as you make it: a bad one (a zero size, a part sunk too far into the ground) is refused with the loader's reason and leaves the prop as it was.

What you see is a preview on your PC only: every copy of the prop on the map changes, collisions stay as the map built them, and leaving the map puts everything back. Nothing is written until **Save package**, which never touches a shipped file: it writes a change package to `DevEdits/<yyyyMMdd-HHmmss>-<Prop>/` in the save folder (**Open folder** shows it), with
- `edit.json` (format `call-of-slop-devedit/1`): the game build, map and map file, prop and prop file, the SHA-256 of the prop file it started from, your note, `propChanges` (every changed value: `{"path": "parts[2].anim.axis", "from": null, "to": "z"}`), `mapOps` (for a prop placed by a Prop op that you moved: the op number and the op `before` and `after`), and `placement` (the new position in world coordinates for a prop no single op placed);
- the whole edited prop file at its own path (`Props/Animated/Anemometer.json`): copy it over the original to apply it;
- `README.txt`, the same in words.

Zip the folder and attach it to the Playtest Desk report. `CallOfSlop.exe --check-devedit <folder>` checks a package (or a folder of them): the prop file loads under the prop's name, each map op patch still matches the map file's op and the patched map loads. The `DevEdits` folder is not a save (never migrated, never in the tester zip).

### Text chat and voice chat

**Text chat** works in matches, warmup and the results screen, and it is the same chat as the lobby room's (same history, same limits).
- **Enter** opens a chat line to everyone, **Y** to your team (both rebindable: *Chat (all)*, *Chat (team)*). While you type, the game controls (moving, shooting, looking) are suspended; Enter sends, Esc cancels. The chat box sits bottom-left above your health: new lines show for 8 seconds and fade; while typing you see the whole history (the last 50 lines).
- Lines are coloured by team (or the player's colour in free-for-all); team chat is tagged **[TEAM]** and only your team gets it (in co-op Zombies that's everyone; in free-for-all team chat isn't sent and you get a hint). A dead player's lines in a live match are tagged **[DEAD]**; the host's **"Dead players' chat reaches only the dead"** (the lobby room's LOBBY AND CHAT section) keeps them from the living. Joins and leaves appear as system lines. Bots don't chat.
- Limits (checked on the server, never trusting the client): printable ASCII, at most 120 characters, 4 lines at once then one every 1.5 s, team chat included.

**Voice chat** (Settings > Audio, *Voice chat*):
- **Your microphone is off until you tick "Use my microphone"**: nothing is recorded or sent before that, and the mic device is only open while it is ticked (or while you test it). Hearing others is on from the start; *Mute all voice* turns every voice off.
- **Push to talk** (hold **X**, rebindable) or **Voice activation** with an adjustable level (the meter shows your level and the threshold). Pick the **Microphone** (or the system default), and **Test mic** plays your voice back through the codec (use headphones). **Voice volume** sets other players' voices, from 0 to **300%** (100% by default). Above 100% the boost goes on the voice samples themselves (OpenAL caps a sound's gain at 1 on most systems) through a limiter, so a loud talker turned up doesn't distort; proximity fading and the mixer's *Voice chat* row still apply on top.
- **Voice: Proximity / Team radio / Off.** *Proximity*: everyone within **40 m** hears you from your head's position, fading with distance (full volume within 3 m, silent at 40 m) and muffled through walls (a ray between you; the EFX low-pass and a quieter level). *Team radio*: only your teammates hear you, at any distance, flat (not positioned), through a telephone-band "radio" filter. *Off*: you neither send nor hear voice.
- **The dead** (in a live match) hear and talk to the other dead, flat, plus team radio; the living don't hear the dead's proximity voice and the dead don't hear the living's (no calling out positions from the grave). In the lobby room and on the results screen everyone hears everyone, flat.
- **Indicators**: a speaker icon next to a talking player's name tag, "<))" after their name on the scoreboard ("(muted)" when you muted them), and a mic icon with TALKING / TEAM RADIO at the bottom of your screen while you transmit.
- **Mute someone, or turn them up or down**: Esc > **PLAYERS (mute)** lists everyone with a *Volume* slider (0-300%, on top of Voice volume), *Mute voice* and *Mute chat*. Volumes and voice mutes are remembered by player name (`settings.txt`, `voice_player` lines); chat mutes last this session.
- **Host**: *Allow voice chat* (the lobby room's LOBBY AND CHAT section, on by default) turns relaying off for the whole server.

How it works: the microphone is read through OpenAL capture (the BRUTAL binding's `Alc.CaptureOpenDevice` / `CaptureDevice`, no extra packages) at 16 kHz mono. No Opus is available, so voice uses **IMA-ADPCM** (4 bits a sample, 64 kbps) in **20 ms frames** of 164 bytes, each starting with the coder state so a lost frame never breaks the next; a DC filter and a soft noise gate run first. Frames go to the server as plain unreliable packets with their own sequence numbers (RakNet's unreliable-sequenced channel would make different talkers' frames, and the game's snapshots, drop each other), about **8.2 KB/s per talker**. The server rate-limits each talker (55 frames/s) and each listener (about 6 talkers at once), routes every frame by the rules above, and relays it only to the players who should hear it, never back to the talker. Each listener has a **jitter buffer** per talker (60 ms, growing to 100 ms on a jittery connection) that puts frames back in order and conceals a lost one by repeating the last frame more quietly; 8 streaming OpenAL sources play the talkers at once. The voice path allocates nothing per frame and costs a few microseconds a frame. Protocol 36.

**Trying voice with friends**: everyone ticks *Use my microphone* in Settings > Audio (Test mic first: you should hear yourself), one person hosts, the others join; hold X and talk. Stand within 40 m to hear each other in Proximity, or pick Team radio in a team mode to talk across the map; walk behind a wall to hear the muffling. The log's `[voice]` lines say which microphone opened and, once a minute, frames sent, played and concealed (and on the host, relayed).

- **Kill frenzy music** (in matches): as you chain kills, a hardbass track fades in and gets harder the more kills you get and the faster you get them, then fades out after a while without kills. Each kill adds *heat* (8, plus up to 14 for a follow-up within 3 s, tapering to nothing after 12 s; +2 per link of a multi-kill chain of kills under 5 s apart, up to +8; +3 for a headshot; max 240). Heat bleeds slowly (3%/s) for 8 s after the last kill, then drains (6%/s plus 2/s). Heat 12 / 28 / 48 / 72 / 120 / 185 reaches **level 1-6** (left again below 8 / 22 / 42 / 64 / 110 / 170). It depends only on how fast you kill, not on the lobby or map size, and is tuned for the pace a strong player keeps on a small 8v8 map (a kill every 4-8 s during a streak), so the top levels are reachable in small lobbies too:
  - **Level 1**: only the drums and bass, behind a closed low-pass filter (380 Hz) and quiet: the club through the wall.
  - **Level 2**: the filter opens: the full beat, claps, hats and the bouncing off-beat bass.
  - **Level 3**: the leads, harmonies, pads and chants come in.
  - **Level 4**: full volume, and the track jumps to its **last drop** (the later lead sound, reverse bass, crash and sub drop).
  - **Level 5 - FRENZY**: louder: the frenzy normally sits at 0.75 of the menu music's level, here it's as loud as the menu music (1.33x level 4), and your gunfire ducks it only half as much (15% instead of 30%). It also plays **faster** (see the tempo note below). A green **FRENZY** banner (the perk-banner style) shows when it's reached.
  - **Level 6 - MAX FRENZY**: as loud as everything else in the game, if not slightly louder: with the sliders at their defaults the music's drop comes out at least as loud as (about 1.05-1.1x) a second of your own gun firing with a frag explosion on top (measured from the game's own sounds, recorded gunshot layers included: the median over the 42 real firearms is about 0.46 RMS at effects volume 1; gunfire alone about 0.19 (the snappy, dry gunshots at your own gun's full gain), the explosion 0.42), the gunfire doesn't duck it at all, and it lands with a crash and a crowd roar plus a **MAX FRENZY** banner. It plays **faster again** than level 5. The music bus goes through a look-ahead limiter (ceiling 0.96) while the frenzy plays: at level 6 it's already working at the default sliders (the music is pushed 1.2x above the reference into it), and nothing clips even with the music and frenzy sliders at 1. Note that at this level the music is as loud as your gunfire by design; the music and frenzy volume sliders still scale it down.
  - A quick double kill starts level 2, a triple kill level 3, four quick kills level 4; a single kill never starts it. Kills needed per level (no headshots; headshots get there a kill or two sooner):

    | A kill every | L1 | L2 | L3 | L4 | L5 FRENZY | L6 MAX FRENZY |
    |---|---|---|---|---|---|---|
    | 1 s | 2 | 2 | 3 | 4 | 6 | 8 |
    | 2 s | 2 | 2 | 3 | 4 | 6 | 9 |
    | 3 s | 2 | 2 | 3 | 4 | 6 | 10 |
    | 4 s | 2 | 2 | 3 | 5 | 7 | 13 |
    | 5 s | 2 | 3 | 4 | 5 | 8 | 23 |
    | 6 s | 2 | 3 | 4 | 7 | never | never |
    | 8 s | 2 | 3 | 6 | never | never | never |

    So a good streak (a kill every 4-6 s) reaches level 4-5, a great one (every 3 s) MAX FRENZY in about 10 kills, and a kill every 12 s or slower never starts it. After a burst to level 4, it holds about 11 s, then eases down (level 2 at about 16 s) and is gone after about 26 s; after a maxed-out spree level 6 holds about 9.5 s, level 5 until 15 s, level 4 until 22 s, and it's gone after about 36 s. (Before 2026-10-22 the higher levels needed a kill every 1-2 s: level 6 took 15 kills a second apart and was out of reach at a kill every 2.5 s or slower, level 5 at 4 s or slower.)
  - Changes land on the **bar line** and crossfade: up within half a bar, down one level at a time (at most every two bars, over two bars), levels 6 and 5 included. Drops loop, so it never falls into a breakdown. **Dying** fades it out over 2 s with the filter closing, and it never plays in the death cam, menus or lobby. Your own gunfire ducks it a little (levels 1-4), and up to level 4 it sits under the menu music's level so the game stays on top.
  - **Tempo at levels 5 and 6**: levels 1-4 play the track at its own BPM; level 5 speeds it up and level 6 more, by multipliers per weapon class (the `"tempo": { "level5", "level6" }` of each class's `"music"` section: Pistol and Assault Rifle x1.10 / x1.20, SMG x1.12 / x1.25, DMR and Sniper x1.08 / x1.16 (the marching drums and braams keep their weight), Shotgun x1.10 / x1.22, LMG x1.08 / x1.18, Special x1.12 / x1.24). Tracks over 160 BPM get a smaller share of the boost (tapering to 40% of it from 208 BPM), so for example a 156 BPM track plays 156 / 171.6 / 187.2 BPM at levels 4 / 5 / 6 in the classic style, 168.5 / 181 for Sniper, and the 215 BPM monster 223.6 / 232.2. It's a real tempo change (the beat clock; the pitch stays), with the kick, the off-beat bass, the screech wah, the sirens and the dotted-8th echo following the beat. Going up lands on the bar line at once; going down (and a class switch to another tempo) glides over one bar, from bar line to bar line.
  - **Zombies** too: zombie kills are worth 0.4 of a player kill and the hold is 5 s (being downed counts as dying); the same six levels apply, so a horde gets there but not instantly: a zombie kill every second reaches MAX FRENZY on about the 22nd kill, every 2 s on about the 40th.
  - The music follows the local player's own meter. The server also runs the same heat model (Source/Game/Frenzy/FrenzyMeterCore.cs) for every player and bot from its kill events and sends each player's level and frenzy class to everyone (2 bytes in the snapshot, protocol 26), for frenzy effects and buffs. One hardbass track from the pool per frenzy, rendered by the same engine with stem gains (drums, bass, melodic parts): about the cost of one hardbass track at levels 3-6 (5 and 6 change gains and the tempo, plus the roar for two seconds) and less at levels 1-2 (the leads aren't rendered).
  - **Frenzy per weapon class**: your frenzy takes the character of the class of the weapon that got your most recent kill (Pistol, SMG, Assault Rifle, DMR, Sniper, Shotgun, LMG, Special, Launcher; a launcher's frenzy throws a lime spark shockwave off every blast and layers a rocket hiss and sub detonation on your shots). Kills without a gun (grenades and other throwables, kill streaks, melee) still add heat but keep the previous class. The per-class data lives in `Weapons/Frenzy/classes.json` (format `call-of-slop-frenzy-classes/1`): one entry per class with "music", "visual", "sound" and "buffs" sections.
  - **A music character per weapon class**: the frenzy music takes on the style of your frenzy class (the rule above; the server's replicated class, predicted locally on your own kill so it never lags). Each class has its own track pool, stem gains, effects on the track and instrument layers that come in level by level, defined in the `"music"` sections of `Weapons/Frenzy/classes.json` (synth code in `Source/Audio/FrenzyStyleRig.cs`):
    - **Pistol - Western outlaw**: a whistled melody, a galloping twangy bass and a whip crack, the whole track in a canyon slap-back echo.
    - **SMG - Chiptune breakcore**: square-wave arpeggios racing over chopped breakbeats, the track a little crunchy (fast tracks).
    - **Assault Rifle - Classic hardbass**: the track as it is (the frenzy before classes).
    - **DMR - Marching drums and brass**: a marching snare with rolls, a bass drum on the downbeats, brass stabs.
    - **Sniper - Cinematic braam**: the four-on-the-floor pulled back under a half-time sub boom and a huge reverb snare, a giant brass braam every two bars (slower tracks).
    - **Shotgun - Gabber stomp**: a distorted gabber kick tuned to the key, double hits at the end of the phrase, everything driven (harder tracks).
    - **LMG - Industrial grind**: palm-muted power-chord chugs, anvil clanks on the off-beats, a double kick at the top levels.
    - **Special - Glitch weird**: the track bit-crushed with beat-repeat stutters and random square blips (the weird track with steady drops).
    - **Launcher - Artillery barrage**: syncopated sub booms landing like shells, a falling whistle before each phrase, a bass drum and, at the top, a braam, the track in a long blast echo (harder tracks).

    A class change mid-frenzy waits for the next bar line and crossfades the two styles over one bar (the track keeps playing). Each class's level 6 stays in the same loudness window against the gunfire, and each class costs at most 1.5x the heaviest hardbass track. The self-test section **Frenzy classes** checks the data, determinism, a rhythm-and-spectrum fingerprint that differs between every pair of classes, the levels building up per class, level 6 per class, the bar-synced crossfade, CPU per class and allocations.

  - **Frenzy buffs** (host setting on the host page, On by default, saved as `frenzy_buffs`; it applies to solo games too): from frenzy level 3, guns of your frenzy class get a small buff that grows up to level 6. It only applies to that class's guns, and it works for bots and in Zombies too:

    | Class | Buff | Level 3 | Level 4 | Level 5 | Level 6 |
    |---|---|---|---|---|---|
    | Pistol | Quick draw: draw/swap time | x0.90 | x0.83 | x0.77 | x0.70 |
    | SMG | Run and gun: spread from moving (firing out of a sprint) | x0.85 | x0.77 | x0.68 | x0.60 |
    | Assault Rifle | Steady hands: recoil kick | x0.94 | x0.91 | x0.88 | x0.85 |
    | DMR | Snap aim: aim-down-sights time | x0.92 | x0.88 | x0.84 | x0.80 |
    | Sniper | Held breath: spread while aimed | x0.85 | x0.78 | x0.72 | x0.65 |
    | Shotgun | Choke: pellet spread | x0.94 | x0.91 | x0.88 | x0.85 |
    | LMG | Belt fed: reload time / move-speed penalty | x0.94 / x0.85 | x0.91 / x0.77 | x0.88 / x0.68 | x0.85 / x0.60 |
    | Special | Vampire rounds: health back per kill | +10 HP | +15 HP | +20 HP | +25 HP |
    | Launcher | Hot loader: reload time | x0.90 | x0.83 | x0.77 | x0.70 |

    The server decides the frenzy, and clients predict the buffs from the replicated level. Move speed and minimum spread are checked on the server with a 1.5 s grace after a frenzy ends, so prediction never gets rubber-banded. The game has no sprint-to-fire delay or scope sway, so the SMG buff cuts the moving-spread penalty and the Sniper buff tightens the aimed cone.
  - **Settings > Audio > Kill frenzy music** (On by default) and **Frenzy volume** (0.80, on top of the music volume), saved as `frenzy_music` and `frenzy_volume`; older settings files load with the defaults. The self-test section **Frenzy music** checks the heat model (the kill patterns reaching each level, the kills-needed table above and the pacing targets: SelfTestFrenzyPacing.cs), bar-synced changes, the easing down, death and the setting off, the volume per level (level 6 against the measured gunfire-and-explosion reference), the ducking per level, the limiter at the loudest sliders, the sliders still multiplying, determinism, allocations and CPU (at most 1.5x the heaviest hardbass track; level 6 no dearer than level 4).
- **Frenzy visuals** (per weapon class): while you're in kill frenzy (the same levels 1-6), your shots take on the look of the class of the weapon that got your most recent kill, subtle at levels 1-2 and strong at 5-6:
  - **Pistol**: gold tracers and muzzle sparks, a quick-draw glint that sweeps along the gun when you draw it or get a kill. **SMG**: neon cyan tracers, speed lines streaking in from the screen edges while you move fast. **Assault Rifle**: hot orange tracers, heat shimmer rising off the barrel as you keep firing. **Marksman (DMR)**: crisp white tracers, a ring of sparks bursting out where each shot lands. **Sniper**: long glowing tracer trails (up to 1.4 s), and each kill sends one slow vignette pulse. **Shotgun**: fiery pellets, embers drifting down where they land and up from the bottom of the screen. **LMG**: heavy spark showers from the ejected brass, a barrel that glows red-hot with sustained fire. **Special**: rainbow tracers with a split glitch ghost, and a slow chromatic flicker at the screen edges.
  - On your screen: your gun glows in the class colour (fading out as you aim down the sights), a tint in the class colour at the screen edges pulses with the frenzy music (never more than 0.25 alpha, only in the outer 16% of the screen, so it never covers where you aim), and a **FRENZY meter** (class icon, six segments, "SMG FRENZY 3" / "MAX SMG FRENZY") sits just above the kill streak HUD.
  - Other players in frenzy (bots too) show it to everyone: their tracers take their class colour and sparks, their gun glows, and from level 5 a slow ring of light circles at their feet, so you can see who's on a spree. Their level and class come from the server.
  - Nothing flashes faster than 3 Hz (the edge pulse is at most 2.1 Hz, the glitch flicker 2.5 Hz with soft ramps; the kill pulse is one slow swell).
  - **Settings > Video > Frenzy visuals**: **Full** (default), **Subtle** (the colours and gun glow with about a third of the sparks, a fainter edge tint and no screen effects) or **Off** (none of it, meter included); saved as `frenzy_visuals`, older settings files load as Full.
  - Cost: all sparks, trails and gun glows are streaks drawn in one instanced draw call for the world and one for your gun (a fixed pool of 2048, no per-frame allocation), the screen effects are a handful of ImGui gradients. The game log has a `[frenzyfx]` line every 5 s while any is drawn (streaks, draw calls, CPU and GPU ms). The looks are built in, written out in the `"visual"` section of each class in `Weapons/Frenzy/classes.json`, and can be tuned there (colour, accent, tracerWidth, sheath, trailLife, muzzleSparks, impactSparks, brassSparks, sparkSpeed, sparkGravity, sparkLife, barrelGlow, edgeAlpha, rainbow, label).
- **Frenzy gun sound** (per weapon class): while you're in kill frenzy, your own gun takes on the sound of your frenzy class (the class of your most recent kill), growing with the level: a class layer under every shot (Pistol: ricochet whine, twangy bass and spur ring; SMG: buzzy square-wave bursts and chiptune blips; Assault Rifle: a distorted hardbass kick, off-beat hat and donk; DMR: a marching snare and rim shot, flammed at the top; Sniper: a whip crack and a cinematic braam; Shotgun: a gabber kick, doubled then tripled; LMG: an industrial clang, grind and belt rasp; Special: bit-crushed stutters), with more sub thump, mechanical clacks, saturation and echo at each tier (levels 1-2, 3-4, 5-6), a driven copy of your shot (saturated, low end boosted) crossfaded in, a small pitch shift (snappier or heavier by class) and, at levels 5-6, the layer spread left and right.
  - Only your own gun changes; other players' guns keep their normal sound so you can still tell them apart by ear. Your normal shot is unchanged, so the MAX FRENZY loudness reference above still holds; a level-6 shot is at most about 1.4x (+3 dB) as loud as a normal one.
  - **Settings > Audio > Frenzy gun sound**: **Full** (default), **Subtle** (the class layer at half strength and half the pitch shift; your shot stays clean and centred) or **Off**; saved as `frenzy_gunsound`, older settings files load as Full.
  - Cost: everything is baked at start-up (8 classes x 3 tiers x 2 variants plus one driven copy per weapon, about 4 MB, a few tens of ms; the game log has a `[frenzygun]` line); a shot only picks buffers and gains (no allocation) and plays them on 10 voices of their own, so they never steal gunfire voices. The tuning lives in the `"sound"` section of each class in `Weapons/Frenzy/classes.json` (signature, levels: the intensity at levels 1-6, never going down; layer, drive, sub, clack, tail, width, pitch). The self-test section **Frenzy gun sound** checks every class has a sound entry with its own signature, every level is at least as intense as the one before, the loudness of a level-6 shot for every weapon and class, the bakes, the per-shot cost, the parser fallbacks and the setting.
- The music is rendered on its own background thread into a small queue of OpenAL streaming buffers (about 0.2 s), without allocating; it costs about 1% of one CPU core (the self-test measures it).
- Making or changing music: [docs/audio/MUSIC.md](audio/MUSIC.md).

### Sandbox and constructs (in development)

**Saved worlds:** with Sandbox chosen, the lobby room and the Single player page let the host start a **New world** or
**Continue** a saved one (map, mode, constructs, stores, dug ground, felled trees and everyone's things; autosaved, SAVE NOW in
the host's pause menu, saved on Back to lobby and on quitting; `Worlds/` in the save folder). docs/sandbox/WORLD-SAVES.md.
**Nudge tool** (top of the tool wheel): moves and turns whole constructs exactly. Click one, or use what the Selector has selected, then drag an arrow of the triad, or an arc in the rotate modes on its ring. R toggles world and local (world Z runs down along gravity), the mouse wheel sets the step or snap angle, RMB puts a drag back. docs/sandbox/CONSTRUCTS.md, "The Nudge tool".

**Selector and Blueprint Desk** (build stations): the selector (full stop) picks a box of parts on a construct to move, copy, delete, paint or attach, and a Blueprint Desk saves a group to your `ConstructBlueprints` folder and stamps it onto other builds; docs/sandbox/CONSTRUCTS.md, "Build stations: the Selector and the Blueprint Desk".

**Sandbox** is the sandbox survival mode being built in milestones (milestone 2: moving joints, logic and wiring, a
drivetrain made of parts, passengers): build vehicles and bases from parts with a tool in your hands, wire them up, drive
them, and shoot their parts off one at a time. It is a Dev-only mode for now: host **Construct Yard** (Sandbox pack) and pick
**Sandbox**. A buggy, a wired buggy with a passenger seat, horn and headlamps, two gates (one on a motorised hinge with a
button), a lift, a turret on a turntable, a parts rack (the yellow shelf) and some loose parts are waiting.

- **Wheels** are real cylinders: a kerb lifts a wheel by its rim, a wall or another vehicle stops it, and it bridges a gap narrower than itself. The configure tool sets a tyre's dry grip, dirt grip, side grip, rolling drag and bounciness.
- **Modular engines**: build your own engine from a crank, cylinders, a fuel system and a flywheel. Crank sections snap end to
  end, cylinders go on their sides (one side inline, two a V or a boxer, four a radial), a carburettor or injector rail on
  any cylinder feeds its bank, and a gearbox or shaft takes the drive from the flywheel. Turbos, superchargers, an exhaust
  outlet and tall smokestacks bolt on; a look at any piece reads "V8 320 kW, thirsty" or says what is missing. Pistons pump,
  stacks pour black smoke under load, and a shot cylinder misfires instead of killing the engine. Four sizes, from a buggy's
  to a mothership's (docs/sandbox/CONSTRUCTS.md, "Modular engines").
- **Linear joints** (inventory: Joints and Motion, Linear): a rail and a carriage. A **Free Slider** rolls between its stops, a **Linear Actuator** runs on the circuit (a Set signal, 0 to 1 along the rail), a **Shaft Linear Drive** runs off a drive shaft and holds with the engine off. Sections end to end make one longer rail with one carriage: three 2 m sections are 6 m of travel, and a powered section drives plain Free Slider rails. `docs/sandbox/CONSTRUCTS.md`, "Linear joints".
- **Pieces of a mechanism**: the physics gun freezes one jointed piece at a time. Hold a construct and press Aim to freeze all of it, then Aim at a piece to unfreeze just that piece and see how it moves; a frozen pendulum on a free base stays put while the base moves round it. The beam on the last piece of a chain pulls through every free joint behind it, and joints pass motion on: a pendulum kicks out when its slider hits a stop. `docs/sandbox/CONSTRUCTS.md`, "Pieces of a mechanism".
- **No-collide tool** (on the wheel, or Tab > Tools): click a piece, then another, and the pair passes through each other; click the pair again to undo. Hold Shift on a click for that one part. The pairs are drawn while the tool is out, and they stay in saves, copies and blueprints.
- **Arms on joints**: a machine feels an arm's true weight where it is now, however many joints are in the arm. It tips when the arm's moment beats the body's, a joint's motion pushes back on the body, and a motor that only holds a load adds nothing.
- **Free rotation** (inventory: Joints and Motion, Free rotation): a **Free Swivel** or **Free Pivot** turns with no motor or power, in six sizes. A Lock signal holds it, and limits are a setting, off by default. The physics gun moves a Free Slider's carriage along its rail, or turns a free part's moving side, without moving the rest of the construct, even a frozen or anchored one; an Actuator or Shaft Linear Drive refuses and says why. `docs/sandbox/CONSTRUCTS.md`, "Free rotation" and "The physics gun".
- **Flexible joints** (inventory: Joints and Motion, Flexible joints): a **Flex Joint** (rubber, 25 degrees) or a **Ball Joint** (50 degrees, and it twists) lets what hangs on it bend any way and spring back, with no motor or power. Three sizes each; the configure tool sets the bend limit, stiffness and damping; a wired signal locks it. It takes 2 or 3 of a construct's 16 joints.
- **Flexible chutes**: a chute across a hinge, piston, turntable or flexible joint becomes a bellows there by itself and keeps carrying. It stretches to 3 times its length and bends 135 degrees: past that it stops and says why, a quarter past that it tears (mend it with the attach tool). Between two constructs use a **Cargo Hose Reel** and **Cargo Hose Inlet** (15 m): a chute into the reel, F to carry the coupling to the inlet, a chute out of the inlet. Driven off past its length it pops out unhurt.
- **Tools**: 3 or 4 takes out the **attach tool** (every part: items from your hands onto a socket, such as seats, light wheels,
  suspensions, tanks, small gearboxes, hinges, doors, lamps, sensors, logic and gun parts, and every
  physics-only piece: frames, panels, foundations, engines, big gearboxes, big wheels, building pieces; its Socket attach
  is three clicks: LMB a socket on the piece, LMB where it goes, spin it with the mouse or wheel (Shift free, Ctrl 5
  degrees, R next facing) and LMB to attach once it is green; the piece can lie up to 30 m away, and a red ghost still goes on to the spin; RMB steps back, Esc cancels; hold Shift at the first click for Point attach, any point on the piece; Freeform attach on its ring joins two parts where they are, within 3 m, in two clicks), 5 the **linking tool** (routed links and logic settings); 1 or 2 back to your guns. **Hands** on the tool wheel: LMB picks up what lies loose or stands in a storage slot, RMB drops what you hold where you look. With a gun out or bare hands
  you can only use things (sit, drive, open doors, press buttons, flip switches and levers), never build or wire.
- **Doors**: anything hung on a hinge is a door, any size, from a flush door to a panel off the Extruder. A Door Hinge fits in the gap of an opening so the door sits flush in the wall and swings out; F on it opens or shuts it, and a Door Handle shows where to take hold. With the configure tool, Opens when pushed sets whether walking into it swings it; a wire into the hinge's Push port overrides that while it is connected.
- **The yellow glow** shows what your hands can use: a seat, a door, a button, a lever, a store, something to pick up, and on those only the part you work (a lever's handle, a button's cap). Tools don't light anything up; a tool that is refused shows red with the reason.
- **Machine screens:** Smelters, Sawmills, Foundries, Assemblers, Extruders, Wheel Formers and the Recycler show on a screen of their own what they are doing, their recipe, what they lack and their progress. Displays: bar gauges and the Graph Screen fill the whole screen with no number, every display has a colour setting, bars and graphs a colour mode, and the inventory shows each with a sample on its screen.
- **Logic parts** (Seats and Logic): Numpad and Code Lock with real keys, Rotary Knob, Slider, Toggle and Rocker Switch, Mushroom Button, Key Switch (owner or a Key in your hands); XOR, NAND, Math Block, Latch, Counter, Memory Cell, Filter, Multiplexer, Random; altitude, tilt, heading, level, damage and occupancy sensors; Wireless Sender and Receiver on a channel; Data Bus and Bus Breakout, eight signals down one link. On screens: Number Readout, Bar and Tall Bar Gauge, Dial Gauge, Graph Screen, Light Bank, Text Sign, and Compass, Altimeter and Speedometer with no wiring. Use on a keypad's key presses it, on its screen or on a sign it opens a small box to type in.
- **Analog Lever** (Seats and Logic > Controls, Small, Medium and Large): a number from 0 to 1 for throttles and speeds. Hold Use on it and move the mouse to drag the handle, from a seat too; the wheel nudges it; with the Hands out LMB drags it as well. The configure tool sets its value, output range, snap step and a spring return.
- **Size classes**: parts come in four sizes, small (everything up to a truck), **Medium** (x4, a 1 m lattice), **Large** (x16, 4 m) and **Capital** (x64, 16 m), found with the size filter over the inventory: frames, trusses, chassis decks, plates, armour, walls with windows and arches, balconies and terraces, domes, spires, stacks, hull sections. Enough to build a carrier or a tracked town: a construct holds up to 16,000 parts. A socket fits a socket of its own size; to bolt small things onto a big hull attach on an **Adapter** (the brass pads in Structure, Adapters and ballast): a big socket on its back, a grid of small ones on its front.
- **Storage Volume** (Storage and Logistics in the parts menu, attach tool): a hopper with a box of interior space you size yourself, up to 40 m a side. With the configure tool out, drag a face handle (or R on the hopper, then drag corner to corner). It holds one bulk material or stored parts, and only what lies inside your construct counts, so build the walls first. F tips in or takes out, a click puts a held part in, and its **Chute in** and **Chute out** ports take chutes. Details: docs/sandbox/CONSTRUCTS.md, "Storage volumes". In creative worlds the configure tool also sets its material and fill.
- **Fluid Tank** (Power and Fuel > Fluid tanks, six sizes, the fuel tanks' sizes): holds one fluid of any kind, with a pipe's Fluid in and Fluid out. Empty, it takes whatever arrives first; a pipe bringing another fluid is refused, and the look line says so. Fuel in it runs engines, power plants and thrusters a pipe reaches. In creative worlds the configure tool sets the fluid and the fill; in survival they fill from pipes.
- **Tank Volume** (Power and Fuel > Fluid tanks): one block with Fluid in and Fluid out, and a box you size as a Storage Volume's: with the configure tool out, drag a face handle (or R on the block, then Fire-drag), up to 40 m a side. It holds 1,000 l a cubic metre of one fluid, drawn see-through at its level, and what it holds weighs. It isn't solid, so build your own walls.
- **Sealed volumes**: a Tank Volume or Storage Volume wants walls. Each open face of its box costs capacity, and what stands above an open side pours out, on a tilt or under hard braking too; open fuel, wood and the like can catch fire. Storage Volumes suffer far less than tanks. The look line says how many faces are open, and with a tool out they show red. The numbers are in `Constructs/Sealing.json`.
- **Track tool**: pick wheels one after another round a loop and it lays a continuous track round them, like a belt on pulleys: any wheel size, triangle tracks, long lows, a raised sprocket that drives the lot. Green or red band while you pick, with the reason; R on a track for its settings, Delete to take it off, LMB to put one that was shot off back on. Its ring on the tool wheel has Part, Whole construct, Reset texture and your recent textures. docs/sandbox/CONSTRUCTS.md, "The texture paint tool".

Survival has no parts menu or noclip: start from a kit near the rack (machines, a drill rig and a saw rig) on a big map such as Proving Ground, and gather, refine and build the rest. Details in docs/sandbox/CONSTRUCTS.md.
- **Inventory**: **Tab** (the Sandbox inventory key, rebindable under Settings > Controls > Sandbox; Sandbox has no
  scoreboard) opens the inventory: tabs for parts, blueprints and tools; on
  the left a search box and the categories, by what a part does (Structure, Buildings, Drivetrain and Engines, Wheels and
  Suspension, Joints and Motion, Power and Fuel, Weapons, Production, Seats and Logic...; the picked one opens its
  sections); on the right a size filter (Small, Medium, Large, Capital) over a grid of 3D tiles (a tile size slider below
  the categories). Hover a tile for its tool, mass, health, armour and description;
  the badge is how many you have ("inf" while parts are endless). Click a part (or the arrow keys and Enter) and it is in
  your hands, with its tool out, exactly as if you took it from the rack; a blueprint (Buggy, Gate, Lift, ...) is built
  in front of you; a tool comes out. The recent row keeps your last picks. Spawning something into the world (a
  blueprint, a faction vehicle, a physics-only part) or a build from the Builds tab leaves the window up, search and
  scroll kept, so you can spawn things back to back; a green note says what came (red: the server's refusal). Taking a
  part into your hands or a tool out closes it, back to building, unless "Keep open after picking" is ticked; Tab again
  or Esc closes it. A map can turn it off with `"partsMenu": false` in its `"sandbox"` section.
- **Links** (the linking tool): on the tool wheel, point at the linking tool and flick further out onto its outer ring
  for its modes (route links, delete, move node, re-route, highlight all). There is no link type to pick: Fire on a device and it lists its ports (data, power, pipe, shaft or chute, in and out) by name; the port you pick gives the link's type. Fire to place each node on the
  surface (the preview goes red and says why when a rule is broken: pipes bend in 15 degree steps, chutes in 45, shafts
  at most 45 and never round a corner), Fire on an input to finish; RMB or Backspace takes the last node off, Esc
  cancels. You don't have to place nodes: after the output, aim at an input and the game routes round the parts, showing the link as a ghost (green, or red with the reason), and a click confirms it. Nodes you click on the way are kept and it routes on from them; hold Free routing for straight, manual segments. Fire on a link to branch off it. A link can be as long as you like: only the span between two nodes has a limit (8 m), so run a long one by walking along it placing nodes; the game finds the way round for 24 m at a time. The ring's edit modes delete, move a node, re-route or highlight every link; letting go on the linking tool itself keeps the last pick.
- **Physics gun with people aboard**: the gun and the Nudge tool can move a contraption with friendly players in or on it (anyone in creative, on your own construct in survival). They stay seated and the gun overrides the driver. Anyone else aboard refuses the grab, and ends it if they get in.
- **Your tool wheel**: Settings > Tool wheel, or the Reload key while the wheel is open: add, remove and reorder its tools. Every tool can go on it, the Selector too. Pick a tool on the list to reorder its outer ring. A tool off the wheel stays in the Tab inventory's Tools tab.
- **Ropes and springs** (the attach tool's ring: Rope, Spring): LMB a point on anything, then LMB a second point, on a construct, a wreck, a loose piece or the ground. A rope keeps the two within its length and snaps over its strength; a spring pushes and pulls (stiffness 0: a damper). RMB or Esc cancels, R steps the size, RMB at a line takes it off, the configure tool sets one, the remover deletes one. In survival a rope costs wood by the metre, a spring metal.
  Links can be shot through (a cut fuel pipe leaks, a cut cable sparks); the attach tool mends them. R changes a
  logic part's setting. Every data link takes one tick, so a NOT linked to itself is a clock.
- **Hydraulics**: the attach tool's ring also has **Cylinder**: LMB two points, R for the size. An Electric cylinder needs only power and a Set signal, and is weak and slow. A Hydraulic cylinder runs on oil: turn a Hydraulic Pump with a shaft (or give it power), run a pipe to a Lever Valve or a Digital Valve Block, and from the valve to the cylinder's head. A bigger pump pushes harder; many cylinders on one pump go slower; a cut hose leaves its cylinder limp and spraying; and a load the engine can't carry stalls it for a few seconds.
- **Tidy links**: the auto-router lies a new link beside an old one. The linking tool's **Loom** (on its ring): LMB the links, R, LMB the points of one run, R: they go along it side by side. **Cable Trays and Clamps**: a node set on one snaps to its lanes, and a link in one takes a fifth of the damage.
- **Joints**: a motorised hinge, a turntable, a piston and a steering pivot move what is fitted on them, pushed by a motor
  with a speed and a strength (an overloaded lift sinks). Unwired, F works a motorised hinge or a piston like a door.
- **Driving**: a seat does nothing by itself. Link it to a **Driving Module** (Seats and Logic > Controls) and the module's
  drive output to the engine, gearbox or any drive part; that seat drives, others carry passengers. Old saves' vehicles need
  this before they go; the look line says so. F on the seat to sit, W/S/A/D to drive, Space to
  brake, F to get out. A vehicle needs a seat with its module, an engine, fuel reaching the engine, a **transmission** touching the engine
  and wheels on suspensions bolted to a **differential** it feeds; front wheels steer on **steering pivots**. Seated,
  fire, aim and R are free for the construct's input readers. The HUD says what's missing. Players standing on a moving
  deck, lift or turntable ride along; a construct that hits you hard enough hurts (by its speed and weight).
- **Contraption space:** on a construct you live in its frame. Its up is your up and it feels like still, level ground: walk, jump and
  build on a banked, rolled or inverted hull, at any speed. You step off by walking off an edge or jumping clear, and keep its speed.
  (docs/sandbox/CONSTRUCTS.md, "Contraption space".)
- **Suspensions** come in eight sizes, kart to capital, by wheel size, and in kinds that mount and move differently: the plain
  bracket, the Pogo Strut (hung from its top, the wheel straight under it), the Swing Arm (the wheel leans with it), the Double
  Wishbone (stays upright) and the Trailing Arm (roll it on its socket for the other side). docs/sandbox/CONSTRUCTS.md, "Suspension types".
  The linking tool runs a half shaft from a differential output to a suspension's Drive in (aim at the suspension or its wheel), which drives that wheel through its travel and a steering pivot. docs/sandbox/CONSTRUCTS.md, "Half shafts".
  A **Steering Differential** (or Steering Axle in the bigger classes) drives its two sides against each other when you steer, so wheels or tracks pivot on the spot and skid-steer on the move, with or without steering pivots. A wire of -1 to 1 into its Steer input (1 is right) takes over from the seat and needs no seat, and the configure tool picks reverse, drag or clutch steering. docs/sandbox/CONSTRUCTS.md, "Drivetrain parts".
- **Damage**: every part has its own health and armour. Shoot the fuel pipe and the engine starves; shoot the
  transmission or the differential and nothing is driven; break a suspension and its wheel falls off; anything cut off
  from the seat falls away as a wreck.
- **Salvage**: with the right tool out, aim (hold) on a wreck, a loose part, a construct nobody built, or someone else's
  once it is disabled (a part of it shot off or wrecked) to take the part into your **inventory**; a destroyed part comes off as a
  **wrecked part** (a body) to haul to a **Recycler**, which gives its material back by weight (power needed in survival). Someone else's working construct can't be taken apart. The HUD shows
  your counts. On a map with `"infiniteParts": false` the rack and the parts menu hand out only what your inventory holds
  and your own parts go back into it. Wrecks nobody is near are cleared away after a few minutes.
- **Refining**: gathered ore, sand and wood go by chute (or F) into a **Smelter** or **Sawmill**, which makes metal, copper, gold, glass, planks or cloth (power needed in survival); a chute or F takes them from its output. A **Foundry** mixes two of those into a second tier material: steel, concrete, laminate, rubber, bronze or circuits. The **Smelting Station** and **Foundry Works** blueprints are ready to try. These are buildings, 3 to 10 m across: they go on a base or a big carrier, not a truck.
- **Assembling**: an **Assembler** builds parts from a recipe you choose with the configure tool (over 480 of them, in `Constructs/Assembling.json`). Chutes, F and parts in your hands feed it materials and parts from different chains; what it makes waits on its tray, and a physics-only part leaves as a body at its open front. The **Assembly Bay** blueprint builds Engines.
- **Extrusion**: an **Extruder** pushes metal, wood, planks or stone through a die as one long piece: a bar, plate, wall, hollow box, I-beam, C-channel, L, T, cross, your own 8 by 8 cell section, a solid **Round** or a **Pipe** with the wall you set (configure tool). Attach **Die Frames** to it for a bigger die (0.5 m up to 6 m, 48 m long); the Medium, Large and Capital Extruders are 8, 16 and 32 m dies, up to 192 m long. Wire a signal into its **Cut** input to part the piece off at the die, or set **Cut every** for a length; the pieces attach into structures like any part. The **Extruder Line** blueprint is a ready one.
- **Press**: stamps parts out of extruded pieces, in the world rather than a menu. Fit a **die** (F with it in your hands, or a chute from a **Die Rack**); the die sets the family: Button, Board, Bracket, Gear, Piston, Housing, Cylinder. Set pieces in its bays with the physics gun, or run a chute from an Extruder into it. The card over each bay says what it wants, and refuses the wrong piece with the reason. A fixed-size part takes its count from the piece's length (a 2 m strip makes 20 Buttons); others follow its section (a thicker bar, a bigger Housing), and the material sets the tier. Presses and dies come in Small, Medium, Large and Capital, and a die fits a press of its size. A **Die Lathe** cuts dies from a solid steel block; Button, Bracket and Gear dies come with a survival start. The **Press Line** blueprint is a ready one. The Assembler stays for everything a die doesn't cover yet.
- **Display panels**: small lit screens on a part, drawn in the world with the part, out of range or out of view they cost nothing. The press's bays and status use them; any part file can add one (`"panels"`, docs/sandbox/CONSTRUCTS.md).
- **Drones**: a Drone Receiver is the seat of a thing with no seat. Sit at a **Remote Console**, or wire a **Remote Transmitter** from any seat, set both to one channel, and you drive or fly it from up to 800 m (3 km with the Medium one), seeing through its camera. Out of range it holds where it is until the signal is back. The **Scout Drone** and **Control Post** blueprints are a ready pair.
- **Cameras and screens**: a **Camera** on any construct, a **Camera Screen** on the same channel. A screen shows a small live picture only while someone stands near and looks at it; otherwise the camera does nothing at all.
- **Tool screens**: each tool you hold has a small screen beside it with its name, mode and keys, following your rebinds; long lists turn a page every few seconds. What the crosshair is on still shows on screen, and Hands keep their hints on the HUD.
- **Wheel Former**: builds a wheel on its hub from rubber, metal, steel, wood, planks, stone or concrete. Its **Run mode** setting, or a wire into **Mode**, picks **Width** or **Depth** (the diameter); a signal into **Cut** parts the wheel off, ready to weld on a suspension's axle. Up to 3 m across, and 12, 24 and 48 m on the Medium, Large and Capital ones.
- **Shelf Bays** snap together, up and along, in small and medium sizes (Storage and Logistics, Shelves). Click a lit slot, or drop a loose part just above a board, and it stands there in a visible stack, as many of one kind as fit, held in place even on something that moves.
- **Smart Terminal**: link chutes from its **Network** port to your shelves, bins and Storage Volumes (the **Smart Depot** blueprint is ready to try) and give it power. Stand close and its screen lists what the stores hold, with counts and what it is pulling. Look at it: the wheel picks an item, **F** brings it to your hands and **R** sends it to the tray and down its **Chute out**, a second for each chute it travels.
- **Inventory Beacon**: a survival build aid. Attach one to a battery and link it by chute to your stores (the **Beacon Depot** blueprint is ready to try). Within 60 m, Tab opens the inventory on everything the chute network holds, with real counts: a click takes a part by radio, placing one uses the next, the Materials tab takes loads from its bins, and parts you take off go back to the network first (your hands if it has no room). Off, out of range or unpowered, survival works as ever and the HUD says why.
- **Build stations**: invest in a build area. A Mirror Table (M: every part also lands across a plane), Line Layer (O: drag a row or field), Replacer (P: swap a part, keeping its joins and links), Build Gantry (U: a camera that orbits your build), Selector and Blueprint Desk, each attached on, powered and chuted to your stores like a beacon, give their aid within about 90 m. Icons at the bottom of the screen show what is live, and the look line says what a station needs. Parts come from the inventory and network; heavy pieces from loose ones nearby. In creative the aids need no station.
- **Machine tiers**: drills, saws, sawmills, smelters, foundries and assemblers each come in five tiers, Scrap (the plain names), **Workshop**, **Industrial**, **Military** and **Plasma**, in the Production category of the parts menu. Each step is bigger (a drill up to 2.5 m wide, a Smelter 3.5 m at tier 1 and 10 m at tier 5), twice as fast, holds more, is tougher and draws more power, for less power a unit. Copper needs a tier 2 drill and smelter, gold a tier 3; the look line says so, and points to a deposit the drill can work. Each tier has its own shape and look, so a glance tells you what it is: Scrap is lashed-up timber and rust, Workshop tidy blue paint and cast iron, Industrial tall concrete with pipes and yellow, Military low olive armour with sandbags, Plasma dark curves with a glowing core. In creative they are all in the parts menu; in survival an Assembler builds them.
- **Scoops dig by being pushed**: a Digging, Grading, Trenching or Rock Bucket on an arm of hinges, pistons or rails cuts the ground when its edge is really pushed in, and holds it as dirt, stone or sand. A full one only pushes. Tip it and it pours: into a bin, a Storage Volume or a machine under it, else onto the ground as a heap you can dig again, or as Material Bundles on anything else.
- **Drills need somewhere to put it**: a Drill Module is a compact rig with a small buffer (2 s of work). Full, it stops, so link its **Chute out** to a Materials Bin, a Storage Volume or a machine with the linking tool. It runs on electric power, or from a **drive shaft** into its **Drive in** on top: a shaft from an engine's Drive out or a gearbox's output. The faster the shaft the faster it drills, up to the tier's rated rpm (1,800 at tier 1, 1,000 at tier 5), and it takes torque from the engine, so a big drill needs a gearbox or a big engine. With a shaft linked it uses no power, and a stopped shaft stops it even with a battery there; the look line says why. The engine needs a driver or a switch on its run port, as ever.
- **Weapons**: guns are parts too, fitted with the attach tool. Bolt a barrel, a magazine, ammo, a muzzle device and a scope
  (weapon builder parts) onto a **receiver**, or fit a heavy gun (**Mounted MG**, **Autocannon**, **Cannon**, **Rocket
  Pod**, **Flamethrower**), and an **ammo box** touching its feed (or at the end of feed chutes). A gun on the body points
  with its construct; on a turntable (and a motor hinge) it follows the look of whoever sits in the seat linked to its **Turret Module** (link the seat in, the module's guns output to the gun; several seats, several turrets; Aim steps a seat with several) on
  it, and their fire key fires it. Anything wired into a gun fires it instead (an input reader on the driver's fire key,
  a switch); a **proximity sensor** wired in makes it a **sentry** that turns onto anyone in range. AP rounds go through
  a part into what is behind it, HE rounds splash, incendiary rounds set wood, fuel and ammo alight, and a holed ammo box
  cooks off. The yard has a gunner turret, a hood-gun buggy, a sentry, a gun bench and targets.
- **Ammo feeds**: a mounted gun's rounds come from what feeds it. Set the **ammo type** on an Ammo Box, Crate or the drag-sized **Ammo Container** (a bunker, by the Storage Volume's rules) with the configure tool; any type fits any gun, and the receiver sets the calibre. A gun starts on a **magazine** (the socket on the receiver's left): hold an empty one in your hands, press F at a box, crate or container to fill it, fit it with the attach tool, and swap it when it runs out. It also clips onto an **Ammo Socket**, on the gun or linked to it, so a few rounds carried by hand feed a gun with no crate or belt; hold a full one and press F on the fitted one to swap them. A magazine keeps its rounds in your backpack and inventory. Later, run an **ammo feed** in the linking tool from a store straight to a gun: no magazine needed, it holds 3 s of fire ready, and a cut feed leaves only those rounds. A feed across a joint bends only so far (it stops at 135 degrees and tears soon after); for a turret that goes all the way round, use an **Ammo Reel**: feed the reel, take its belt with F and plug it into an **Ammo Socket** on the gun. Put an **Ammo Switch** in a feed to choose by a wire (0 the first, 1 the next); a gunner's reload clears the gun for the new type. Handheld guns keep their Ammo parts. A loaded feed that is cut burns along itself, up to 8 m each way, as far as a switch.
- **Rounds fly until they land**: a built or mounted gun's round that hits nothing keeps going. Shot straight up it comes down about 23 s later, slowed to 60 m/s and doing a sixth of its damage. In space it goes 42 km and more.
- **Powder charge**: set how hard a round leaves, 25% to 300%, on a receiver with the configure tool or on the Gun Workbench for a hand gun. Low is a slow round on a long arc with little recoil; high is fast and flat, hits harder and kicks harder, and a short barrel wastes the top of the range and shoots wide. Built hand guns' rounds fall in Sandbox, as mounted guns' do.
- **Mounted guns' rounds fall**, the gunner's aim allows for it and a cross marks where they land. **Heavy rounds dig** (60 damage and up: a .50 chews the ground).
- **Artillery**: a **Field Gun** or **Howitzer Receiver** with a tube and a feed fires real shells on a real arc, 420 m and more, slowly, with the biggest blasts in the game (9 m, 43 m on a merged 3x3) and craters to match. Mount it on a motor hinge on a turntable with a Turret Module, **look where the shell should land** and fire; hold **Aim** for the high arc. An orange cross marks where the gun lands as it points, and the HUD gives the range, flight time and elevation. Shells: High Explosive, Siege, Incendiary, Smoke. They are too big to hold.
- **Flamethrowers and harpoons**: two more kinds of gun in the same system, for the hand (at the workbench) and for a
  vehicle (bolted up, and bigger as a merged receiver). The **Firebreather Receiver** with a nozzle and a fuel feed throws a
  short cone of fire (10 m by hand, 15 m on a 2x2) that sets wood, fuel and ammo alight, burns players and gets past armour; on a
  construct it also burns the construct's own fuel. The **Whaler Receiver** fires a barbed head on a real rope into a construct, a
  wreck, a loose body, the ground or a player (40 m). While a line is out, **Fire reels it in** and **R cuts it**; it holds and
  drags, and snaps over its rating (a hand gun's is 1.5 t, a big merged receiver's 120 t). A harpooned player is held by the line:
  **F tears it out**, for 10 damage.
- **Spawning bots and zombies** (creative worlds; the inventory's **Spawn** tab): pick a **friendly bot** (on your
  side: it follows you and fights enemy bots and zombies), an **enemy bot** (fights players and friendly bots) or a
  **zombie group**; a bot's difficulty (Easy to Insane), its gun (any, a weapon class or one gun) and how many; a zombie
  group's size, 1 to 500,000 (a slider, a number and presets 10/100/1k/10k/100k/500k; above 100,000 it warns it may be
  slow), and whether the zombie types are mixed in. **PLACE** closes the window: a ghost circle follows the crosshair
  (red with the reason in a wall, in mid-air or on a construct), Fire spawns there (again and again), RMB or Esc stops.
  Up to 64 zombies come as full zombies rising at the spot; a bigger group goes into the mass horde round it (the nearest
  wake as full zombies). Zombies hunt players and friendly bots and swipe at constructs in their way (doors and panels
  give way). **CLEAR ALL** removes every spawned bot and zombie. Spawned bots don't respawn. Joined players spawn too, up to
  8 bots and 64 zombies each at once (never a crowd), and **CLEAR MINE** removes only theirs; the host can turn their
  spawning off with "Joined players can spawn". The host also sets the most bots (16 by default) and zombies
  (500,000). Survival worlds have no direct spawns.
- **Spawner parts** (Spawn group): a **Bot Spawner** and a **Zombie Spawner** are parts like any other (attach tool, anchored
  or on a vehicle, moved with the physics gun, saved in blueprints). The configure tool sets what they spawn (team,
  difficulty and gun; or walkers or mixed types), the rate a minute, the group size, the most alive at once, the total
  (0: no limit), the radius and whether they start on. With the linking tool their data inputs **enabled**, **spawn
  now** and **rate** and outputs **alive** (how many it has out) and **spawned** (a pulse) appear in the port picker: a
  pressure plate can start a wave, a compare on "alive" can stop it. A spawner shows a light while it is on.

Each tool has its own box model in your hands (and in other players' hands), with a crank, sparks or a beam while it
works; a part you carry sits in your off hand. Parts, blueprints and the tools' models are data files (`Constructs/Parts`,
`Constructs/Blueprints`, `Constructs/Tools`; `--check-construct-parts` checks them), and a map gets the mode with a `"sandbox"` section. The design, the data format, the decisions made so far and
what comes next are in [docs/sandbox/CONSTRUCTS.md](sandbox/CONSTRUCTS.md).

- **Big systems**: the Medium, Large and Capital sizes hold what makes a mothership work: ramp decks and drawbridges on motor hinges, lift platforms on rated pistons, arched gates, hangar doors, catapults and arrestor gear, docking clamps and magnetic locks that hold a crewed vehicle fast (and charge and refuel it) until a signal lets it go, winches, crane booms, conveyors, naval guns, magazines and hoists; the Ship systems group has the Bridge Helm, crew stations, the Fire Director (one gunner fights every turret wired to it), sensors and lights. Vehicles' wheels now stand on other constructs: a parked car rides a moving deck, and drives off it. `docs/sandbox/CONSTRUCTS.md`, "Large systems".

## Video Screens and Music Players

In Sandbox, a **Video Screen** (three sizes) or a **Music Player** plays YouTube links and the game's own tracks in the world, and everyone near hears it fade with distance. Use the configure tool on it: paste a link, build a list of up to 32 lines, play, pause, stop. Each player's game runs its own copy of YouTube's player, kept to the same time. Links need Windows and the `Browser` folder that ships with the game; the game's own tracks play on every platform. Settings > Audio has a Screens volume and a switch for other players' videos. How it works: `docs/sandbox/MEDIA.md`.

## Updates

Release builds check GitHub for a newer release and can install it from inside the game.

- **Your version** is in the bottom-right corner of the menus (e.g. `v0.2026.1022.5 (abc1234)`; a `dotnet build` / `Start.bat` copy says `dev build`). Versions are `0.YYYY.MDD.N`: year, month * 100 + day, and the release number.
- **Checking:** at startup the game asks GitHub in the background (it never delays startup; offline is fine), at most once every 6 hours (the answer is cached in `update_check.txt` in the save folder; it holds one answer, so nothing piles up). **Settings > Player > Updates** has **Check for updates** (at most once a minute), **Release page**, and **Check for updates when the game starts** to turn the startup check off. Dev builds only check when you press the button.
- **Update available:** a banner on the main menu shows the new version and its notes with **Install**, **Later** (hide it until next launch) and **Skip this version** (no banner until a newer release; undo it in Settings > Player).
- **Install** downloads the zip with a progress bar (**Pause** keeps the partial download; Install resumes it), checks its size and SHA-256 against the release's `update.json`, unzips it into a **new folder next to your current build** (`CallOfSlop-<version>`, next to the folder you unzipped the old build into), starts the new `CallOfSlop.exe` and closes the old one. Your saves live in `%APPDATA%\CallOfSlop` (see below), so progress, loadouts and settings carry straight over. The running build is never overwritten. If the game's folder can't be written to, the new build goes to `%LOCALAPPDATA%\CallOfSlop\Builds`. Failures (no disk space, a damaged download, no connection) show a message with **Retry** and a link to the release page.
- **Old versions are cleaned up:** every folder the updater unzips gets a small `.callofslop-build` marker (version, folder name, install time). When the new build reaches its main menu it records that it works in its marker and, a few seconds later, removes in the background what is no longer needed next to it: older build folders **the updater installed**, downloads of versions already installed (`CallOfSlop-<version>.zip.download`; a paused download of a newer release is kept for Install to resume), unzips that were interrupted over an hour ago (`.partial`), and leftover temp files. By default it **keeps the previous version** for rollback (the newest older one that reached its menu). **Settings > Player > Updates** has **Remove old versions after updating** and **Keep previous version for rollback** (both on), and **Clean up old versions now**, which lists what it would remove (folders and sizes) and what it keeps and why, and removes nothing until you press **Remove**. Every removal goes to the console and to `update.log` in the save folder.
  - **What is never removed:** anything that isn't a direct child of the folder your builds sit in; links and junctions (and, inside a removed folder, links are removed as links, never followed); folders without the marker, or whose marker names another folder (a build you unzipped yourself, a renamed or copied folder, your dev folder, builds installed before this updater existed: delete those yourself); the running build and any newer one; a build with saves in it (`portable.txt`, any save file or `AudioMixes` next to its exe, or your save folder inside it: move the saves yourself, then delete it); a build a running Call of Slop was started from.
  - **Safe if interrupted:** a folder is first renamed to `CallOfSlop-<version>.deleting` (Windows refuses while a file in it is open, so a running copy is never half deleted), then emptied with its marker removed last. A removal that stops part way is finished on the next launch, even with the option off. Everything is checked again right before it is deleted.
  - **Leftover files:** because each version unzips into its own folder, an update never leaves files a newer build no longer ships. Old files only pile up when a build is unzipped **over** an older one, or in a dev `bin` folder that `dotnet build` / `Start.bat` keeps reusing (it adds and updates files but never removes them). That is why the game still ignores the retired `Maps/Classic`, `Maps/CollisionPoint` and `Maps/HighGround` folders when their maps match `Maps/Legacy`'s (`MapPack.RetiredFolders`); delete them yourself, or delete `bin` for a clean build.
- **Security:** the game only downloads this repository's own GitHub release files over HTTPS (`https://github.com/TwitchTheSniper/CallOfSlop/releases/download/...`; any other URL in a manifest is refused), checks the SHA-256 before using anything, refuses zips with paths outside their folder, and runs nothing from the download except the new `CallOfSlop.exe` after it passed those checks. No GitHub token is used.
- **SmartScreen:** builds aren't code-signed yet, so Windows SmartScreen may warn the first time you run a zip you downloaded with a browser ("More info" > "Run anyway"). Updates installed from inside the game don't carry the browser's "Mark of the Web" (the game downloads and unzips the files itself and removes any `Zone.Identifier` stream), so SmartScreen doesn't stop them. The Release workflow has an optional code-signing step (Azure Artifact Signing) for later.
- **Playing together:** everyone needs a build with the same protocol version; the server browser says when yours is older (above).


**Big drive** (docs/sandbox/CONSTRUCTS.md, "Big drive"): what moves and powers big constructs, in the Medium, Large and
Capital size classes. Giant tracks and bogies on hub motors (each powered from the circuit, no shafts, on a steering pivot
if it is to turn), big engines, gearboxes, shafts and axles, gas struts, leg pistons, jacks and landing struts; boilers,
furnaces, gensets and reactors feeding the circuit, chimneys that smoke with them; bunkers, battery banks, fuel mains; jets and
lift fans in five sizes, with Sprint holding a height for a flying mothership. A capital body of 100,000 t drives, turns,
rides rough ground and hovers. There is no water in the game, so no ship parts. `Source/PartKit/Generators/BigDriveParts.cs` writes them.

### Cutting a release (for the maintainer)

1. Make sure `main` is green.
2. **Actions > Release > Run workflow** on `main`. Leave *version* empty for `0.YYYY.MDD.<run number>` (or type one in that form), and write one line of *notes* (testers see it in the banner). *Dry run* does everything except publishing.
   Or push a tag: `git tag v0.2026.1022.1 && git push origin v0.2026.1022.1`.
3. The workflow (`.github/workflows/release.yml`, Windows) builds with the version stamped in, runs the self-test, packages with `tools/package.ps1` (the same script `tools/Package.bat` runs locally), optionally signs the exe, checks the package with the game's own updater (`CallOfSlop.exe --verify-update update.json <zip>`), and publishes the release with `CallOfSlop-<version>.zip` and `update.json` using the built-in `GITHUB_TOKEN`.
4. Every tester's game offers the update within 6 hours of its next launch (or straight away with *Check for updates*).

Code signing (optional, off): set the repository variable `SIGNING_ENABLED=true`, the variables `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_SIGNING_PROFILE` and the secrets `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` (details in the workflow's comments).

`update.json` fields: `version`, `build`, `sha` (git commit), `protocol` (ServerInfo.ProtocolVersion), `url` (the zip's release URL), `size`, `sha256`, `notes`, `minUpdater` (a release that needs a newer updater than the player's game is offered as a manual download), `published`. The top-level `url` / `size` / `sha256` are always the Windows zip. A release with a Mac download also has `"platforms": {"osx-arm64": {"url", "size", "sha256"}}`: Mac builds take that entry (checked exactly like the top-level one) and never the Windows zip, and say "no download for this computer yet" when a release has none; Windows builds ignore it.

### Steam (in development): the foundation

The game can run under Steam (`Source/Platform/Steam`, `docs/steam/STEAM.md`), but Steam is **optional**: every GitHub zip, LAN game and self-test runs exactly as before, with the Steam layer off.

- **When Steam starts:** a Steam build (`dotnet publish -p:SteamAppId=1750920` stamps Call of Slop's App ID in), a `steam_appid.txt` next to the program (a developer's file; it is in `.gitignore` and never packaged), `--steam` (the Spacewar placeholder App ID 480, local testing only) or `--steam=NNN`, or the Steam client launching the game. `--no-steam` always wins. The log says `[steam] off / unavailable / running` with the reason.
- **What it does so far:** the Steam persona name is your display name (**Settings > Player > Use my Steam name**), Steam players' avatars show in the pre-match lobby's player list when both sides are on Steam, the Steam overlay frees the mouse and opens the pause menu, a Steam build started outside Steam relaunches through Steam, and a Steam build never checks GitHub for updates (Steam updates it). Steam names and avatars travel as Steam IDs in `Msg.SteamIds` (protocol 74), sent only when someone is on Steam.
- **Playing over Steam (Phase 2, protocol 75):** with Steam running, hosting listens both ways: the usual UDP port (LAN, invite codes, server lists) and Steam networking sockets, peer to peer by Steam ID through Valve's relays (no port forwarding, UPnP or STUN needed). The host also makes a Steam lobby (**Multiplayer > HOST A GAME > Steam lobby**: Public, Friends or Invite only). Friends join from the server browser (public lobbies show with "Steam"), an overlay invite ("Invite Steam friends" in the lobby room), "Join game" on your profile, or Steam starting the game with `+connect_lobby`. Rich Presence shows what you play; a client on Steam proves itself with a session ticket, and the host can kick or ban by Steam ID (Pause > HOST). The self-tests run the Steam transport on a recorded backend; LAN and GitHub builds use RakNet exactly as before.
- **Not yet:** achievements, Cloud, Workshop, Steam Input. Those are the next phases; the layer's backend interface (`ISteamBackend`) is where they plug in.

### Mac (Apple Silicon): not yet shipped

The Mac build is ready but **switched off**: releases are Windows only until the developer turns it on.

- **What players get:** `CallOfSlop-<version>-mac.zip` holding a `CallOfSlop` folder with `CallOfSlop.app`, `READ ME FIRST.txt` (`tools/mac/TESTERS-MAC.txt`), `MOVING YOUR SAVES.txt` and `NOTICE.txt`. Apple Silicon only (osx-arm64, self-contained, no Intel build), macOS 14 or newer.
- **Inside the app:** the program, .NET and the BRUTAL natives (GLFW, OpenGL loader, ImGui, OpenAL Soft, RakNet, meshoptimizer, stb...) in `Contents/MacOS`; the game data (`Maps`, `Weapons`, `Parts`, `Props`, `Baked`, ...) in `Contents/Resources`, where `Source/App/AppFolders.cs` finds it; `Info.plist` with the version, the icon (`tools/mac/AppIcon.png`, drawn by `tools/mac/make_icon.py`), and the microphone (voice chat) and local network (UPnP) prompts. A plain build folder on a Mac (dev builds, CI) keeps everything side by side, as on Linux.
- **Where things go on a Mac:** saves in `~/Library/Application Support/CallOfSlop`, logs (`callofslop.log`, `selftest.log`) in `~/Library/Logs/CallOfSlop` (the app never writes into its own bundle: a downloaded app may run from a read-only copy), updates in `~/Library/Application Support/CallOfSlop/Builds`. **Settings > Player > Open save folder** opens Finder.
- **Not signed by Apple (yet):** the bundle is ad-hoc signed, so the first launch needs one confirmation: macOS 15+ **System Settings > Privacy & Security > Open Anyway**, macOS 14 right-click > **Open** (READ ME FIRST.txt has the steps, and the `xattr -dr com.apple.quarantine` fallback). Moving the folder out of Downloads with Finder first stops macOS running it from a read-only copy.
- **Platform details:** OpenGL 4.1 core with `#version 410` shaders (the most macOS offers): the game never asks a Mac for the 4.6 context it uses elsewhere (docs/render/OPENGL46.md). Retina: the 3D view renders at the full framebuffer size, and the menus scale with the window height in points, so a Retina Mac gets the same UI size as a 1x screen, drawn sharp. Text boxes use Cmd+C / Cmd+V (ImGui's Mac behaviour); game binds are the same keys as on Windows (Left Ctrl crouches). The mouse is captured with GLFW's disabled cursor (no raw mouse motion on macOS). UPnP and STUN are plain sockets and work unchanged. The updater downloads the Mac zip, unzips it, makes sure the program is executable and opens the new `CallOfSlop.app` with `open -n`.
- **Building on a Mac:** `dotnet build -c Release -p:PlatformTarget=arm64` (the csproj says x64 for Windows and Linux; the command line overrides it, so the csproj stays untouched), then `dotnet bin/Release/net10.0/CallOfSlop.dll`. The app: `tools/mac/package_mac.sh publish|bundle|zip <version>` (needs pwsh; see the script's header).
- **Release workflow:** the `mac` job in `.github/workflows/release.yml` runs on `macos-latest` alongside the Windows job when the run's **mac** box is ticked or the repository variable `MAC_RELEASE_ENABLED` is `true`: build, the full self-test, publish, bake, `CallOfSlop.app`, a check of the app itself (a few self-test sections run by the app's own program, then its signature must still verify), zip, and the game's own `--verify-update ... --platform osx-arm64`. `publish-mac` then attaches the zip and adds the `platforms.osx-arm64` entry to the release's `update.json` (never on a dry run). Off, the release is exactly the Windows one. To try it without publishing: **Run workflow** with **Dry run** and **mac** ticked. Developer ID signing and notarisation is a skipped step like the Windows one (`MAC_SIGNING_ENABLED`, details in the workflow's comments, entitlements in `tools/mac/CallOfSlop.entitlements`).

## Where your saves live

Saved Sandbox worlds are in the `Worlds` folder of the save folder, one folder a world (docs/sandbox/WORLD-SAVES.md).

Your own files (`progress.txt` with level, XP, weapon XP and prestige; `loadout.txt` with loadouts; `appearance.txt` with your hat and look; `settings.txt`; `workbench.txt` and `blueprints.txt`; audio mixes `audio_mix.json` and `AudioMixes/`) are kept in a **save folder outside the game**, so they **carry over to every new build automatically**:

- **Windows:** `%APPDATA%\CallOfSlop\` (paste that into Explorer's address bar), **macOS:** `~/Library/Application Support/CallOfSlop/`, **Linux:** `~/.local/share/CallOfSlop/`.
- **Settings > Player > Saves** shows the folder and has an **Open save folder** button.
- **Portable mode:** put an empty `portable.txt` next to `CallOfSlop.exe` and the saves stay next to the game (USB sticks, dev copies). **`--save-dir <path>`** on the command line uses any folder (it wins over both).
- **Moving from an older build:** older builds kept the saves next to the game. On startup, any save the save folder doesn't have yet is **copied** from next to the game (`[saves] migrated progress.txt from <folder>` in `callofslop.log`); on the very first run of a freshly unzipped build it also looks for your most recent other Call of Slop build beside it (sibling folders, e.g. the previous tester zip) and copies from there. The originals are never moved or deleted. If both have a file, the save folder's copy wins and the other one is left alone (logged).
- **Safe saving:** every save is written to a temp file and swapped in, so a crash can't leave half a file, and the previous save is kept as `NAME.bak` (e.g. `progress.txt.bak`). A damaged save loads its backup (the damaged copy is kept as `NAME.corrupt`). Each file starts with a `version=1` line; files without one (older builds) load exactly as before, and a save written by a *newer* build than the one you're running is never saved over (the lobby and Settings > Player say so).
- Game data (maps, weapons, props, `classes.json`, `hats.json`, ...) stays next to the game, as does `callofslop.log` (in the Mac app: data in `CallOfSlop.app/Contents/Resources`, logs in `~/Library/Logs/CallOfSlop`). The smoke test (`--smoketest`) plays with a throwaway copy of your saves in the temp folder, and the self-test uses its own temp folder, so neither can change your progress.
